# Skill 编写规则

本页用于承接本仓库 Skill 编写方法论。
这是 Agent 私有知识, 不再作为用户主 review 正文。

## 设计模式

### Tool Wrapper 工具包装器

- 适合给 Agent 补充特定技术或工具知识
- 常见结构是 `SKILL.md` 加一个轻量 `references/` 规则页
- 当前仓库的工具型 Skill 可使用 `*-tool` 后缀

### Generator 生成器

- 适合生成结构稳定的文档、模板或代码骨架
- 通常组合 `references/` 里的风格规则与 `assets/` 里的模板
- 只有确实需要固定产物结构时才引入 `assets/`

### Reviewer 审查者

- 适合收口检查、门禁和质量评审
- 评分标准与检查清单应拆到独立引用页
- 当前仓库的 review 规则优先放在专门的 review Skill 中

### Inversion 反转

- 适合先收集关键信息, 再输出方案的任务
- Agent 先按框架提问, 信息齐全后再生成结果
- 若缺少关键前提就会影响结果, 应优先考虑此模式

### Pipeline 流水线

- 适合带阶段门禁、确认节点或多步交付的复杂任务
- 不同步骤可按需加载不同的引用页或模板
- 只有单一模式无法覆盖任务时, 再考虑组合多种模式

## 设计模式决策流程

- 首要目标是补充领域知识时, 优先用 `Tool Wrapper`
- 需要输出高度一致的结构化产物时, 优先用 `Generator`
- 核心任务是检查、评分或审核时, 优先用 `Reviewer`
- 必须先澄清模糊需求或收集前置条件时, 优先用 `Inversion`
- 存在多个独立阶段且需要阻断条件时, 优先用 `Pipeline`

## 本仓库 Skill 结构规则

- 扩展 superpowers 的本地 Skill 统一使用 `project-extension-` 前缀
- 仓库主入口与流程入口优先使用最短、最自然的名字
- 主 `SKILL.md` 默认只做路由、用途说明和边界声明
- 详细方法论、规则清单和补充说明优先收进 Skill 私有 `references/`
- `assets/` 只存模板、示例或其他需要被复用的静态资产
- `references/` 的目标是降低选择成本, 不是展示分类完整性
- 如果多个入口没有明确场景差异, 必须合并而不是平行保留

## 写作边界

- Skill 编写方法论默认只服务 Agent, 不再作为用户主 review 正文
- 需要用户人工 review 的正文应保留在用户可审阅的主入口, 不要和 Agent 私有方法论混放
- 重构 Skill 时, 应先确认哪些内容是事实源, 哪些内容只是路由说明
