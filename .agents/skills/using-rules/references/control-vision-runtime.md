# 控制、视觉与运行时规则

## 适用范围

- 本页用于控制链、角色运行入口、视觉速度输入、调参与诊断顺序相关实现。
- 项目路线目标以 `docs/developer/strategy.md` 为准, 任务推进顺序以 `docs/developer/tasks.md` 为准。
- 控制事实以 `docs/developer/control.md` 为准, 视觉职责以 `docs/developer/vision.md` 为准, 串口字段以 `docs/developer/protocol.md` 为准。

## 项目与角色边界

- 项目总路线由“寻找态状态机集”和“搬运态状态机集”组成。
- 主车负责环境理解、目标搜索、统一任务决策、状态切换与协同编排。
- 辅车负责跟随协作、执行配合与状态回传。
- 主车与辅车都参与运动, 两车都默认维持本地方向闭环。
- 高速多车通信与速度前馈属于正式控制主线能力。
- 任何实现扩展都要先回答是否直接服务完赛主线; 不能直接服务时默认不扩大范围。

## 运行入口与角色层事实

- `src/main.py` 是正式单入口, 负责按钮判定和脚本分发。
- `src/script/remote_control.py` 读取 D8 / D9 角色输入, 并创建对应角色运行入口。
- `vision/master/` 负责主车 `UART3` 上游控制接入与 `UART8` 速度转发。
- `vision/assistant/` 负责辅车 `UART8` 前馈输入与 `UART6` 视觉速度修正的读取编排。
- 辅车角色层只承担接口编排与前馈 / 修正融合, 不额外堆叠第二套底盘执行内核。
- 共享控制内核负责通用底盘执行与方向稳定。
- `TransportCar` 不承担辅车跟随角色逻辑, 角色层输出最终速度后回到共享底盘原生入口。

## 控制系统固定事实

- 控制层级固定为位置误差收敛 -> 速度环 -> PWM 输出。
- 反馈来源固定为编码器速度 / 里程计与 IMU 航向信息。
- 控制模式至少区分速度模式、位置模式和角度保持模式。
- 5ms 控制周期预算属于实现阶段硬约束, 超预算先降复杂度, 再讨论新特性。
- 参数与阈值集中在 `src/config/params.py`。
- 角度主链路优先依赖零漂校准、滤波、四元数积分和动态控制周期, 不依赖视觉角度。
- `xy` 编码器积分不作为高精度位置真值, 但 `xy` 位置式控制保留为多段误差修正链路。

## 速度前馈与视觉修正

- 主车通过 `UART3` 接收上游控制命令, 经 `UART8` 向辅车转发速度前馈和角度目标。
- 辅车把 `UART8` 的 `vx / vy` 作为前馈向量, 把 `UART6` 的 `vx / vy` 作为视觉修正向量。
- 辅车最终平移速度按轴相加: `UART8` 前馈向量 + `UART6` 视觉向量。
- 任一路当前包未出现的速度轴按 `0` 处理; 没有新包时沿用该路上一包, 直到被新包改写或显式零包清空。
- 辅车旋转输入只来自 `UART8` 或底盘本地角度控制; `UART6` 不承载角速度前馈和绝对角度目标。
- `UART8` 与 `UART6` 的速度字段解析复用同一份共享边界, 乱序、空白、缺省轴和非法字段判定保持一致。

## 状态机与协议边界

- 全局状态机由主车维护, 状态编号和事件编号以 `docs/developer/state.md` 为准。
- 协议层只定义字段、报文格式和同步语义, 不承载具体业务状态机职责。
- 业务状态机不得反向要求高频串口包携带冗长上下文字段。
- 需要可靠建立的上下文走状态同步短包; 高频运动、前馈和修正数据走速度控制文本。
- 状态机任务设计应避免阻塞式等待语义, 保持控制周期持续推进。

## 调参与诊断顺序

- 控制系统调参流程固定为: `calibrate_gyro.py` -> `pid_identify.py` -> 内环 -> 外环 -> 航向保持 -> 组合轨迹联调。
- 参数辨识先行, 使用 `pid_identify.py` 生成电机参数。
- 改控制算法前先确认硬件基线: 编码器方向、电机方向、IMU 校准。
- 控制问题按固定顺序排查: 振荡、响应慢、稳态误差、航向漂移、轨迹偏差。
- 高频跟随相关实现先收口输入边界、状态所有权与角色层职责, 再决定是否需要额外解耦层。
- 若出现状态抖动, 先排查输入时效、协议边界和滤波, 不要直接扩大架构层次。
- 进入设备路径后, 对控制相关变更必须准备调参与验证记录, 不接受只凭主观体感下结论。
