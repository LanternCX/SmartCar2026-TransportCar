# 实现核心规则

## 适用范围

- 本页是所有代码实现、行为调整和重构任务的默认必读页。
- 本页只保留跨场景硬门禁, 不承载协议全文、比赛路线正文或最终收口评审。
- 若改动触及硬件事实、串口协议、坐标语义或联调语义, 继续读 `hardware-protocol.md`。
- 若改动触及 PID、运动学、里程计、角色运行入口、视觉速度输入或调参诊断, 继续读 `control-vision-runtime.md`。
- 若改动触及文档、注释、文档字符串或 Skill 正文, 继续读 `docs-and-comments.md`。

## 平台与导入约束

- 目标平台是 RT1021 + MicroPython, 本地 Python 版本以 `pyproject.toml` 为准。
- 板端入口与主线运行时代码不得依赖 `os.path`, 路径处理使用板端可用的最小字符串逻辑。
- 板端入口与主线运行时代码不得依赖 `types` 这类板端可能缺失的标准库模块。
- 运行时代码默认不要依赖 `typing`; 如需类型辅助, 使用不影响板端导入的兼容写法。
- 板端入口不得依赖临时伪造包对象来驱动相对导入, 板端文件平铺上传时应直接使用可落地的导入路径。
- 主线运行时代码中的包内依赖与硬件模块依赖必须直接导入, 不保留 `ImportError` / `ModuleNotFoundError` 兜底、假对象或默认值回退。
- 硬件接口必须以 `seekfree_demo/` 中已出现的能力为准; demo 未出现的方法或行为不得自行假设。
- `seekfree_demo/v3.0.0/` 与其他 demo 冲突时, 默认优先以 `v3.0.0` 为准; 对 `IMU660RX` 与 `encoder` 的 `get()` 读取, 先按新 demo 建立 `ticker.capture_list(...)` 采样触发链。
- 参数与阈值统一放在 `src/config/` 分层配置下, 按运动、视觉、安全和持久化边界取用。
- 禁止静默失败; 只捕获预期异常并保留上下文。

## 目录与职责边界

- 仓库正式代码根目录是单一 `src/`; 目录存在性和代码阅读顺序以 `README.md` 与 `docs/developer/` 入口为准。
- 入口层、脚本层、共享底盘、角色运行时、硬件封装、参数配置和存储边界必须保持单一职责。
- 角色层不得复制共享底盘执行内核, 底盘执行内核不得承载角色状态机决策。
- 下层不得依赖上层; 禁止循环依赖、跨层跳跃调用、隐式上下文协议和状态双写。
- 领域模块需要拆成 2 个以上内部实现文件时, 优先改为包目录加 `__init__.py`, 不用共同前缀平铺模拟命名空间。

## LSP / Pyright 排障约束

- 若 `src/` 包内导入在运行时正常、但 Pyright 报 `unknown import symbol`, 先检查仓库根目录是否存在同名包遮蔽 `src/` 下真实模块。
- 遇到同名包遮蔽时, 优先改为 `from config import params as _params` 这类模块级导入再用 `getattr(...)` 取值, 不要为了消红改坏板端导入路径。
- 对 `execfile` 这类板端提供的全局能力, 优先保持运行时代码写法不变; 若仅是 Pyright 误报, 使用单行局部忽略, 不新增 `builtins.pyi` 覆盖整套内建声明。

## TDD 与验证层选择

- 行为改动必须先选测试层, 并先有失败测试。
- 测试驱动开发步骤固定为 RED -> GREEN -> REFACTOR。
- 纯逻辑与确定性行为优先放到 `tests/unit/`。
- 命令、协议与副作用契约优先放到 `tests/contract/`。
- 文档、注释、Skill 正文、目录索引和软约束规则不写硬约束测试, 只在 review 中检查。

## 最小验证入口

- 测试命令以 `tests/README.md` 和仓库 `README.md` 为准。
- 使用 `uv` 执行本地测试和脚本, 不在 Skill 中复制固定 pytest 命令。

## 板端路径判定与确认要求

满足任一条件即进入板端路径:

- 修改硬件驱动层
- 修改底盘运行时 owner 或控制执行内核
- 依赖真实串口、编码器、IMU、电机或 ticker
- 需要证明板端状态、模块导入、诊断输出或真实动作链路

进入板端路径后:

- 先完成可保留的本地自动测试。
- 再通过对话协作确认设备可连接、文件可上传执行、模块可导入、最小诊断可用与现场动作结果。
- 板端确认以操作步骤、预期、实测结果、失败归因与后续复盘要点作为依据。
- 不接受只凭串口有输出、主观体感或“让车动一下”作为完成依据。

## 内存与运行时装配门禁

- 对共享底盘执行内核、角色运行入口、诊断面和板端探针的改动, 第一关注点是不要破坏最小内存占用边界。
- import-time 副作用必须可见且受限, 禁止目录扫描、自动发现、自动注册和重型单例初始化。
- 模块级可变运行时全局状态属于阻断项。
- 可延迟功能不得放回构造期无条件初始化。
- 热路径不得新增无解释的大字符串拼接、大临时容器或动态分配。
- 新增常驻对象前, 先写清唯一 owner、加载阶段、分类、触发条件和必要性。
- 改动运行时 owner 时, 至少要预想并记录 `mem_free_after_import`、`mem_free_after_core_init`、`mem_free_after_feature_init`、`mem_free_runtime_idle` 和 `diag_survival` 的影响。
- 若板端最小诊断面、延迟加载边界或 owner 唯一性说不清, 先停下补边界。
