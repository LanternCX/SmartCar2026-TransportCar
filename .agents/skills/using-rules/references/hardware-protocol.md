# 硬件与协议规则

## 适用范围

- 本页用于实现前核对硬件事实、串口链路、协议入口、坐标语义和联调确认边界。
- 完整串口协议正文统一维护在 `docs/developer/protocol.md`。
- 状态编号、事件编号和状态同步语义统一维护在 `docs/developer/state.md`。
- 控制职责与视觉职责分别联读 `docs/developer/control.md` 与 `docs/developer/vision.md`。

## 硬件事实确认规则

- 未在仓库正文或代码中明确给出的引脚、串口、电平、接线或设备行为事实, 必须先问用户, 禁止猜测。
- 现场判断角色时先看输入电平, 不要直接按开关朝向口头推断。
- D8 / D9 角色输入按 `src/vision/vehicle_role.py` 解码:
  - `D8=0, D9=1` 表示主车。
  - `D8=1, D9=0` 表示辅车。
  - 其他组合属于异常输入。
- `src/main.py` 使用 `C8 / C9` 长按做启动脚本分发:
  - 长按 `C8` 进入 `src/script/pid_identify.py`。
  - 长按 `C9` 进入 `src/script/calibrate_gyro.py`。
  - 不按按钮进入 `src/script/remote_control.py`。
  - 两个按钮同时长按视为异常启动场景。

## 串口链路事实

- `UART3`: 上位机 -> 主车, 用于上游速度控制。
- `UART8`: 主车 -> 辅车, 用于主辅速度前馈与状态同步短包。
- `UART6`: 辅车视觉 -> 辅车, 用于视觉速度修正。
- 未确认硬件接线的视觉同步链路不指定串口号。
- 新增串口链路前, 先登记串口号、方向、用途和报文类型。

## 协议使用规则

- 字段、报文格式、示例和接收规则以 `docs/developer/protocol.md` 为准。
- 状态编号、目标编号、事件编号和状态跳转语义以 `docs/developer/state.md` 为准。
- 高频速度链路使用短文本和最新值语义, 不携带冗长调试字段。
- 低频可靠同步使用状态同步短包、确认包、重复发送和幂等处理。
- 正式协议不维护兼容层和多套字段双轨说明。
- 车端通用状态查询不作为正式串口协议主线; 需要运行状态交换时, 使用状态同步或事件回报包。

## 坐标与参考系规则

- 坐标字段语义与协议格式以 `docs/developer/protocol.md` 为准。
- 车体正方向以 `docs/developer/control.md` 和底盘实现共同核对; 若文档、代码或现场表现冲突, 先停下向用户确认。
- 说“左 / 右 / 前 / 后 / 顺时针 / 逆时针”时必须标明参考系。
- 涉及 `x/y/angle`、`vx/vy/omega`、`dx/dy/d_angle` 时, 必须说明是世界系、车体系、绝对量还是相对量。
- 没有板端确认记录前, 不要口头改写方向含义或靠改增益符号掩盖方向问题。

## 视觉输入边界

- 车端底盘不处理图像数据。
- 主车角色入口负责 `UART3` 上游控制接入与 `UART8` 速度转发, 不消费视觉观测。
- 辅车角色入口消费 `UART8` 前馈输入与 `UART6` 视觉速度修正, 最终速度回到共享底盘执行链。
- 视觉端输出字段和速度修正语义以 `docs/developer/protocol.md` 与 `docs/developer/vision.md` 为准。
- 引入更多视觉设备、观测字段或环境感知能力前, 先明确职责分工与协议字段。

## 联调前检查与异常排查

- 启动新一轮联调前, 先补齐协议定义、串口方向、板端检查项和预期观测输出。
- 若出现方向异常, 按顺序排查: 发送格式、参考系理解、电机方向、编码器方向、IMU 校准。
- 输出结论前必须完成语义自检: 参考系、字段 / 控制量、阶段语义、相对量 / 绝对量。
- 联调输出使用统一失败分类: `connect_failed`、`deploy_failed`、`probe_failed`、`observe_failed`、`board_check_pending`。
