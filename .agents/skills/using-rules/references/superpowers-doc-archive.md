# Superpowers 文档归档规则

## 适用范围

- 本页只承接 `docs/superpowers/specs/` 与 `docs/superpowers/plans/` 的归档、搬运与目录整理规则
- 目标是统一 `specs/` / `plans/` 的历史文档归档口径, 避免每次按功能重新解释

## 归档主规则

- 当任务触及 `docs/superpowers/specs/` 与 `docs/superpowers/plans/` 的归档、搬运或整理时, 默认按已合并 `PR` 归档, 不按功能主线或当前是否仍常看做二次判断
- 只要文件能够明确归属到已合并 `PR`, 就直接进入对应 `archive/PR#<id>/`
- 若文件暂时无法直接反查到唯一 `PR`, 默认按文件日期就近归入时间最近的已合并 `PR`
- 不长期保留 `待确认` 中间桶; 若只是暂时查不到唯一 `PR`, 应尽快按时间规则归桶并删除空的 `PR#待确认`

## 根目录规则

- `docs/superpowers/specs/` 与 `docs/superpowers/plans/` 根目录默认只保留尚未归属到已合并 `PR` 的新文档
- 若某份文档已经能归到已合并 `PR`, 即使它仍经常被打开, 也不因此继续留在根目录

## 引用修正规则

- 当外部入口文档仍引用旧根路径时, 应同步把路径更新到新的 `archive/PR#<id>/` 位置
- 优先修正当前仍会被直接打开的入口文档、规则文档和 memory 留证
- archive 内部历史文档之间的旧根路径自引, 只有在本轮搬运直接造成理解断点时才处理, 不默认展开历史大清洗

## 执行顺序

- 先确认文件归属到哪个已合并 `PR`
- 再建立缺失的 `archive/PR#<id>/` 目录
- 再搬运文件
- 最后修正必要入口引用并删除空目录
