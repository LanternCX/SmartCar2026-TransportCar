# 硬件与协议规则

## 事实源与使用方式

- 完整 OpenArt 协议正文统一维护在 `references/openart-protocol.md`
- 本页只保留已确认硬件事实、联调入口和协议查阅路由, 不与完整长协议正文混排
- 若代码现状与正文冲突, 先核对当前代码事实与已确认硬件事实, 再收口正文或实现
- 若正文未明确给出引脚、串口、电平或接线事实, 必须先问用户, 禁止猜测

## 已确认硬件事实

- `src/boot.py` 中 Button 1-4 的板级引脚分别为 `C8`、`C9`、`C14`、`C15`
- `D8/D9` 角色输入带上拉电阻, 读到 `1` 表示开关关闭, 读到 `0` 表示开关闭合
- 现场判断角色时先看输入电平, 不要直接按开关朝向口头推断
- 板级上存在多路串口资源, 视觉链路的实际接入方式以运行时代码为准
- 当前运行时代码只保留 `vision/master/` 与 `vision/assistant/` 角色入口骨架, 未启用旧视觉输入链
- `UART3` 用于主车接收上游控制命令与查询, 不承担主辅转发语义
- `UART8` 用于主车到辅车的正式通信链路
- 在当前项目里, 无线串口协议链路直接作为遥控链路; `UART3` 协议控制链打通即视为遥控能力打通

## 视觉与坐标语义

- 坐标、字段语义与协议格式统一以 `references/openart-protocol.md` 为准
- 坐标与正方向固定为: `y+` = 前进, `x+` = 右移, `omega+` / `d_angle+` = 顺时针
- `dx/dy/d_angle` 表示车体系相对增量, `x/y/angle` 表示世界系绝对目标
- 说“左 / 右 / 前 / 后 / 顺时针 / 逆时针”时必须标明参考系
- `push_angle_deg = -90` 只能解释为相对当前复位零点的绝对航向目标, 没有板端确认记录前不要口头改写方向含义

## 协议正文路由

- 需要完整协议定义、链路约定、字段表与报文格式时, 直接查看 `references/openart-protocol.md`

## 视觉入口与重写边界

> 本段只保留稳定协议事实与必须统一的状态机判据; 临时排障经验不要直接写进这里。

- 当前运行时代码不消费旧视觉输入, 不维护旧视觉状态机, 不提供 `?vision` 查询
- 当前保留的是主辅角色入口骨架, 具体视觉协议与状态机边界以后续重写实现为准

## 联调前检查与异常排查

- 启动新一轮视觉联调前, 必须先补齐新的协议定义、查询口径与板端检查项, 不能沿用已删除旧视觉链的联调结论
- 若出现方向异常, 先按顺序排查视觉发送格式、车体坐标理解、电机方向、编码器方向
- 输出结论前必须完成语义自检: 参考系、字段 / 控制量、阶段语义、相对量 / 绝对量
- 联调输出必须使用统一失败分类: `connect_failed`、`deploy_failed`、`probe_failed`、`observe_failed`、`board_check_pending`

> 本页负责“硬件 / 协议事实 + 联调核对口径”, 不负责比赛方向与任务优先级。
