## 控制系统固定事实

- 控制层级固定为位置环 -> 速度环 -> PWM 输出
- 反馈来源固定为编码器的速度 / 里程计与 IMU 的航向信息
- 控制模式至少区分速度模式、位置模式、角度保持模式
- 当前主线的底盘基础约束固定为: 主辅车默认维持自身方向闭环, 不允许把方向保持写成后补增强项
- 主车当前阶段业务上不主动运动, 但底盘层仍必须保留与辅车同等级的通用运动能力与方向稳定能力
- 改算法前先确认硬件基线: 编码器方向、电机方向、IMU 校准
- 参数辨识先行, 使用 `pid_identify.py` 生成最新电机参数
- 当前主线只保留用于前馈的参数辨识, `PID` 参数不进入自动辨识范围
- 当前 OpenArt 跟随主线的控制量坚持位置式表达, 不退化成速度式主控制链路
- 当前 OpenArt 跟随主线保持“主车只发二维 `dx/dy`、不发外部角度目标”的业务边界, 但辅车执行层本地方向闭环必须始终开启
- 角度主链路优先依赖零漂校准 + 滤波 + 四元数积分 + 动态控制周期, 不依赖视觉角度
- `xy` 编码器积分不作为高精度位置真值, 但 `xy` 位置式控制仍保留为多段误差修正链路
- 5ms 控制周期预算属于实现阶段硬约束, 超预算先降复杂度, 再讨论新特性
- 视觉状态机可以直接接入高频跟随主流程, 不需要额外的低频 / 高频解耦层
- 视觉抖动导致的状态抖动通过滤波解决, 不通过架构层面的解耦规避
- 状态机任务设计上应主动避免"等待完成"的阻塞语义, 不以架构解耦作为补救手段

## 调参与诊断顺序

- 控制系统调参流程固定为: `calibrate_gyro.py` -> `pid_identify.py` -> 内环 -> 外环 -> 航向保持 -> 组合轨迹联调
- 控制问题应按固定顺序排查: 振荡、响应慢、稳态误差、航向漂移、轨迹偏差
- 进入设备路径后, 对控制相关变更必须同步准备调参与验证记录, 不接受只凭主观体感下结论
