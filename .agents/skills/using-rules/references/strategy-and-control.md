## 控制系统固定事实

- 控制层级固定为位置误差收敛 -> 速度环 -> PWM 输出
- 反馈来源固定为编码器的速度 / 里程计与 IMU 的航向信息
- 控制模式至少区分速度模式、位置模式、角度保持模式
- 当前主线的底盘基础约束固定为: 主辅车默认维持自身方向闭环, 不允许把方向保持写成后补增强项
- 主车在项目路线目标中承担搜索、切换和协同编排职责, 底盘层仍必须保留与辅车同等级的通用运动能力与方向稳定能力
- 改算法前先确认硬件基线: 编码器方向、电机方向、IMU 校准
- 参数辨识先行, 使用 `pid_identify.py` 生成最新电机参数
- 当前主线只保留用于前馈的参数辨识, `PID` 参数不进入自动辨识范围
- 当前主车通过 `UART3` 接收上游控制命令, 再经 `UART8` 向辅车转发速度前馈
- 当前辅车最小跟随闭环按角色层速度目标实现: `vision/assistant/` 负责接管 `UART8` 现有控制协议中的速度控制量与 `UART6` 本地视觉观测, 在角色层内完成融合后写回共享底盘执行链
- 这条辅车闭环使用现有协议边界: `UART8` 保持现有控制协议, 角色层优先消费其中的 `vx / vy / omega` 速度控制包, 其余查询和非速度控制命令透传给共享底盘; `UART6` 使用 `x=<x>,y=<y>` 视觉协议, 不新增主辅通信协议主题
- 共享控制内核只负责通用底盘执行与方向稳定, 不承担辅车跟随角色逻辑, 实现阶段不要把融合或跟随语义压回 `TransportCar`
- 辅车角色层闭环属于已实现事实, 主车侧路线目标不写成完整运行链事实
- 角度主链路优先依赖零漂校准 + 滤波 + 四元数积分 + 动态控制周期, 不依赖视觉角度
- `xy` 编码器积分不作为高精度位置真值, 但 `xy` 位置式控制仍保留为多段误差修正链路
- 5ms 控制周期预算属于实现阶段硬约束, 超预算先降复杂度, 再讨论新特性
- 高频跟随相关实现先收口输入边界、状态所有权与角色层职责, 再决定是否需要额外解耦层
- 若出现状态抖动, 先排查输入时效、协议边界和滤波, 不要直接扩大架构层次
- 状态机任务设计上应主动避免阻塞式等待语义, 保持控制周期持续推进

## 调参与诊断顺序

- 控制系统调参流程固定为: `calibrate_gyro.py` -> `pid_identify.py` -> 内环 -> 外环 -> 航向保持 -> 组合轨迹联调
- 控制问题应按固定顺序排查: 振荡、响应慢、稳态误差、航向漂移、轨迹偏差
- 进入设备路径后, 对控制相关变更必须同步准备调参与验证记录, 不接受只凭主观体感下结论
