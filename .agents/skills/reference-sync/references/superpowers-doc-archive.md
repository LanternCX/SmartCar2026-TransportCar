# Superpowers 文档归档规则

## 适用范围

- 本页承接 `docs/superpowers/specs/` 与 `docs/superpowers/plans/` 的归档、搬运与目录整理规则。
- 目标是统一 specs / plans 的归档口径，避免每次按功能重新解释。
- 本页不负责具体设计正文或执行正文。

## PR 状态确认

- PR 归属和合并状态优先通过本地 git 记录、GitHub PR 页面或用户提供的 PR 信息确认。
- 无法确认唯一 PR 时，先记录不确定性，并按文件日期就近归入时间最近且已确认合并的 PR。
- 无法确认任何已合并 PR 时，保留在根目录并在本次交付中说明待确认项。

## 归档主规则

- 当任务触及 `docs/superpowers/specs/` 与 `docs/superpowers/plans/` 的归档、搬运或整理时，默认按已合并 PR 归档，不按功能主线或打开频率做二次判断。
- 只要文件能够明确归属到已合并 PR，就直接进入对应 `archive/PR#<id>/`。
- 文件暂时无法直接反查到唯一 PR 时，按文件日期就近归入时间最近的已合并 PR，并在交付说明中标注依据。
- 不长期保留 `待确认` 中间桶；不能确认合并 PR 的文件保留在根目录并记录待确认原因。

## 根目录规则

- `docs/superpowers/specs/` 与 `docs/superpowers/plans/` 根目录默认只保留尚未归属到已合并 PR 的新文档。
- 若某份文档已经能归到已合并 PR，即使它经常被打开，也不因此继续留在根目录。

## 引用修正规则

- 当外部入口文档引用根路径时，同步把路径更新到对应 `archive/PR#<id>/` 位置。
- 优先修正当前会被直接打开的入口文档、规则文档和 memory 留证。
- archive 内部历史文档之间的根路径自引，只有在本轮搬运直接造成理解断点时才处理。

## 执行顺序

1. 确认文件归属到哪个已合并 PR。
2. 建立缺失的 `archive/PR#<id>/` 目录。
3. 搬运文件。
4. 修正必要入口引用并删除空目录。
