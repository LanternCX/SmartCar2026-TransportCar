# Vision Core

- 本仓库维护 RT1021 车端角色运行、底盘执行、主辅通信和本地视觉链路接入; OpenART 仓库维护识别、速度计算、task 同步确认和事件回报。
- 视觉仓库不维护车端全局状态机; 本仓库不实现红色目标、色标或边线图像识别算法, 只消费视觉侧速度和事件。
- 主车 OpenART 负责目标识别、搜索速度、搬运入口对正、结束判定、绕行视觉修正和回库黄线停车判定。
- 辅车 OpenART 负责主车色标跟随、找物体、搬运入口对正、绕行视觉修正和自主回库黄线巡线。
- 主车 RT1021 负责本车 `UART6` 视觉 task 编排、主车视觉速度接入、主车状态机调度和 `UART8` 主辅同步。
- 辅车 RT1021 负责 `UART8` 前馈输入、`UART8` 子状态同步、本车 `UART6` 视觉 task 同步、本车 `UART6` 视觉输入和共享底盘写回。
- 辅车角色层口径: `UART6` 视觉提供 `vx / vy`; `UART8` 前馈提供 `vx / vy / omega`; `vx / vy` 裸相加, `omega` 只取 `UART8`; 两路异步输入保持上一包。
- 主车与辅车分别通过本地开关选择纯 YOLO 或纯色块物体识别; 物体阶段每张图像只运行当前模式对应的检测器。
- OpenART 调试模式是绕过通信的上电识别预览入口; 只持续采图、识别和绘制候选, 不发送速度、事件或 ACK。
- 物体识别不使用隔帧、旧候选、ROI 跟踪、预测、动态阈值或底盘暂停/恢复; 单帧漏检立即按目标丢失处理。
- 任务物体类别可以跨阶段保持, 检测框、位置、面积和速度不跨图像复用。
- 视觉参考帧率只用于根据实际图像周期缩放控制输出, 不参与检测器选择。
- 视觉模式切换需要独立 `context_id`; 只换状态不换上下文时, 接收端可能把新任务包当成重复包忽略。
- 正式视觉入口不能携带调试默认上下文; 调试默认值只用于孤立探针, 不进入正式 task 编排。
- 坐标口径必须统一到同一层语义; 原始图像 Y、倒装矫正 Y、协议 Y 和状态机判据不能混用。
- 视觉状态机基于框边界关系切换阶段时, 协议层必须回传完整框; 不把单点观测硬塞给需要边界语义的状态机。
- 多检测输入下, 诊断快照跟随 selected input 路径; 不能默认用 protocol latest observation 代表状态机真实输入。
- 主车收到 `sync done` 只证明 OpenART 确认了同步消息, 不证明视觉上下文已经按预期应用; 需要用后续事件、速度或可观测输入验证。
- 调试视觉目标接近、远离、丢失和饱和问题时, 先看 hook 是否命中、目标远近单调性是否成立、速度是否已到限幅, 再扩大到状态机。
- 状态机与高频视觉闭环必须分离; 阶段锁语义不能进入高频控制链, 高频修正也不能推进主流程 hook 序号。
- 绕行视觉修正作为平移速度叠加处理, 不把目标误差重新解释成半径模型; 绕行修正参数独立于搜索、找物体和跟随参数。
- 回库 Play 事件窗口必须受步骤生命周期 gate 约束; 不能只靠状态编号过滤旧事件或早到事件。
- 回库黄线停车优先固定列采样这类可观测特征; 不用窗口数量、跳变次数或隐式状态扩展掩盖口径问题。
- 回库阶段要区分决策状态与运动行为; 视觉配置通过 hook 上下文切换, 不把发现标志或完成标志塞进速度包。
- 回库色标、黄线和目标搜索使用独立判定配置; 不复用不同任务的命中窗口。
- 取消状态时同步清理车端状态机、运行时入口、OpenART hook 分发和契约测试, 避免留下可触发旁路。
- 图像识别算法可以替换候选来源, 但车端协议、视觉事件语义和状态机消费口径保持稳定。
- 模型没有覆盖或现场已稳定的元素不强行纳入 YOLO 路径, 避免把可控改动扩大成训练与联调任务。
- YOLO 模型 owner 收口在运行入口或明确服务 owner, 不放无边界模块级可变状态。
- OpenART 视觉画面存在倒装/反转矫正语义; 写 ROI、底边、顶部、黄线和绕行判定时先确认当前使用的是原始图像坐标、矫正后显示语义、协议坐标还是状态机语义, 不按普通图像坐标直觉推断上下方向。
