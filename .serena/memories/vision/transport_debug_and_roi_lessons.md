# 搬运视觉调试与 ROI 语义教训

- 现场车运行时不能同时监听视觉串口消息；不要擅自要求开启 trace 或依赖视觉串口监听作为调试前提。
- 用户要求先分析时，不要直接改代码或打开调试能力；证据不足时先说明证据缺口，再征得同意后加日志或改诊断链路。
- 调试日志链路与行为修复要分开管理；如果已有未完成调试改动，先 stash，再单独处理当前行为问题。
- `OBJECT_X_TOLERANCE_PX` / `OBJECT_Y_TOLERANCE_PX` 的语义是对正/命中容差，不应再复用为正式搬运候选 ROI 裁剪窗口。
- 正式搬运候选筛选如果需要窗口，应使用独立参数，避免把目标在死区外过滤掉，导致后续速度计算拿不到目标。
- ROI 裁剪要先确认坐标语义：协议底边 Y 与图像坐标 Y 方向相反；横向需要闭环时不要用窄 X ROI 把死区外目标裁掉。
- 纯色块模式下也要检查候选生成、候选过滤、速度死区三段链路；不能只看目标识别记忆。
- 找不到物体不等于应该清理目标跟踪记忆；清理目标意图和当前帧是否找到目标是两件事，不能混为一谈。
- 每次涉及 commit 必须先给出提交信息并等待用户确认；提交子仓库后同步提交主仓库 submodule 指针。
