# Runtime Memory Optimization

- RT1021 + MicroPython 板端主线优先优化常驻总占用, 再优化碎片; 碎片只在后续存在大块连续分配风险时作为第一目标。
- 导入期通常是内存峰值; 能前移的正式运行依赖应在进入状态机前导入, 让大块常驻对象先分配并让峰值尽早暴露。
- `gc.collect()` 应在关键导入/初始化观测点和 verbose `mem_info` 前执行; `mem_info` 不先 GC 会把临时对象残留误判为常驻占用。
- 临时小对象通常不是长期碎片主因; 风险来自“若干临时小对象之后分配长期大对象”, 临时对象释放后留下的小洞难以服务后续连续大对象。
- 新增长期对象前先确认 owner、生命周期、是否跨单一运行周期保留、是否能局部化或复用; 只为诊断、日志、测试便利存在的长期对象默认不进板端主路径。
- 角色运行时和协议路径优先避免 qstr 压力: 字段名、状态名、来源标签、日志文本、字符串状态和字典快照都属于常驻成本; 能用整型常量、短字段、tuple/list 槽位或直接过程逻辑表达时, 不引入字符串键和测试便利字典。
- 诊断面保持最小观测口: 保留启动关键阶段、状态跳转和错误日志; 同步细日志、事件细日志、速度来源文本、快照字典和长期诊断计数默认不放入正式板端路径。
- 拆模块不自动省内存; 如果启动前仍会导入, 拆分可能增加模块对象和 qstr。只有把非主路径能力变成默认不导入时, 拆分才可能降低峰值。
- 结构更清晰但板端内存未改善, 不算内存优化。内存优化必须用板端 `mem_free/mem_alloc/mem_info` 或 `.mpy` 体量对比给出证据。
- 临时内存探针允许用于实测定位, 但提交前删除; 正式提交只保留稳定、必要的最小观测口。
