# Runtime Core

- 正式入口是 `src/main.py`; 不按按钮进入 `src/script/remote_control.py`; 测试模式下不按按钮进入 `src/script/test.py`。
- 长按 `C14` 上电进入参数辨识脚本; 长按 `C15` 上电进入陀螺仪校准脚本。
- 主车和辅车身份由车号读取结果决定, 不由启动按钮决定。
- 主车维护唯一任务决策主线, 避免多处动作仲裁; 辅车执行跟随、配合和状态回传。
- 共享底盘执行内核保持统一, 但主车和辅车使用各自硬件接线映射。
- 低压保护按车辆身份选择阈值: 主车 `11.5V`, 辅车 `3.7V`。
- 可靠事件清残留速度缓存和向底盘写零速度是不同动作; 位置或角度锁定期间不能让可靠事件零速度覆盖正在执行的锁定目标。
- 调试“状态到了但车没动”时, 先确认目标是否下发, 再查 `command_lock`、目标清空来源和后续输入覆盖, 不要只按状态机未跳转排查。
- 运行时性能问题先低频分段定位 `rx / step / tx`, 再缩小到单函数; 高频控制和通信热路径避免重复导入与持续打印。
- 阶段切换必须显式处理控制残留: 位置、角度和视觉 intent 从 active 变为 inactive 时, 需要释放上一拍保持目标、PID 积分和残留速度缓存。
- 连续视觉观测与一次性增量命令不能共用同一语义; 离散动作继续由锁保护, 高频视觉闭环在主控内部覆盖式刷新目标。
- 位置式控制要区分过渡目标和保持目标; 每个阶段都应明确理论保持角度, 不能继承上一阶段未完成的目标角。
- 视觉目标点误差适合保留位置式控制表达; 不因 `xy` 积分精度差就退化成速度式主控制, 角度链可靠时从视觉主链中剥离。
- 跨周期控制状态要显式保存平移模式、转向来源和持续速度目标; 宽泛布尔值不能同时表示是否激活、当前模式和转向来源。
- 角度环、速度环、前馈和姿态积分应使用同一拍真实时间差; 现场现象随打印量变化时, 优先怀疑时间基准不一致。
- 零周期保护可以保留朝向保持输出, 但速度环不能把零周期当成大时间步; 需要显式回退到固定控制拍长。
- 搬运闭环验收覆盖搜索、搬运、收尾和下一轮搜索; 搬运结束不是简单停车, 脱离、回身、横移和下一轮视觉 hook 都属于同一闭环。
- Stage 1 主机测试通过不能替代 Stage 2 或 HIL; Stage 2 是板端最小可信 smoke, Stage 3 是 `UART3` 人工或 AI 在环调试, 跳过 Stage 3 时验收口径不能写成完整通过。
- Stage 2 lite 只能证明最小 query / 结构化输出链路可执行; lite 回退既要避免完整业务对象初始化, 也要避免一次性读取大源码文件。
- RT1021 + MicroPython 内存排障要分启动期、初始化期、运行期和诊断期; 同时区分业务对象不足、日志格式化放大、导入期峰值和运行期高频分配。
- 板端 OOM 不总是瞬时分配不足; 脱机运行后再连接更容易复现时, 同步检查长期占用、堆碎片、模块级对象和分散 owner。
- 复位或 `Ctrl-C` 停止主循环不保证释放已创建的全局对象; 部署或排障前需要确认解释器中是否残留运行时对象。
- 低内存板端优先保留 `?health / ?tick / ?vision` 最小诊断面; 系统还活着但状态机不跳时, 先看最近 OOM 阶段、tick 前进和视觉输入, 不依赖高频日志判断。
- 当最小查询也只能返回 `MemoryError` 时, 问题通常已经收敛到当前堆状态无法承接诊断分配, 优先检查长期高占用和高频日志压力。
- 高频观测日志默认不放在 `INFO`; 诊断输出不能持续放大 `UART3` 写超时、控制周期抖动或日志格式化内存峰值。
- 运行时字符串配置允许人工输入时, 非法值不能静默失败; 否则现场排障会变成“没有日志且不知道原因”。
- 设备时序 bug 不能只靠主机测试闭环; `VSM TRANS`、航向变化、tick 和速度输出这类低频结构化证据用于定位残留动作发生在哪一拍。
