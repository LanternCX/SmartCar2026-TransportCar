# Protocol Core

- 串口职责: `UART3` 是 REPL/日志/现场调试; `UART6` 是本车 RT1021 与本车 OpenART; `UART8` 是主辅车直连。
- 两台车各自使用本车 `UART6`; 主车 `UART6` 和辅车 `UART6` 不是同一条物理链路。
- 正式通信使用固定长度 bytes 帧; 业务层处理 topic 与 body, 不直接读写 UART、不清 UART 缓冲、不处理 ACK 或重发。
- 高频速度链和低频可靠状态链必须分开分析; 车能动只证明 UDP 最新值链工作, 不代表 TCP/ACK 状态链闭环。
- 固定短帧必须有帧头和 CRC8; 只靠 mode/topic/role 扫描会在坏字节、半包、粘包和错位时误消费假帧并跳过真帧。
- 接收层必须跨轮询保留不足一帧的残片; 低频 ACK / 事件帧最容易因分段到达被吞掉。
- 高频 UDP 可以丢旧值, 但“允许丢旧值”不能替代可靠分帧、重同步和 CRC 校验。
- 车端与 OpenART 复制协议实现时, 任意帧格式、CRC、topic body 或可靠语义调整都必须两仓同步修改并同步验证。
- 真实联调默认按“车先上电、视觉后上电、串口分段到达”设计, 不按整帧同时到达的理想路径判断。
- 高频控制链优先短包和最新值; 低频状态同步必须具备确认、重发、幂等和可重同步能力。
- 无线模块或底层链路自带校验不能替代主控业务分帧; 业务层仍需要帧头、长度、CRC、topic 和残片拼接。
- 协议迁移必须同批处理运行时入口、主辅链路、视觉链路、文档和契约测试; 非正式协议入口和旁路测试需要同步清理。
- `UART6` 同时承载视觉与控制类数据时, 非当前字段或不完整载荷应在协议层被吞掉, 避免误落入手动命令或状态同步链。
- 带调试 trace 的串口验证应断言正式结果是否出现, 不把附加 trace 文本当作协议正文。
- 诊断 query 必须按来源串口回包; `UART3` 调试链路、`UART6` 本地视觉链路和 `UART8` 主辅链路不能共享模糊回包路径。
- 串口职责切换时先区分上游控制入口、本地视觉入口和主辅通信入口; 不能把一条链路的迁移误扩到其他入口。
- 业务 body 只编码 topic 的有效字段; 帧层统一补零并保持 15 字节固定帧长。
- `LOCAL_VISION_CONTROL` 只保留回库黄线 Gate 开关, 不包含 YOLO 暂停与恢复 action。
