# Architecture Core

- 竞赛主线重构不保留兼容层; owner 已经迁移时, 调用方应显式依赖目标 owner, 不用兼容 API 包一层维持表面兼容。
- `services/`、`utils/` 和共同前缀平铺文件不能当作长期收纳箱; 有状态、协议、生命周期或复杂协作的领域应收敛为明确分包。
- 行数达标不等于职责健康; facade、协议和状态机模块需要同时看 owner 边界、状态复制、装配时机和测试锁定。
- 对 RT1021 + MicroPython, 结构清晰不是充分验收标准; 若导入峰值、常驻内存和最小依赖加载没有改善, 拆分不算完成。
- 与运行时代码相关的 review 先回答新增了哪些常驻对象、为什么必须常驻、板端内存证据是什么, 再讨论结构美观度。
- facade 只读转发 owner 当前状态, 不缓存第二份运行时状态, 不在 import-time 装配重对象。
- 静态分析修复优先轻量契约和明确 MRO; 不为 MicroPython 运行时代码引入重型 typing 依赖, 并验证占位成员不会抢真实实现。
- 嵌入式运行时协作接口应显式声明能力, 不用 `TypeError` 等异常试探接口形态, 避免掩盖真实 bug。
- runtime owner 拆分先收口真实职责, 再保留必要的实例级 facade; facade 的存在不能成为多 owner 状态双写的理由。
- owner 下沉不自动代表编排层变薄; 超长单文件通常说明 import 面和定义密度仍然过高, 可以作为结构告警指标。
- 参考系统只作为参考代码时, 主线运行时必须自足, 不依赖参考目录模块、入口或测试面。
- 大规模裁剪先冻结删减顺序和裁剪清单, 再推进主线系统, 降低边重构边误删的风险。
- 文档是后续会话事实入口时, 文档口径、契约测试和归档边界同步维护; 归档核对优先按文件路径验证, 不用正文搜索替代。
- Skill、项目文档和 Serena memory 的职责分开: Skill 持有可执行工作流, 项目文档持有外部事实与项目决策, Serena memory 持有跨会话调试和设计判断。
- 面向 agent 的 Skill 优先保留决策入口和风险边界, 不复制完整命令手册。
