# Memory Policy

- Serena memory 是本项目唯一默认记忆系统; 协作记忆目录不是默认上下文来源。
- 记录门槛: 只写稳定、非显而易见、能减少未来重复探索的信息。
- 应记录: 设计原因、路线取舍、失败方案、硬件/比赛/板端约束、调试根因、跨仓库同步边界、完成标准。
- 不记录: 代码能直接读出的行为、接口清单、函数调用流程、一次性过程日志、失效阶段计划、测试输出流水账。
- Debug 结论写成问题模式、触发条件、根因、以后如何识别和验证; 不保存完整排查流水。
- Refactor 结论写成边界和不能混淆的职责; 不保存改名、搬文件和阶段过程。
- Milestone 结论写成仍影响决策的能力边界和阶段约束; 不保存过期路线回顾。
- 当代码、文档或硬件事实改变导致 memory 过期时, 直接更新或删除 memory 中对应结论, 不保留历史性口吻。
- 若需要完整演化追溯, 优先查 GitHub issue / PR / git log, 而不是长期保留大段项目流水账。
