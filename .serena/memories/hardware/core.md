# Hardware Core

- 底盘形态: 主车和辅车各一台全向车底盘。
- 视觉分工: 主车安装两颗正交视角摄像头; 辅车车体提供可识别标记; 辅车底盘不处理图像数据。
- 主辅链路: `UART8` 直连, 用于速度前馈、辅车子状态同步和辅车结果回报。
- 本地视觉链路: 两台车各自用本车 `UART6` 连接本车 OpenART。
- 调试链路: `UART3` 接入 REPL, 用于板端日志和现场调试。
- 边界检测: 灰度传感器服务搬运收尾确认。
- 陀螺仪零飘结果保存到 `/flash/gyro_offset.txt`; 电机辨识结果保存到 `/flash/ident_params.txt`。
- 参数辨识中速度除以 3 是三轮全向底盘耦合口径, 不应误判为 bug。
- 主车运行时姿态口径必须对齐板端姿态检查链路的 `yaw_deg`; 姿态、轮向映射和动态 dt 会共同影响控制手感。
- 跑通过的辨识脚本和诊断脚本是接线、方向与采样事实的可执行参考; 运行时不要另写一套方向映射或采样语义。
- 参数辨识不能修复补偿链没有启动的问题; 先确认目标锁定、采样、积分、补偿输出和目标轮速链路。
- 硬件事实缺失时先查仓库文档和测试, 仍缺失则问用户, 不猜引脚、接线或设备行为。
- 板端脚本按平铺上传和直接运行设计; 不假设主机侧包结构、`os.path`、`types`、`__file__`、`__package__` 或 `__spec__` 在 MicroPython 上稳定可用。
- 主机代码修正不等于板端文件已更新; 涉及真机问题时需要核实设备上的实际文件或行为, 不能用主机侧搜索替代。
- `raw REPL` 接管失败不直接归因为工具错误; 板子运行态、串口窗口、复位时机和固件状态都属于同级排查对象。
- 同代码换板后现象显著改善时, 板子硬件状态或 MicroPython 固件状态异常属于正式排查方向。
- 板端首个失败点持续后移时, 按最新 traceback 修当前 blocker; 不把后续兼容问题继续归因为 OOM。
- 对 `IMU660RX`、编码器和底盘采样链, 采样触发、数据引用绑定和时间步长来源按设备示例逐项对齐, 不靠主机侧直觉补齐。
