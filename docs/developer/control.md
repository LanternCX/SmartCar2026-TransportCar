# 电控设计

> 说明：正式基线使用单一 `src/`。入口使用 `src/main.py` 与 `src/script/*`，脚本分发采用 `C8/C9` 长按。

## 串口协议入口

正式串口通信协议见 [串口通信协议](protocol.md)。本文件只说明控制链和角色层事实，不承载完整协议正文。

## 控制目标与主要特性

- **三轴独立控制**：支持 `x` 轴（横向）、`y` 轴（纵向）和 `w` 轴（旋转）三个方向的独立速度或位置控制
- **双模式控制**：
  - **速度模式**：直接指定目标速度，车模保持运动
  - **位置模式**：指定目标位置/角度，车模按位置误差直接收敛并锁定
- **全向运动能力**：采用三轮福来轮布局，支持任意方向运动
- **自动姿态保持**：当角速度接近 0 时自动进入角度保持模式，保证车模不会因干扰而出现航向角漂移
- **参数辨识与校准**：直流电机（无电流环）的参数辨识和自动陀螺仪零飘校准
- **多层滤波架构**：编码器采用中值滤波、双窗口线性回归滤波等多种滤波方案
- **分层控制**：位置误差收敛与速度环闭环配合
- **运动锁定机制**：对相对位置目标等会累加运动结果的控制输入进行加锁，避免重复输入导致非预期位移

## 有效口径

- 项目路线目标按主车维护“寻找态状态机集 + 搬运态状态机集”的任务决策主线理解。
- 实现路径收口为主辅角色层分工；主车负责 `UART3` 上游控制接入、`UART8` 当前底盘速度转发、本车 `UART6` 主车视觉 hook 通信与本地底盘并行执行，主车侧的环境理解、目标搜索、状态切换和协同编排属于路线目标范围。
- 主车与辅车都参与运动，两车底盘闭环能力都属于通用能力边界，在目录结构与算法设计中一并维护。
- 正式代码结构使用单一 `src/`，相关脚本路径统一按 `src/script/...` 理解。
- 入口组织使用 `src/main.py` 与 `src/script/*`；按钮长按脚本分发采用 `C8/C9`。
- 主辅通信方案按 `UART8` 直连理解；视觉运行入口统一收口在 `vision/master/` 与 `vision/assistant/`，主车按当前写入共享底盘的速度目标经 `UART8` 持续向辅车发送前馈；辅车角色层把 `UART8` 作为前馈输入、把 `UART6` 作为视觉输入。
- 高速多车通信与速度前馈属于正式控制主线能力，用于增强双车协同跟随的响应速度和稳定性。
- 纯视觉跟随本身响应不够快，闭环容易偏软，因此需要把主车的运动意图以速度前馈方式及时转发给辅车。
- 辅车最小闭环通过 `vision/assistant/` 角色层接入共享底盘执行链，由角色层负责 `UART8` 与 `UART6` 的接口编排；两路短包按 [串口通信协议](protocol.md) 的链路定义解释，并复用同一套共享解析边界；最终底盘接收的是两路平移速度的按轴裸相加结果与 `UART8` 或底盘本地角度控制提供的旋转输入。
- 辅车在 `ASSISTANT_FOLLOW` 中对两路输入采用“保持上一包”的语义：`UART8` 输入包形成前馈向量，`UART6` 输入包形成视觉向量；任一路输入包未出现的速度轴按 `0` 处理；没有新包时继续沿用该路上一包，直到被新包改写或被显式零包清空。
- 辅车在 `ASSISTANT_IDLE` 中清空两路速度缓存并写入零速度目标, 后续速度短包不再更新角色层速度缓存, 也不再写入非零底盘速度。
- 辅车在 `ASSISTANT_APPROACH_OBJECT` 中清空两路运动输入, 等待本地视觉确认找物体同步；确认后只使用 `UART6` 本地视觉速度, 不叠加 `UART8` 前馈。
- `UART8` 与 `UART6` 的速度短包由同一份共享解析边界处理，避免两路在字段顺序、缺省轴和非法输入判定上各走各的口径；具体字段归属以 [串口通信协议](protocol.md) 为准。
- `UART3` 使用上游控制链路：主车从 `UART3` 接收速度短包，并在本地共享底盘执行；主车按 [串口通信协议](protocol.md) 把当前底盘速度目标经 `UART8` 持续转发给辅车；辅车角色层把 `UART8` 视为前馈输入、把 `UART6` 视为视觉输入。
- 这条辅车闭环复用共享底盘的速度执行能力，`TransportCar` 不承担辅车跟随角色逻辑，也不为这条能力新增角色分支。
- 前馈策略按状态切换理解：寻找相关跟随和搬运相关跟随都要用到前馈，但它们服务的视觉输入和协同目标不同。
- 正式验证口径由本地自动测试和对话协作记录组成；板端联调、动作确认与现场复盘统一在协作过程中完成并记录。


## 主车物体搜索与绕行控制边界

- 主车物体搜索状态流为 `IDLE -> SEARCH_OBJECT -> ORBITING -> SEARCH_OBJECT`。
- 主车搜索运行入口进入角色周期后主动进入 `SEARCH_OBJECT`。
- `SEARCH_OBJECT` 中，主车平移速度来源为 OpenART Vision master 通过本车 `UART6` 发送的 `v,<vx>,<vy>`。
- `SEARCH_OBJECT` 中，主车 RT1021 不根据 `o` 观测包计算搜索 P 控制量。
- `SEARCH_OBJECT` 中，主车状态机不显式接管 `omega`。
- 底盘本地方向保持继续用于抑制航向漂移。
- 主车视觉事件只触发主车判断，不直接迁移全局状态。
- 主车收到匹配 `context_id` 的 `TARGET_FOUND` 后, 由主车状态机发起辅车 idle 同步。
- 主车等待辅车 idle ACK 时停止本车搜索运动, 不应用新的主车视觉搜索速度, 也不开始绕行。
- 辅车 idle ACK 到达后, 主车进入 `ORBITING`。
- `ORBITING` 中，主车使用共享底盘统一绕行模式绕到上电基准航向的绝对 `+90°`。
- `ORBITING` 中，主车不使用主车视觉搜索速度和 `UART3` 上游速度覆盖绕行控制。
- `ORBITING` 完成后主车回到 `SEARCH_OBJECT`，继续使用视觉速度对正目标，并向辅车同步找物体子状态。
- 辅车找到目标并回报后，主车只发起一次辅车绕行同步。
- 辅车绕行完成后回到本地持续对正目标，不再因为后续对正再次发起绕行。
- 同一控制拍内存在合法 `UART3` 上游速度包和合法 `UART6` 视觉速度包时，角色层优先使用 `UART3` 输入作为最终底盘速度；同拍没有合法 `UART3` 上游速度包时，主车视觉 `v` 搜索速度生效。
- 主车 `UART6` 视觉速度按最近一个合法 `v,<vx>,<vy>` 包保持；收到显式零包 `v,0,0` 后清空视觉速度。
- 上下文不匹配的合法视觉事件需要确认，但不触发状态跳转。

## 核心控制流程

```
1. TransportCar 初始化
   ├─ 硬件初始化（UART、IMU、电机、编码器）
   ├─ 参数加载（电机辨识参数、陀螺仪零偏）
   ├─ 滤波器初始化
   └─ PID 控制器初始化

2. 定时器启动（5ms 周期）
   └─ pit1.callback(car.mark_tick) 触发 car.step()

3. 每周期执行 step()
   ├─ 读取传感器数据（编码器、IMU）
   ├─ 编码器滤波 + 速度计算
   ├─ IMU 姿态解算（四元数积分）
   ├─ 里程计更新（位置和航向角）
   ├─ 角色层接管输入编排（辅车路径）
   ├─ 串口短包接收与解析
   ├─ 速度/位置模式切换和锁定逻辑
   ├─ PID 计算（位置环 → 速度环 → 电机输出）
   └─ 运动学逆解（机器人速度 → 三轮轮速）

4. 电机驱动 + UART 反馈
```

## 控制模式详解

> 说明：本节描述控制算法能力边界；相关边界变化时同步修订本节。

### 速度模式（Velocity Mode）

指定目标速度，车模以该速度持续运动。

速度控制入口按“平移轴 / 转向轴”分开处理：

- `vx/vy` 只接管平移轴目标，不会顺手清掉 `angle`
- `omega` 只接管转向轴目标，不会顺手清掉 `x/y`
- 因此 `vx/vy + angle` 会在同一控制拍里融合成“边走边转”

当 `omega` 接近 0 时（< `HOLD_SPEED_EPS`），系统自动进入**角度保持模式**，即：
- 保持目标航向角不变
- 对航向角偏差使用 PID 反馈控制自动纠正
- 防止车模因外界干扰而漂移

### 位置模式（Position Mode）

车模按车体位置和目标位置之间的误差直接生成速度目标，并在误差收敛后锁定在目标位置/角度。

**位置控制流程**：
1. 计算位置偏差（目标 - 车体位置）
2. 按比例系数 `POS_KP` 直接把位置误差映射成目标速度，并按 `POS_MAX_SPEED` 限幅
3. 目标速度传入速度环进一步闭环计算
4. 当位置误差满足 `POS_TOLERANCE` 时，认为达到解锁条件并退出锁定状态

### 运动锁定机制（Motion Lock）

为了防止相对运动目标重复输入时位移累加，系统引入运动锁定：

- **进入锁定**：写入位置/角度目标时
- **锁定期间**：允许新的位置或模式控制输入直接覆盖既有目标
- **跨轴并存**：平移轴与转向轴目标允许同时存在，最终在控制拍末端统一融合到三轮目标速度
- **解除锁定**：位置到达且速度静止，或被复位流程打断
- **状态观测**：诊断字段用于区分状态是 `locked`、`unlocked` 还是 `none`

## 控制算法

> 说明：本节中的算法描述用于说明实现边界与控制结论；具体代码组织允许按内存约束和运行时边界做实现级整理。

### 前馈 + 反馈两层控制结构

```
目标速度 → 前馈补偿 + 速度环 PID 输出 → PWM 占空比 → 电机
                     ↑
                  编码器反馈
```

- **前馈**：基于电机参数辨识结果（增益 `K` 和时间常数 `tau`），预测目标转速所需的 PWM 占空比，也就是通过参数辨识计算出一个估计的目标速度到电机占空比的映射关系，在无负载的情况下是很准的，但是有负载的时候还是需要通过闭环控制来补偿。
- **速度环**：使用编码器反馈的实际速度进行增量反馈修正，并叠加前馈补偿；速度环带有二次误差项，不是简单的单层 PD 环。

由于全向轮的性质，实际上车模在运动过程中各轮的阻尼存在各向异性，也就是在每个运动方向上的阻尼并不一致，前馈也因此并不准确。

### 编码器滤波与速度计算

N20 自带的八线霍尔编码器精度和稳定性都没有，因此采用多层滤波策略通过离散的速度样本估计真实速度：
1. **中值滤波**：去除随机脉冲干扰
2. **差分限幅滤波**：限制单周期速度变化率，防止陡峭跳变
3. **双窗口线性回归滤波**：对脉冲序列进行线性拟合，提高速度计算精度
4. **输出低通**：进一步平滑最终速度估计

### IMU 姿态解算（四元数积分）

```
IMU 原始数据（加速度 + 角速度）
     ↓
四元数积分（每周期更新）
     ↓
四元数 → 欧拉角（Yaw/航向角）
```

## 参数辨识

### 电机参数辨识（`src/script/pid_identify.py`）

目的：自动测定电机的动态特性（增益和时间常数），用于前馈补偿。

**流程**：
1. 给电机施加阶跃 PWM 指令（`IDENT_STEP_DUTY = 5000`）
2. 在 4 秒内采集编码器反馈数据
3. 使用系统辨识算法（IMC 方法）拟合直流电机无速度环的一阶模型：`G(s) = K / (1 + tau*s)`
4. 计算三个轮参数（K 和 tau）之后保存到 `/flash/ident_params.txt`

### 陀螺仪零飘校准（`src/script/calibrate_gyro.py`）

目的：测定陀螺仪在静止状态下的输出偏差，用于姿态解算补偿。

**流程**：
1. 采集 2000 个 IMU 样本（车模完全静止）
2. 计算各轴平均值和标准差
3. 保存陀螺仪三轴零点到 `/flash/gyro_offset.txt`

不进行此步骤会导致航向角长期漂移（尤其是相对位置模式）。
