# 项目核心方案

> 说明：当前正式基线采用单一 `src/`，并已切到 `main.py` 单入口 + `C8/C9` 长按脚本分发。若讨论更深层的 3.0 运行时拆分，再查看对应设计文档。

> 本文件只定义项目方向，不展开具体技术实现。
>
> 除被更新设计文档显式覆盖的项目外，本文件仍是项目最高优先级方向共识，所有后续讨论应以此为基础。
>
> 实现规则、TDD 流程与内存装配门禁统一维护在 `using-rules` 私有参考页。

## 1. 总目标

- 第一目标：稳定完赛。
- 第二目标：在稳定完赛后逐步提速。

## 2. 方案路径

> 说明：本节按当前正式基线描述项目方案。入口层已经完成 `main.py` 适配，更深层的运行时拆分仍属于下一轮主题。

- 采用主辅协同。
- 主车负责环境理解、任务决策与唯一任务状态机维护。
- 辅车负责配合执行与状态回传, 不处理图像数据。
- 两车通过保持稳定相对关系完成搬运。
- 主车统一仲裁双摄观测和主辅动作控制。
- 主车与辅车在职责上显式区分：主车负责视觉处理与唯一任务状态机，辅车负责命令执行与状态回传；当前仓库正式目录统一为单一 `src/`。
- 当前阶段虽然业务上采用“主车不主动运动、主车只控辅车随动”，但主辅车底盘都默认维持自身方向闭环，不允许把方向保持写成后补增强项。
- 主车当前不主动运动只表示本阶段业务验收范围，不表示主车底盘缺失基础运动能力；主车底盘仍应保留与辅车同等级的通用运动能力与方向稳定能力。

## 3. 当前硬件条件

### 现状

> 说明：本节描述当前硬件条件与当前链路口径。

- 底盘形态：两台全向车底盘（主车 + 辅车）。
- 控制分工：
  - 主车承担双 UART 持续接收、任务状态机、决策与调度。
  - 辅车承担执行、配合与状态回传。
- 视觉分工：
  - 主车安装两颗摄像头, 视角正交布置。
  - 两份视觉代码可分开维护, 但必须遵循统一车端协议。
  - `camera_id` 只表示物理相机身份, 不表示职责相机。
  - `category` 只表示检测类别, 可在不同物理相机上重复出现。
  - 辅车车体提供可识别标记, 辅车底盘不处理图像数据。
- 通信方式：当前阶段主辅通过 `UART3` 直连通信协同。
- 无线串口控制链路直接作为当前阶段的遥控链路；`UART3` 协议控制链打通即视为遥控能力打通。
- 视觉链路采用 `UART6` / `UART8` 两路持续回传，由主车主动接收。

### 方向增量

- 新增灰度传感器用于边界检测。
- 目标是把“是否推到边界”从视觉判断升级为“传感器可直接判定”。
- 该能力用于提高越线确认的稳定性与一致性。
- 视觉协议需要从“单框输入”升级为“单次查询对应单相机当前帧, 可返回多条检测结果”。

## 4. 搬运策略

> 说明：本节描述当前搬运策略。主车主动参与运动属于下一轮主题。

- 主车使用一套任务状态机统一管理找目标、辅车对正、搬运与避障。
- 近场相机负责搬运物体与辅车标记观测。
- 环境相机负责避障与环境观察。
- 每路相机持续回传当前缓存帧信息，主车按最近有效结果做双摄仲裁，并允许单帧对应多条检测结果。
- 主车必须在车端完成跨相机仲裁, 不把物理相机硬编码成唯一类别来源。
- 主车融合双摄观测后，当前阶段负责驱动辅车动作。
- 主车当前阶段只给辅车下发二维 `dx/dy` 随动控制，不给辅车下发外部角度目标；辅车应在本地方向闭环保持开启的前提下执行随动。
- 两车车头相对夹持目标物。
- 阵型保持不变，整体横向移动完成搬运。
- 每次搬运完成后，不重建阵型，直接进入下一目标。
- 依靠全向移动能力做路径调整与避障。

## 5. 核心原则

- 优先成功率，不追求早期极限速度。
- 优先连续完成能力，而不是单次最快。
- 优先可恢复能力，避免一次异常导致全局失败。
- 任何优化都不能破坏稳定完赛能力。
- 当前正式验证主线由本地自动测试和对话协作记录组成；板端状态、真实动作与现场表现统一通过协作过程记录结果。
- 任务状态机只允许主车维护一份，不允许多处维护动作决策主线。
- 视觉实现可以分开维护，但车端协议必须统一。
- 视觉主线采用双 UART 持续回传口径。
- 对福来轮底盘而言，方向保持是基础能力，不是额外优化项；当前主线验收必须同时关注“能随动”和“朝向稳定”。

## 6. 进度分层

### 阶段一：可完成

- 能稳定完成单次搬运。
- 出现干扰后可继续任务或安全退出。

### 阶段二：可连续

- 能在保持阵型条件下连续搬运多个目标。
- 任务切换平稳，不依赖人工重置。

### 阶段三：可提速

- 在不降低成功率前提下缩短单次耗时。
- 对障碍和扰动保持稳定表现。

## 7. 成功判据

- 搬运成功率稳定。
- 连续搬运能力稳定。
- 异常情况下具备可恢复或可控退出能力。
- 全流程可重复，不依赖偶然状态。
- 边界判定稳定，不依赖单一视觉条件。
- 当前阶段的成功判据关注双 UART 持续接收稳定性。
- 主车能够稳定识别辅车标记、搬运物体与障碍信息，并在当前阶段稳定驱动辅车动作。

## 8. 补充方向

- 灰度传感器作为边界检测通道，纳入完赛主线能力。
- 最终判定逻辑优先追求“稳定一致”，不追求复杂判断。
