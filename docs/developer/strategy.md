# 项目核心方案

> 说明：正式基线采用单一 `src/`，入口按 `main.py` 单入口 + `C8/C9` 长按脚本分发理解。

> 本文件只定义项目方向，不展开具体技术实现。
>
> 本文件是项目最高优先级方向共识，所有讨论应以此为基础。
>
> 实现规则、TDD 流程与内存装配门禁统一维护在 `using-rules` 私有参考页。

## 1. 总目标

- 第一目标：形成可连续运行的双车协同搬运路线，并稳定完赛。
- 第二目标：在稳定完赛后逐步提速。

## 2. 方案路径

> 说明：本节描述项目方案，入口层使用 `main.py`。

- 采用主辅协同。
- 项目总路线由“寻找态状态机集”和“搬运态状态机集”组成。
- 主车负责环境理解、目标搜索、统一任务决策、状态切换与协同编排。
- 辅车负责跟随协作、执行配合与状态回传。
- 主车与辅车都参与运动，两车都默认维持本地方向闭环。
- 主车统一仲裁视觉观测、多车通信和速度前馈。
- 高速多车通信与速度前馈是正式主线能力。
- 主车与辅车在职责上显式区分：主车负责视觉处理和任务决策主线，辅车负责协同执行和状态回传；仓库正式目录统一为单一 `src/`。

## 3. 硬件条件

### 基础条件

> 说明：本节描述硬件条件与链路口径。

- 底盘形态：两台全向车底盘（主车 + 辅车）。
- 控制分工：
  - 主车承担视觉接收、状态机推进、任务决策与协同调度。
  - 辅车承担跟随协作、执行配合与状态回传。
- 视觉分工：
  - 主车安装两颗摄像头，视角正交布置。
  - 两份视觉代码可分开维护，但必须遵循统一车端协议。
  - 辅车车体提供可识别标记，辅车底盘不处理图像数据。
- 通信方式：主辅通过 `UART8` 直连通信协同。
- 无线串口控制链路作为遥控链路；主车通过 `UART3` 接收上游速度短包，`UART3` 控制链打通即视为遥控能力打通。
- 视觉层按 `vision/master/` 与 `vision/assistant/` 维护主辅角色入口；主车视觉负责物体观测、hook 上下文与事件回报，辅车视觉负责跟随速度修正。协议以 `docs/developer/protocol.md`、状态以 `docs/developer/state.md`、视觉职责以 `docs/developer/vision.md` 为准。

### 能力边界

- 灰度传感器用于边界检测。
- 目标是把“是否推到边界”纳入稳定一致的越线判定。
- 该能力用于提高搬运收尾确认的稳定性。
- 视觉链路的设备接入与观测字段变更，应在单独设计中定义新协议并同步文档。

## 4. 协同策略

### 寻找态状态机集

- 寻找态从边线重新起步。
- 上一物体到边线后，双车先沿边线平移，避开刚完成搬运的物体。
- 随后进入主前辅后构型。
- 辅车通过识别主车上的色标进行跟随。
- 主车负责寻找下一个物体。
- 主车找到物体后，先进入“主车目标朝向相对物体目标方向”的分类状态。
- 分类状态按 `0 / 90 / -90 / 180` 四类分支判断接下来由谁让位、是否需要绕行以及是否需要增加重排状态。
- 当主车车身方向与物体目标方向一致时，主车先让辅车。
- 完成让位或重排后，辅车向前步进配合，为进入搬运构型做准备。

### 搬运态状态机集

- 搬运态从找到物体并完成切入后开始。
- 基本状态至少包含：找到物品、搬运推进、避障插入。
- 直行搬运采用前后推构型：两车一前一后协同推进。
- 横向协同采用左右推构型：两车各转 `30` 度后协作推进。
- 主车目标是让搬运物体持续保持在自己的推杆上，并向目标位置推进。
- 辅车目标是保持协同支撑，并避免搬运物体碰到自己的推杆。
- 避障状态可插入搬运流程，且避障时两车构型可与直行推进不同。

### 单轮循环主框架

- 第一件物体在搬运态中完成推进，并通过边界检测完成本轮收尾确认后，系统退出该搬运分支。
- 系统回到寻找态起点前，双车先各自向后退，主动拉开与刚完成搬运物体的距离，避免下一轮寻找一开始就与上一目标发生干扰。
- 后退完成后，主车原地向后回身 `180` 度；回身完成后，双车再各自向前步进，重新整理成主前辅后的寻找构型：主车在前负责继续搜索，辅车在后通过识别主车标记持续跟随主车。
- 主车在寻找态中搜索第二个物体，辅车此时不直接围绕第二个物体动作，而是先稳定跟住主车，保证双车整体仍处于可控构型。
- 主车锁定第二个物体后，不直接默认绕到物体目标方向，而是先进入“主车目标朝向相对物体目标方向”的分类状态。
- 分类状态按 `0 / 90 / -90 / 180` 四类分支判断下一步应由谁让位、是否需要绕行、是否需要额外增加重排状态，以及应进入哪一类切入策略。
- 当分类结果为主车车身方向与物体目标方向一致时，主车先让辅车，把搬运所需的位置关系让出来。
- 当分类结果为其他角度关系时，系统进入对应分支下的让位、绕行或重排流程，直到双车重新整理到可进入搬运的准备关系。
- 让位、绕行或重排完成后，辅车再向前步进配合，系统据此完成从寻找态到搬运态入口的切换。
- 进入搬运态后，系统按对应分支和构型要求选择推进方式：适合直行协同时进入前后推构型，适合横向协同时进入左右推构型。
- 主车在搬运推进中负责持续把物体稳定在自己的推杆上并朝目标位置推进，辅车负责协同支撑并避免物体碰到自己的推杆。
- 如果推进过程中出现障碍，搬运态可插入避障状态；避障完成后，再回到对应推进分支继续搬运，而不是重新开始整轮寻找流程。
- 第二个物体完成推进并再次通过边界确认后，这一轮“从搬完第一个物体到搬完第二个物体”的完整循环结束，系统回到下一轮寻找态。

## 5. 核心原则

- 优先成功率，不追求早期极限速度。
- 优先连续完成能力，而不是单次最快。
- 优先可恢复能力，避免一次异常导致全局失败。
- 任何优化都不能破坏稳定完赛能力。
- 正式验证主线由本地自动测试和对话协作记录组成；板端状态、真实动作与现场表现统一通过协作过程记录结果。
- 任务决策主线只允许主车维护一份，不允许多处维护动作仲裁主线。
- 寻找态状态机集和搬运态状态机集分别建模，不混成一套平铺状态。
- 速度前馈按状态切换，不假设整程只使用一种前馈策略。
- 视觉实现可以分开维护，但车端协议必须统一。
- 视觉输入随阶段切换理解：寻找阶段服务主车搜索和辅车跟随，搬运阶段服务物体保持、构型推进与避障。
- 对福来轮底盘而言，方向保持是基础能力，不是额外优化项；主线验收必须同时关注“能协同”和“朝向稳定”。

## 6. 进度分层

### 阶段一：可验证

- 主车到辅车的高速通信可稳定工作。
- 速度前馈能够增强双车跟随链路，验证方案可行。

### 阶段二：可闭环

- 能分别打通寻找态最小闭环和搬运态最小闭环。
- 能完成单目标从搜索到搬运收尾的完整流程。

### 阶段三：可连续

- 能稳定完成寻找态和搬运态之间的切换。
- 能在角度分支和避障插入条件下连续处理多个目标。

### 阶段四：可提速

- 在不降低成功率前提下缩短搜索、切换、搬运和绕障耗时。
- 对障碍和扰动保持稳定表现。

## 7. 成功判据

- 多车通信稳定，速度前馈能够有效增强双车跟随。
- 寻找态和搬运态都具备可重复的最小闭环。
- 单目标搬运成功率稳定。
- 连续搬运能力稳定。
- 异常情况下具备可恢复或可控退出能力。
- 全流程可重复，不依赖偶然状态。
- 边界判定稳定，不依赖单一视觉条件。
- 主车能够稳定识别主车标记、搬运物体与障碍信息，并稳定推进状态切换与协同行为。

## 8. 补充方向

- 灰度传感器作为边界检测通道，纳入完赛主线能力。
- `0 / 90 / -90 / 180` 四类角度关系作为正式分支入口纳入路线。
- 状态相关的速度前馈作为控制主线能力纳入实现与验证。

## 9. 使用规则

- 新会话先阅读本文件。
- 仓库目录统一按单一 `src/` 理解。
- 需要调整方向时，先更新本文件，再推进实现。
