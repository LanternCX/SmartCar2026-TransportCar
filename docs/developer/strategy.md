# 项目核心方案

> 说明：其中与 `main.py` 单入口、UART6/UART8 持续接收、主辅分别烧录、`UART3` 主辅直连通信、最小状态回传、以及“当前阶段主车不动、只控辅车跟随”相关的旧口径，已由 `docs/superpowers/specs/2026-03-30-master-assistant-hardware-design.md` 覆盖；若存在冲突，当前以该设计文档为准，待后续统一清理。

> 本文件只定义项目方向，不展开具体技术实现。
>
> 除被更新设计文档显式覆盖的项目外，本文件仍是项目最高优先级方向共识，所有后续讨论应以此为基础。
>
> 实现规则、TDD 流程与内存装配门禁已迁入 `using-rules` 私有参考页，不再放在本目录供人工逐份 review。

## 1. 总目标

- 第一目标：稳定完赛。
- 第二目标：在稳定完赛后逐步提速。

## 2. 方案路径

> 说明：以下条目中凡涉及“双摄轮询”“统一运行时 profile”“主车同时驱动自身和辅车动作”的内容，均属于上一阶段口径；当前阶段请以 `docs/superpowers/specs/2026-03-30-master-assistant-hardware-design.md` 中的“双 UART 持续接收”“分别烧录”“主车不动、只控辅车跟随”为准。

- 采用主辅协同。
- 主车负责环境理解、任务决策与唯一任务状态机维护。
- 辅车负责配合执行与状态回传, 不处理图像数据。
- 两车通过保持稳定相对关系完成搬运。
- 主车统一仲裁双摄观测和主辅动作控制。
- 运行时必须显式区分主车/辅车 profile：主车负责视觉处理与唯一任务状态机，辅车关闭视觉处理，仅保留命令执行与状态回传；当前阶段该 profile 区分通过分别烧录 `master` / `assistant` 静态体现，而不是统一运行时内的角色切换。

## 3. 当前硬件条件

### 现状

> 说明：本节保留部分旧阶段表述用于理解演进背景；其中视觉链路与当前阶段主辅动作分工若与 2026-03-30 设计文档冲突，以后者为准。

- 底盘形态：两台全向车底盘（主车 + 辅车）。
- 控制分工：
  - 主车承担双 UART 持续接收、任务状态机、决策与调度。
  - 辅车承担执行、配合与状态回传。
- 视觉分工：
  - 主车安装两颗摄像头, 视角正交布置。
  - 两份视觉代码可分开维护, 但必须遵循统一车端协议。
  - `camera_id` 只表示物理相机身份, 不表示职责相机。
  - `category` 只表示检测类别, 可在不同物理相机上重复出现。
  - 辅车车体提供可识别标记, 辅车底盘不处理图像数据。
- 通信方式：当前阶段主辅通过 `UART3` 直连通信协同。
- 视觉链路：此处“单视觉串口轮询两颗相机”的表述属于旧阶段口径；当前阶段已改为 `UART6` / `UART8` 两路持续回传、主车主动接收。

### 方向增量

- 新增灰度传感器用于边界检测。
- 目标是把“是否推到边界”从视觉判断升级为“传感器可直接判定”。
- 该能力用于提高越线确认的稳定性与一致性。
- 视觉协议需要从“单框输入”升级为“单次查询对应单相机当前帧, 可返回多条检测结果”。

## 4. 搬运策略

> 说明：本节中“主车同时驱动自身动作与辅车动作”的描述属于旧阶段策略口径；当前阶段默认按“主车不动、控制辅车跟随”推进，后续如恢复主车参与运动，需要以新设计文档中的阶段装配表为准。

- 主车使用一套任务状态机统一管理找目标、辅车对正、搬运与避障。
- 近场相机负责搬运物体与辅车标记观测。
- 环境相机负责避障与环境观察。
- 每路相机持续回传当前缓存帧信息，主车按最近有效结果做双摄仲裁，并允许单帧对应多条检测结果。
- 主车必须在车端完成跨相机仲裁, 不把物理相机硬编码成唯一类别来源。
- 主车融合双摄观测后，当前阶段默认只驱动辅车动作；若后续阶段恢复主车参与动作控制，应以新设计文档中的阶段定义与装配边界为准。
- 两车车头相对夹持目标物。
- 阵型保持不变，整体横向移动完成搬运。
- 每次搬运完成后，不重建阵型，直接进入下一目标。
- 依靠全向移动能力做路径调整与避障。

## 5. 核心原则

- 优先成功率，不追求早期极限速度。
- 优先连续完成能力，而不是单次最快。
- 优先可恢复能力，避免一次异常导致全局失败。
- 任何优化都不能破坏稳定完赛能力。
- 任务状态机只允许主车维护一份，不允许多处维护动作决策主线。
- 视觉实现可以分开维护，但车端协议必须统一。
- 旧阶段的“单视觉串口轮询”原则已废止，当前阶段以双 UART 持续回传口径为准。

## 6. 进度分层

### 阶段一：可完成

- 能稳定完成单次搬运。
- 出现干扰后可继续任务或安全退出。

### 阶段二：可连续

- 能在保持阵型条件下连续搬运多个目标。
- 任务切换平稳，不依赖人工重置。

### 阶段三：可提速

- 在不降低成功率前提下缩短单次耗时。
- 对障碍和扰动保持稳定表现。

## 7. 成功判据

- 搬运成功率稳定。
- 连续搬运能力稳定。
- 异常情况下具备可恢复或可控退出能力。
- 全流程可重复，不依赖偶然状态。
- 边界判定稳定，不依赖单一视觉条件。
- 当前阶段的成功判据应关注双 UART 持续接收稳定性，不再以共享视觉串口轮询为前提。
- 主车能够稳定识别辅车标记、搬运物体与障碍信息，并在当前阶段稳定驱动辅车动作。

## 8. 补充方向

- 灰度传感器作为边界检测通道，纳入完赛主线能力。
- 最终判定逻辑优先追求“稳定一致”，不追求复杂判断。

## 9. 使用规则

- 新会话先阅读本文件，并同时阅读 `docs/superpowers/specs/2026-03-30-master-assistant-hardware-design.md`。
- 若出现方案分歧，先检查是否属于 2026-03-30 设计文档已显式覆盖的冲突项；若不是，再以本文件对齐方向。
- 若分歧属于已被 2026-03-30 设计文档显式覆盖的冲突项，则以该设计文档为准。
- 需要调整方向时，先更新本文件，再推进实现。
