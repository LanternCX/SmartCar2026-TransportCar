# 视觉设计

> 说明：本文件描述当前视觉链路事实与后续规划。若与 `docs/developer/strategy.md`、`docs/developer/tasks.md`、`docs/developer/control.md` 冲突，以后三者为准。

## 当前事实

- 视觉输入由主控通过 `UART6` 接收。
- 视觉协议按单行 `x=<x>,y=<y>` 文本解析观测。
- 主控侧只缓存最新一帧视觉观测，并按超时规则判断是否仍然有效。
- 主控侧将视觉输入作为单向观测使用，不向视觉侧回传控制阶段。
- 视觉观测进入主控内部状态机后，用于生成 `x / y / angle` 目标。
- 诊断查询使用 `obs_x`、`obs_y` 与目标点字段描述当前视觉状态。
- 当前视觉状态机包含 `IDLE`、`ALIGN_ANGLE`、`ALIGN_DIST`、`ALIGN_DX`、`ORBITING`、`PUSHING`、`RETURNING`、`DONE` 阶段。

## 后续规划

- 主车继续承担视觉相关决策与唯一任务状态机维护。
- 视觉代码可以按设备侧分别维护，但车端协议需要保持统一。
- 辅车车体继续提供可识别标记，辅车底盘不处理图像数据。
- 若后续引入更多视觉设备或环境观测能力，应在单独设计中明确职责分工与协议字段，再同步更新开发文档。
