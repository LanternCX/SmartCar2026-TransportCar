# 视觉设计

> 说明：本文件描述当前视觉链路事实与项目路线中的视觉职责。若与 `docs/developer/control.md` 或已确认的专项设计冲突，以后者为准；若讨论的是更高层路线目标，再联读 `docs/developer/strategy.md` 与 `docs/developer/tasks.md`。

## 串口协议入口

正式串口通信协议见 [串口通信协议](protocol.md)，状态编号与事件编号见 [状态机定义](state.md)。本文件只说明视觉链路职责，不承载完整协议正文。

## 当前基线

- 当前代码按 `vision/master/` 与 `vision/assistant/` 角色层组织角色运行入口。
- `vision/master/` 当前阶段是主车上游控制与速度转发入口：接管 `UART3` 下行控制，并按 [串口通信协议](protocol.md) 中的 `UART8` 主辅前馈链路转发给辅车；原始整行命令继续交给主车共享底盘处理。
- 主车当前阶段不接视觉输入，不消费视觉观测，也不做自主行控。
- `vision/assistant/` 是辅车角色运行入口：负责接入 `UART8` 前馈输入与 `UART6` 视觉输入。
- `vision/assistant/follow_runtime.py` 会创建辅车角色运行时对象，并在 `step()` 控制周期中参与双路速度输入读取编排和底盘调度。
- 辅车角色层在控制周期内统一编排 `UART8` 与 `UART6` 的读取：两路字段按 [串口通信协议](protocol.md) 的链路定义解释，非速度片段同样继续交给共享底盘；任一路单独存在时也可以直接形成最终速度。
- 辅车当前实现把 `UART8` 解释为前馈输入、把 `UART6` 解释为视觉输入；最终生效的 `vx / vy` 通过两路按轴裸相加形成，`omega` 当前只由 `UART8` 提供；角色层对两路都采用“保持上一包”的语义，不额外追加等待式同步逻辑。
- 视觉代码可以按设备侧分别维护，但角色入口统一在 `vision/master/` 与 `vision/assistant/` 下；其中主车包当前只承担串口转发职责，视觉消费入口留给后续专项设计。
- 正常运行入口会先识别车号，再切到 `vision/master/` 或 `vision/assistant/` 对应包。
- 辅车车体提供可识别标记，辅车底盘不处理图像数据。

## 路线职责

### 寻找态状态机集

- 寻找态从边线重新起步。
- 主车负责搜索下一个物体。
- 辅车通过识别主车上的色标进行跟随。
- 这一阶段的视觉输入首先服务于“主车找目标、辅车跟主车”。
- 视觉观测需要支撑边线平移避让、主前辅后构型建立、主车绕行和搬运前切入准备。

### 搬运态状态机集

- 搬运态从找到物体并完成切入后开始。
- 这一阶段的视觉输入首先服务于搬运物体保持、构型推进和避障插入。
- 直行推进时，视觉关注两车与搬运物体之间的协同关系。
- 横向协同时，视觉需要服务左右推构型下的推进和稳定性判断。
- 边界收尾阶段与灰度传感器共同服务越线确认。

## 使用原则

- 视觉输入按阶段理解：寻找态和搬运态关注的对象不同，不能混写成同一种观测任务。
- 主车承担视觉相关决策与任务状态切换主线，但当前实现阶段先固定为 `UART3` 上游控制接入 + `UART8` 速度转发，不在 `vision/master/` 内接入视觉消费实现。
- 主车视觉包作为主车视觉职责落点，不把主车视觉判断逻辑压回共享底盘。
- 辅车角色层当前只承担前馈输入、视觉输入的编排与共享底盘速度写回，不在角色层额外扩第二套底盘执行内核。
- 辅车角色层同时消费 `UART8` 与 `UART6` 上的速度控制文本；`UART8` 负责提供前馈向量，`UART6` 负责提供视觉修正向量；任一路单独存在时都可以直接形成速度；最终速度控制继续回到共享底盘原生入口。
- 辅车角色层对两路输入按统一速度向量理解：`UART8` 当前包形成前馈向量，`UART6` 当前包形成视觉向量；未出现的速度轴按 `0` 处理；两路都按最近一包持续生效；最终输出对 `vx / vy` 取两路逐轴裸相加结果，对 `omega` 只取 `UART8` 当前值。
- `UART8` 与 `UART6` 的速度字段解析复用同一份共享边界，乱序、空白、缺省轴和非法字段判定保持一致；具体字段归属以 [串口通信协议](protocol.md) 为准。
- 视觉职责文档只描述“看什么、服务谁、用于什么切换”，不展开检测算法和动作级实现细节。
- 引入更多视觉设备、更多观测字段或更丰富的环境感知能力时，应在单独设计中明确职责分工与协议字段，再同步更新开发文档。
