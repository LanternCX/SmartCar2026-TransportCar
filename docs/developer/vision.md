# 视觉设计

## 视觉角色与分工

- 主车安装两颗摄像头, 视角正交布置, 对应最终方案中的两个正交 OpenArt。
- 两份视觉代码可分开维护, 但必须遵循统一车端协议。
- `camera_id` 只表示物理相机身份, 不表示职责相机。
- `category` 只表示检测类别, 可在不同物理相机上重复出现。
- 辅车车体提供可识别标记, 辅车底盘不处理图像数据。
- 当前跟随专项主线不再采用轮询式视觉协议, 而是由两个 OpenArt 分别通过 `UART6` / `UART8` 持续回传视觉结果, 主车主动接收并消费两条独立数据流。

## 视觉在搬运策略中的位置

- 长期方向上, 主车仍使用一套任务状态机统一管理找目标、辅车对正、搬运与避障。
- 近场相机负责搬运物体与辅车标记观测。
- 环境相机负责避障与环境观察。
- 当前跟随专项主线中, 不再把“每次查询一帧”作为默认前提, 而是优先消费持续回传的误差结果。
- 当前跟随专项主线中, 视觉误差到控制量的映射直接采用 P 环。
- 主车必须在车端完成跨相机仲裁, 不把物理相机硬编码成唯一类别来源。
- 主车融合双摄观测后, 同时驱动主车自身动作与辅车动作。

## 视觉状态机迁移

当前仓库长期方向上已经接管原 OpenArt 端的状态机跳转逻辑。迁移后的职责边界如下：

- OpenArt：负责视觉识别。在当前跟随专项主线中, 两个 OpenArt 分别计算各自链路的目标误差, 再通过 `UART6` / `UART8` 连续回传结果。
- RT1021 主控：在长期方向上负责状态机跳转、里程计判定、推行/返回阶段切换，以及 dx/dy/d_angle 风格控制意图的生成; 但当前跟随专项主线中, 状态机不进入高频主闭环。

迁移后的内部状态机仍保持以下阶段：

- `IDLE`
- `ALIGN_ANGLE`
- `ALIGN_DIST`
- `ALIGN_DX`
- `ORBITING`
- `PUSHING`
- `RETURNING`
- `DONE`

其中 `push_angle` 当前由 `src/config/params.py` 中的固定参数提供，以便在不修改 OpenArt 协议的前提下保持车辆行为稳定。
