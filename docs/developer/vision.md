# 视觉设计

> 说明：本文件描述当前视觉链路事实与项目路线中的视觉职责。若与 `docs/developer/strategy.md`、`docs/developer/tasks.md`、`docs/developer/control.md` 冲突，以后三者为准。

## 当前基线

- 视觉输入由主控通过 `UART6` 接收。
- 视觉协议按单行 `x=<x>,y=<y>` 文本解析观测。
- 主控侧只缓存最新一帧视觉观测，并按超时规则判断是否仍然有效。
- 主控侧将视觉输入作为单向观测使用，不向视觉侧回传控制阶段。
- 视觉代码可以按设备侧分别维护，但车端协议需要保持统一。
- 正常运行入口会先识别车号，再切到 `vision/master/` 或 `vision/assistant/` 对应包。
- 辅车车体提供可识别标记，辅车底盘不处理图像数据。

## 路线职责

### 寻找态状态机集

- 寻找态从边线重新起步。
- 主车负责搜索下一个物体。
- 辅车通过识别主车上的色标进行跟随。
- 这一阶段的视觉输入首先服务于“主车找目标、辅车跟主车”。
- 视觉观测需要支撑边线平移避让、主前辅后构型建立、主车绕行和搬运前切入准备。

### 搬运态状态机集

- 搬运态从找到物体并完成切入后开始。
- 这一阶段的视觉输入首先服务于搬运物体保持、构型推进和避障插入。
- 直行推进时，视觉关注两车与搬运物体之间的协同关系。
- 横向协同时，视觉需要服务左右推构型下的推进和稳定性判断。
- 边界收尾阶段与灰度传感器共同服务越线确认。

## 使用原则

- 视觉输入按阶段理解：寻找态和搬运态关注的对象不同，不能混写成同一种观测任务。
- 主车继续承担视觉相关决策与任务状态切换主线。
- 主车视觉包负责把视觉观测组织成判断依据与动作意图。
- 辅车视觉包负责承接本车视觉校准与主车前馈输入，不把主车判断逻辑回流到辅车侧。
- 视觉职责文档只描述“看什么、服务谁、用于什么切换”，不展开检测算法和动作级实现细节。
- 若后续引入更多视觉设备、更多观测字段或更丰富的环境感知能力，应在单独设计中明确职责分工与协议字段，再同步更新开发文档。
