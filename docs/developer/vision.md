# 视觉设计

## 当前阶段目标

- 当前阶段只解决“辅车主动跟随主车”。
- 主车新的找物视觉主线暂不展开实现。
- 搬运阶段是否继续依赖视觉, 当前不纳入本轮目标。

## 角色分工

- 辅车 OpenArt：负责识别主车标记、完成跟随阶段判断、直接生成辅车已支持的 `follow` 请求。
- 辅车执行侧：负责接收并执行 `follow` 请求, 保留当前已有的解析、运动计算与安全停下能力。
- 主车：旧的跟随视觉链已经删除, 当前只保留后续继续做找物前的最薄起点。

## 当前主链

- 当前视觉主链不是“主车持续读双路视觉后统一驱动辅车”。
- 当前视觉主链是“辅车 OpenArt -> 辅车执行侧”。
- 辅车 OpenArt 通过 `UART6` 向辅车执行侧持续发送最新 `follow` 请求。
- 主辅之间的 `UART3` 基本通信链路仍保留, 但不再承担辅车高频跟随主链。

## 协议口径

- 当前视觉输出必须直接对齐辅车已支持的 `follow` 请求。
- 不额外扩第二套视觉字段族。
- 无目标或保持阶段时, 视觉端发送无效 `follow` 请求, 由辅车保持安全停下。

## 当前非目标

- 不实现主车新的找物主线。
- 不恢复主车读取旧跟随视觉输入。
- 不恢复主车基于视觉结果为辅车生成高频控制。
- 不在本轮讨论搬运物体视觉闭环。
