# 串口通信协议

## 1. 定位

本文件按串口链路定义通信协议。协议只规定每条串口链路使用哪一种报文格式、每个字段表示什么，以及接收端如何解释报文。

状态编号、目标编号、事件编号和状态跳转语义见 [状态机定义](state.md)。比赛路线、阶段目标和任务策略见 [总体方案](strategy.md)。

## 2. 已确认串口链路

| 串口 | 方向 | 协议用途 | 报文类型 |
| --- | --- | --- | --- |
| `UART3` | 上位机 -> 主车 | 上游速度控制 | 速度控制文本 |
| `UART8` | 主车 -> 辅车 | 主辅前馈与状态同步 | 速度前馈文本、状态同步短包 |
| `UART6` | 辅车视觉 -> 辅车 | 视觉速度修正 | 速度修正文本 |

未确认硬件接线的视觉同步链路不在本文件中指定串口号。

## 3. 通用分帧规则

- 编码：ASCII。
- 分帧：一行一帧。
- 行尾：发送端使用 `\r\n`，接收端接受 `\n` 和 `\r\n`。
- 同一行内使用 `,` 分隔字段。
- 字段前后的空白由接收端忽略，字段名和值内部不使用空白字符。
- 无法解析的帧由接收端丢弃或按本地错误处理记录，不要求发送错误帧。

## 4. 速度控制文本

速度控制文本使用键值字段：

```text
<key>=<value>[,<key>=<value>...]
```

数值使用十进制浮点文本，不使用科学计数法。

### 4.1 字段表

| 字段 | 含义 | 使用链路 |
| --- | --- | --- |
| `vx` | 车体系 x 方向速度或速度修正量 | `UART3`、`UART8`、`UART6` |
| `vy` | 车体系 y 方向速度或速度修正量 | `UART3`、`UART8`、`UART6` |
| `omega` | 角速度前馈 | `UART3`、`UART8` |
| `w` | `omega` 的别名 | `UART3`、`UART8` |
| `angle` | 绝对角度目标 | `UART8` |

坐标方向：

- `vx+`：车体系 x 正方向。
- `vy+`：车体系 y 正方向。
- `omega+` / `w+`：车体系旋转正方向。
- `angle`：接收端底盘角度控制使用的绝对角度目标。

具体车体正方向以控制文档和底盘实现为准；协议只固定字段名和链路归属。

### 4.2 `UART3` 上游速度控制

`UART3` 接收上位机发给主车的速度控制文本。

允许字段：

```text
vx=<value>
vy=<value>
omega=<value>
w=<value>
```

示例：

```text
vx=1.0,vy=-2.5,omega=0.5
```

规则：

- 至少包含一个速度字段。
- `w` 与 `omega` 表示同一类角速度输入。
- 主车本地底盘直接消费 `UART3` 原始命令行。
- 主车角色层从 `UART3` 命令行中抽取速度相关字段，经 `UART8` 转发给辅车。

### 4.3 `UART8` 主辅前馈

`UART8` 承载主车发给辅车的前馈信息。

允许字段：

```text
vx=<value>
vy=<value>
omega=<value>
w=<value>
angle=<value>
```

示例：

```text
vx=1.0,vy=-2.5,angle=15.0
```

规则：

- `vx` 和 `vy` 表示主车转发给辅车的平移速度前馈。
- `angle` 表示主车转发给辅车的绝对角度目标。
- 主车收到 `UART3` 上的 `omega` 或 `w` 字段时，`UART8` 转发当前绝对角度字段 `angle`。
- 辅车把 `UART8` 的 `vx`、`vy` 作为前馈向量。
- 辅车把 `UART8` 的 `angle` 作为底盘角度目标处理。
- `omega` 和 `w` 保留为 `UART8` 直接角速度前馈字段，主车速度转发链路不使用它们替代 `angle`。

### 4.4 `UART6` 辅车视觉速度修正

`UART6` 承载辅车视觉端发给辅车的速度修正量。

允许字段：

```text
vx=<value>
vy=<value>
```

示例：

```text
vx=-0.5,vy=0.25
```

规则：

- `vx` 和 `vy` 表示视觉跟随产生的平移速度修正量。
- `UART6` 不承载绝对角度目标。
- `UART6` 不承载角速度前馈。
- 辅车把 `UART6` 的 `vx`、`vy` 与 `UART8` 的 `vx`、`vy` 按轴相加，形成最终平移速度输入。
- 辅车旋转输入只来自 `UART8` 或底盘本地角度控制。

## 5. 状态同步短包

状态同步短包用于低频可靠同步，不用于高频速度控制。

状态同步短包只在需要状态同步的链路上使用。已确认的主辅状态同步链路使用 `UART8`。当前速度式跟随测试链路不要求先建立状态同步。

### 5.1 状态包 `s`

格式：

```text
s,<seq>,<state>,<target>,<arg>
```

字段定义：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `seq` | `0` 到 `255` 的整数 | 状态同步编号 |
| `state` | `0` 到 `255` 的整数 | 状态编号，见 [状态机定义](state.md) |
| `target` | `0` 到 `255` 的整数 | 目标编号，见 [状态机定义](state.md) |
| `arg` | 有符号整数 | 状态参数，见 [状态机定义](state.md) |

示例：

```text
s,12,3,1,0
```

### 5.2 确认包 `a`

格式：

```text
a,<seq>
```

字段定义：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `seq` | `0` 到 `255` 的整数 | 已确认的状态同步编号 |

示例：

```text
a,12
```

### 5.3 事件包 `r`

格式：

```text
r,<seq>,<event>,<value>
```

字段定义：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `seq` | `0` 到 `255` 的整数 | 对应的状态同步编号 |
| `event` | `0` 到 `255` 的整数 | 事件编号，见 [状态机定义](state.md) |
| `value` | 有符号整数 | 事件附加值 |

示例：

```text
r,12,2,0
```

### 5.4 同步规则

- 状态发送端生成新的 `seq` 后发送 `s` 包。
- 接收端收到有效 `s` 包后进入对应状态，并回复 `a` 包。
- 状态发送端收到相同 `seq` 的 `a` 包后认为同步完成。
- 状态发送端在等待确认期间重复发送同一个 `s` 包。
- 接收端重复收到同一个 `s` 包时重复回复 `a` 包，不重复初始化本地状态。
- 接收端收到过期 `seq` 的 `s` 包时丢弃该包。
- `r` 包只回报事件，不直接改变全局状态。

## 6. 速度式跟随链路运行规则

速度式跟随链路由三段组成：

1. `UART3`：上位机向主车发送速度控制文本。
2. `UART8`：主车向辅车转发速度前馈和绝对角度。
3. `UART6`：辅车视觉向辅车发送速度修正量。

运行规则：

- 三段链路都按最新速度输入运行，不逐包确认。
- 缺包不等于零量。
- 停车或清空某一路输入时，发送端必须显式发送零量。
- 速度式跟随链路不依赖状态同步短包。
- 状态同步短包与速度控制文本可以共用同一串口链路，但接收端必须按行首格式区分。

## 7. 车端状态查询

本协议不定义车端通用状态查询报文。

运行阶段需要交换状态机事件时使用 `r` 包。需要可靠切换状态时使用 `s/a` 同步过程。

## 8. 扩展边界

- 新增串口链路前，先登记串口号、方向和使用协议。
- 新增字段前，先明确字段属于哪一条串口链路。
- 高频速度链路不使用冗长调试字段。
- 正式协议不维护多套字段双轨说明。
