# 串口通信协议设计约束

## 文档边界

本文件只维护串口链路的外部事实、设计取舍和历史调试结论。协议字段、topic 注册、body 长度、方向约束、缓存处理和异常计数以代码、注释和行为测试为准。

## 链路分工

- `UART3`: 调试终端与车端之间的 REPL、日志和现场调试链路。
- `UART6`: 本车 RT1021 与本车 OpenART 之间的本地视觉链路。
- `UART8`: 主车与辅车之间的直连链路。

两台车各自使用本车硬件上的 `UART6`; 主车 `UART6` 与辅车 `UART6` 不是同一条物理链路。`UART3` 不进入正式传输层。

## 设计取舍

- 高频速度链使用最新值语义, 可以丢旧值, 不承担状态切换边界。
- 低频状态、事件和控制边界使用可靠同步语义, 需要独立验证 ACK 和重发闭环。
- 车能动只证明高频速度链工作, 不证明低频可靠状态链已经闭环。
- 固定短帧必须具备帧头和 CRC8; 只靠模式、topic 或角色方向扫描会在坏字节、半包、粘包和错位时误消费假帧。
- 接收层必须跨轮询保留不足一帧的残片; 现场最容易丢失的是低频 ACK 或事件包, 不是高频速度包。
- 车端与 OpenART 视觉端复制协议实现时, 帧格式、CRC、topic body 或可靠语义变化必须两仓同步修改并同步验证。
- 真实联调默认按“车先上电、视觉后上电、串口分段到达”设计, 不按整帧同时到达的理想路径判断。
- 业务 body 只编码 topic 的有效字段, 帧层统一补零到固定帧长。
- 本地视觉可靠控制只承载回库黄线 Gate 开关。

## 可靠事件边界

- 可靠事件用于建立状态切换边界, 不能依赖最后一帧高频速度包表达停车。
- 清理残留速度缓存和向底盘写零速度是两个不同动作。
- 位置或角度锁定期间, 可靠事件不能覆盖正在执行的锁定目标。
