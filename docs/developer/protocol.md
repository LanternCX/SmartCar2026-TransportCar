# 串口通信协议

## 1. 定位

本文件定义车端串口通信的正式协议。协议按通信可靠性分为两类：

1. UDP 模式：用于高频、短包、允许丢包的数据流。
2. TCP 模式：用于低频、必须确认、可重复发送的可靠同步。

串口链路带宽有限，高频数据必须优先使用短包。需要可靠到达的信息必须通过同步包、确认包、重复发送和幂等处理完成，不能把所有高频数据包扩展成冗长结构。

状态编号、目标编号、事件编号和状态跳转语义见 [状态机定义](state.md)。比赛路线、阶段目标和任务策略见 [总体方案](strategy.md)。控制职责与视觉职责分别见 [控制说明](control.md) 和 [视觉说明](vision.md)。

## 2. 已确认串口链路

| 串口 | 方向 | 协议用途 | 报文模式 |
| --- | --- | --- | --- |
| `UART3` | 上位机 -> 主车 | 上游速度控制 | UDP 数据流 |
| `UART8` | 主车 <-> 辅车 | 主辅速度前馈、状态同步、确认和事件回报 | UDP 数据流、TCP 同步 |
| `UART6` | 辅车视觉 -> 辅车 | 视觉速度修正 | UDP 数据流 |

未确认硬件接线的视觉同步链路不在本文件中指定串口号。新增串口链路前，先登记串口号、方向、用途和报文类型。

## 3. 通用分帧规则

- 编码：ASCII。
- 分帧：一行一帧。
- 行尾：发送端使用 `\r\n`，接收端接受 `\n` 和 `\r\n`。
- 同一行内使用 `,` 分隔字段。
- 字段前后的空白由接收端忽略，字段内部不使用空白字符。
- 无法解析的帧由接收端丢弃或按本地错误处理记录，不要求发送错误帧。

## 4. 协议模式

### 4.1 UDP 模式

UDP 模式用于高频数据流。它的目标是低带宽占用和最新值优先。

规则：

- 包结构必须短。
- 默认不确认。
- 默认不重传。
- 默认只保留最近一包。
- 丢包不触发状态回退。
- 需要归零或停用时必须显式发送零量或停用量，不能把缺包解释成零量。
- 高频包不默认携带完整同步上下文。

### 4.2 TCP 模式

TCP 模式用于低频可靠同步。它的目标是让双方确认某个同步上下文已经建立。

规则：

- 使用短包。
- 发送端重复发送同步包，直到收到确认。
- 接收端收到同步包后回确认。
- 同一个同步包重复到达时，接收端必须按幂等规则处理。
- 旧同步包到达时，接收端必须能忽略。
- TCP 模式只做轻量可靠同步，不实现完整 TCP 协议。

## 5. 抽象包类型

| 类型 | 模式 | 抽象用途 |
| --- | --- | --- |
| `s` | TCP | 同步上下文 |
| `a` | TCP | 确认同步上下文 |
| `v` | UDP | 速度或控制量数据流 |
| `o` | UDP | 观测或误差数据流 |
| `r` | UDP 或半可靠 | 状态或结果回报 |

新增包类型前必须先判断它属于 UDP 模式还是 TCP 模式。高频包默认走 UDP 模式；必须可靠到达的低频同步走 TCP 模式。

## 6. UDP 数据流包

### 6.1 速度包 `v`

格式：

```text
v,<vx>,<vy>[,<omega>]
```

字段定义：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `vx` | 浮点数 | 车体系 x 方向速度或速度修正量 |
| `vy` | 浮点数 | 车体系 y 方向速度或速度修正量 |
| `omega` | 浮点数 | 车体系角速度，按链路职责可选 |

链路规则：

- `UART3` 使用 `v` 包承载上位机给主车的速度控制。
- `UART8` 使用 `v` 包承载主车给辅车的速度前馈。
- `UART6` 使用 `v` 包承载辅车视觉给辅车的速度修正。
- `UART6` 只贡献 `vx` 和 `vy`，不作为辅车角速度来源。
- `UART8` 可提供辅车旋转输入。
- 停车或清空某一路输入时，发送端必须显式发送零量。

示例：

```text
v,1.0,-2.5,0.5
v,0,0,0
```

### 6.2 观测包 `o`

格式：

```text
o,<seq>,<x>,<y>,<value>
```

字段定义：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `seq` | `0` 到 `255` 的整数 | 当前观测关联的同步编号 |
| `x` | 浮点数 | 观测或误差 x 分量 |
| `y` | 浮点数 | 观测或误差 y 分量 |
| `value` | 浮点数 | 观测附加值 |

规则：

- `o` 包用于观测、误差或视觉侧结果数据流。
- `o` 包只保留最近一包。
- `o` 包不触发全局状态切换。
- 某条链路使用 `o` 包前，必须先在本文件登记链路职责和字段含义。

### 6.3 UDP 数据流运行规则

- 数据流按当前已建立的同步上下文解释。
- 数据流只保留最新值。
- 数据流不等待上一包处理完成。
- 数据流不要求逐包确认。
- 数据流包长优先级高于可读性。
- 如果某类数据流必须带同步编号，必须说明为什么值得牺牲带宽。

## 7. TCP 同步包

### 7.1 同步包 `s`

格式：

```text
s,<seq>,<state>,<target>,<arg>
```

字段定义：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `seq` | `0` 到 `255` 的整数 | 状态同步编号 |
| `state` | `0` 到 `255` 的整数 | 状态编号，见 [状态机定义](state.md) |
| `target` | `0` 到 `255` 的整数 | 目标编号，见 [状态机定义](state.md) |
| `arg` | 有符号整数 | 状态参数，见 [状态机定义](state.md) |

示例：

```text
s,12,3,1,0
```

### 7.2 确认包 `a`

格式：

```text
a,<seq>
```

字段定义：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `seq` | `0` 到 `255` 的整数 | 已确认的同步编号 |

示例：

```text
a,12
```

### 7.3 同步过程

可靠同步使用“重复发送 + 确认 + 幂等”的最小过程。

流程：

1. 发送端生成新的同步编号。
2. 发送端发送 `s` 包。
3. 接收端收到有效 `s` 包后，更新本地同步上下文。
4. 接收端发送 `a` 包。
5. 发送端收到相同 `seq` 的 `a` 包后，认为同步完成。
6. 若发送端未收到确认包，则间隔重发同一个 `s` 包。
7. 接收端再次收到同一 `s` 包时，不重复初始化，只重新确认。
8. 接收端收到旧 `s` 包时，忽略该包。

同步包表达的是“当前同步上下文”，不是一次性事件。重复发送不得造成重复动作。

## 8. 回报包 `r`

格式：

```text
r,<seq>,<event>,<value>
```

字段定义：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `seq` | `0` 到 `255` 的整数 | 对应的同步编号 |
| `event` | `0` 到 `255` 的整数 | 事件编号，见 [状态机定义](state.md) |
| `value` | 有符号整数 | 事件附加值 |

示例：

```text
r,12,2,0
```

规则：

- `r` 包用于状态或结果回报。
- `r` 包不直接改变全局状态。
- 全局状态切换必须通过新的 `s` 包同步。
- 若某个结果必须可靠到达，应在对应状态同步上下文中重复回报，直到发送端进入下一同步上下文。

## 9. 包长设计规则

高频包优先使用短字段、位置字段或固定顺序字段。

推荐：

```text
v,1.2,0.3
s,12,3,1,0
a,12
```

不使用冗长键值结构作为正式高频协议：

```text
type=stream,state=12,vx=1.2,vy=0.3
```

键值结构可以用于临时人工调试记录，但不得作为正式运行链路协议保留。

## 10. 车端状态查询

本协议不定义车端通用状态查询报文。

运行阶段需要交换状态机事件时使用 `r` 包。需要可靠切换状态时使用 `s/a` 同步过程。临时现场调试可以使用临时日志或人工联调记录承接，不写入正式通信协议。

## 11. 扩展边界

新增协议字段或包类型前，必须先回答：

1. 它属于 UDP 模式还是 TCP 模式。
2. 它是否高频发送。
3. 它是否必须可靠到达。
4. 它是否必须每包携带同步上下文。
5. 它是否会显著增加无线串口带宽占用。

只有低频 TCP 同步包可以优先考虑可读性；高频 UDP 包必须优先考虑短包。正式协议不维护历史协议入口、兼容层或多套字段双轨说明。
