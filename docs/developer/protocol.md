# 串口通信协议

## 1. 定位

本文件定义车端、主辅车间与本地视觉链路使用的正式串口协议。协议按可靠性分为两类：

1. 数据流短包：用于高频、短包、允许丢包的数据流。
2. 可靠短包：用于低频、必须确认、可重复发送的同步或结果回报。

状态编号、目标编号、事件编号和状态跳转语义见 [状态机定义](state.md)。控制职责与视觉职责分别见 [控制说明](control.md) 和 [视觉说明](vision.md)。

## 2. 已确认串口链路

| 串口 | 方向 | 协议用途 | 报文模式 |
| --- | --- | --- | --- |
| `UART3` | 上位机 -> 主车 | 上游速度控制 | 数据流 |
| `UART8` | 主车 <-> 辅车 | 主辅速度前馈；辅车状态上下文同步 | 数据流、状态同步 |
| `UART6` | 本车 RT1021 <-> 本车 OpenART | 本地视觉链路；主车用于视觉 hook 上下文、搜索速度和事件；辅车用于视觉速度修正 | 数据流、可靠短包 |

两台车各自使用本车硬件上的 `UART6`，主车 `UART6` 与辅车 `UART6` 不构成同一条物理链路。新增串口链路前，先登记串口号、方向、用途和报文类型。

## 3. 通用分帧规则

- 编码：ASCII。
- 分帧：一行一帧。
- 行尾：发送端使用 `\r\n`，接收端接受 `\n` 和 `\r\n`。
- 同一行内使用 `,` 分隔字段。
- 字段前后的空白由接收端忽略，字段内部不使用空白字符。
- 无法解析的帧由接收端丢弃或按本地错误处理记录，不要求发送错误帧。

## 4. 编号分层

可靠通信同时使用两个编号：

| 编号 | 适用包 | 维护方 | 含义 |
| --- | --- | --- | --- |
| `reliable_seq` | `s`、`r` 创建；`a` 携带被确认包序号 | `s`、`r` 按发送端、串口链路和发送方向维护；`a` 不创建可靠包序号 | 用于可靠包确认、重发和去重 |
| `context_id` | `s`、`r`；诊断观测使用 `o` 时携带 | 由主车状态机创建 | 用于业务上下文匹配 |

规则：

- `reliable_seq` 只表达可靠传输身份，不表达业务状态。
- `context_id` 只表达业务上下文，不表达可靠确认身份。
- `a,<reliable_seq>` 携带被确认包的 `reliable_seq`，只确认该可靠包已被接收端处理，不表达业务上下文。
- 每条链路每个发送方向同一时刻只维护一个待确认可靠包。
- 新可靠包必须使用新的 `reliable_seq`。
- `a` 包不创建、不消耗确认端自己的新可靠包序号。

## 5. 包类型

| 类型 | 模式 | 用途 |
| --- | --- | --- |
| `v` | 数据流 | 速度或速度修正量 |
| `o` | 数据流 | 视觉观测或误差诊断 |
| `s` | 可靠短包 | 建立状态或视觉 hook 上下文 |
| `a` | 可靠短包 | 确认 `s` 或可靠 `r` |
| `r` | 可靠短包 | 回报必须可靠送达的事件或结果 |

## 6. 数据流短包

### 6.1 速度包 `v`

格式：

```text
v,<vx>,<vy>[,<omega>]
```

字段定义：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `vx` | 浮点数 | 车体系 x 方向速度或速度修正量 |
| `vy` | 浮点数 | 车体系 y 方向速度或速度修正量 |
| `omega` | 浮点数 | 车体系角速度，按链路职责可选 |

链路规则：

- `UART3` 使用 `v` 包承载上位机给主车的速度控制。
- `UART8` 使用 `v` 包承载主车当前底盘速度目标给辅车的速度前馈。
- 主车在 `UART8` 上按当前写入共享底盘的速度目标持续发送前馈；该目标可来自 `UART3` 上游速度包，也可来自主车 `UART6` 视觉速度输入。
- 新合法速度目标覆盖前馈内容，显式零包形成零前馈。
- `UART8` 的状态同步短包不承载本阶段主车视觉搜索事件。
- 主车 `UART6` 接收 OpenART Vision master 给主车 RT1021 的车端速度输入，格式为 `v,<vx>,<vy>`。
- OpenART Vision master 在 `SEARCH_OBJECT` 中维护主车搜索 P 环，并通过 `v,<vx>,<vy>` 控制主车搜索速度。
- 主车搜索的纵向控制量来自归一化底边误差，输出按图像高度缩放后限幅。
- 主车搜索控制不依赖 `o` 观测包；主车视觉搜索主线不周期发送 `o` 包。
- 辅车 `UART6` 使用 `v` 包承载辅车 OpenART 给辅车 RT1021 的视觉速度修正。
- 辅车 `UART6` 只贡献 `vx` 和 `vy`，不作为辅车角速度来源。
- `UART8` 可提供辅车旋转输入。
- 停车或清空某一路输入时，发送端必须显式发送零量。

### 6.2 观测包 `o`

`o` 包用于视觉观测或误差诊断。主车搜索控制不根据 `o` 包计算主车搜索 P 控制量，OpenART Vision master 的主搜索输出使用 `v,<vx>,<vy>`。

格式：

```text
o,<context_id>,<x>,<y>,<value>
```

字段定义：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `context_id` | `0` 到 `255` 的整数 | 视觉上下文编号 |
| `x` | 浮点数 | 物体中心相对画面中线的横向误差 |
| `y` | 浮点数 | 物体归一化底边相对图像底边的纵向误差 |
| `value` | 浮点数 | 目标强度，本阶段使用候选目标面积 |

规则：

- `o` 包不携带 `reliable_seq`。
- `o` 包不逐包确认。
- `o` 包只按最近一帧解释。
- `o` 包不触发全局状态切换。
- 主车搜索主线不要求周期发送 `o` 包。

## 7. 可靠短包

### 7.1 同步包 `s`

主车视觉 hook 上下文同步格式：

```text
s,<reliable_seq>,<context_id>,<state>,<target>,<arg>
```

字段定义：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `reliable_seq` | `0` 到 `255` 的整数 | 本次同步包的可靠包序号 |
| `context_id` | `0` 到 `255` 的整数 | 业务上下文编号 |
| `state` | `0` 到 `255` 的整数 | 状态编号，见 [状态机定义](state.md) |
| `target` | `0` 到 `255` 的整数 | 目标编号，见 [状态机定义](state.md) |
| `arg` | 有符号整数 | 状态参数或 hook 配置编号 |

规则：

- `s` 包用于建立必须可靠到达的上下文。
- 主车进入 `SEARCH_OBJECT` 时，通过本车 `UART6` 向主车 OpenART 发送 `s` 包建立 hook 上下文。
- 接收端收到有效 `s` 包后发送 `a,<reliable_seq>`。
- `context_id` 是 `0..255` 环形编号。
- 相同 `context_id` 的重复 `s` 必须幂等处理并重新确认。
- 新于已建立上下文的 `s` 才覆盖已建立上下文。
- 非新上下文的合法 `s` 不覆盖已建立上下文，但需要返回对应确认。
- `context_id` 先后关系按与可靠序号一致的半环规则判断：差值落在 `1..127` 视为新于已建立上下文，差值为 `0` 视为重复，差值落在 `128..255` 视为非新上下文。

辅车状态上下文同步格式：

```text
s,<seq>,<state>,<target>,<arg>
```

字段定义：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `seq` | `0` 到 `255` 的整数 | 本次状态同步序号 |
| `state` | `0` 到 `255` 的整数 | 状态编号，见 [状态机定义](state.md) |
| `target` | `0` 到 `255` 的整数 | 目标编号，见 [状态机定义](state.md) |
| `arg` | 有符号整数 | 状态参数 |

规则：

- 该格式只用于 `UART8` 辅车状态上下文同步。
- 接收端收到有效同步包后发送 `a,<seq>`。
- 同步序号按 `0..255` 半环规则判断先后。
- 该格式不携带 `context_id`，不作为主车视觉 hook 上下文。

### 7.2 确认包 `a`

格式：

```text
a,<reliable_seq>
```

字段定义：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `reliable_seq` | `0` 到 `255` 的整数 | 已确认可靠包的可靠包序号 |

规则：

- `a` 包只确认 `s` 或可靠 `r` 已被处理。
- `a` 包携带被确认包的 `reliable_seq`。
- `UART8` 状态同步中，`a,<seq>` 确认对应状态同步序号。
- `a` 包不创建、不消耗确认端自己的新可靠包序号。
- `a` 包不携带 `context_id`。
- `a` 包不表示业务状态已切换。

### 7.3 事件回报包 `r`

格式：

```text
r,<reliable_seq>,<context_id>,<event>,<value>
```

字段定义：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `reliable_seq` | `0` 到 `255` 的整数 | 本次事件回报包的可靠包序号 |
| `context_id` | `0` 到 `255` 的整数 | 业务上下文编号 |
| `event` | `0` 到 `255` 的整数 | 事件编号，见 [状态机定义](state.md) |
| `value` | 有符号整数 | 事件附加值 |

主车视觉 hook 事件：

- 主车 OpenART 使用 `r,<reliable_seq>,<context_id>,<event>,<value>` 可靠回报 `TARGET_FOUND`。
- `event` 为 `TARGET_FOUND` 时，`value` 表示目标强度，本阶段使用候选目标面积。
- 主车 RT1021 收到格式合法的 `r` 包后，每次都返回 `a,<reliable_seq>`。
- 重复 `r` 包必须幂等处理并重新确认。
- 上下文匹配且事件为 `TARGET_FOUND` 时，只触发主车状态机判断。
- 上下文不匹配的合法 `r` 包需要确认，但不触发状态跳转。
- 事件确认只表示可靠送达，不表达全局状态迁移。

## 8. 主车本地视觉可靠通信

主车 RT1021 与主车 OpenART 的本地视觉 hook 链路采用对等可靠语义。任何一端发送必须可靠到达的同步或结果时，都重复发送同一可靠包，直到收到对端确认。接收端收到同一可靠包的重复帧时按幂等规则处理，并重新发送确认。

`UART8` 主辅速度前馈保持数据流语义。`UART8` 的状态同步短包不承载本阶段视觉搜索状态机的可靠事件回报。

## 9. 串口发送节流

同一条物理串口上同时承载数据流包和可靠包时，发送策略按包类型区分：

- `v/o` 数据流包不做发送前后延时。
- `s/a/r` 可靠包发送前后各使用固定 1 ms 短延时。
- 主车 RT1021 与 OpenART Vision master 使用同一条可靠发送规则。
- 可靠包重复发送由可靠通信层按低频节奏调度，不在高频数据流路径中累积阻塞。

该策略用于避免可靠包与同周期数据流包连续挤占串口发送缓冲，同时不让高频数据流每帧承担阻塞成本。

## 10. Vision 端协议职责

- OpenART Vision master 是 Vision 仓库主车视觉入口，运行在主车 OpenART，负责接收 `s` hook 上下文、发送 `a` 确认、维护主车搜索 P 环、通过 `v,<vx>,<vy>` 下发主车搜索速度，并在 hook 条件满足时通过可靠 `r` 回报 `TARGET_FOUND`。
- OpenART Vision assistant 运行在辅车 OpenART，负责通过 `v,<vx>,<vy>` 输出视觉速度修正量。
- Vision 端不维护全局状态机。
- 视觉事件只触发主车判断，不直接迁移全局状态。

## 11. 扩展边界

新增协议字段或包类型前，必须先回答：

1. 它属于数据流短包还是可靠短包。
2. 它是否高频发送。
3. 它是否必须可靠到达。
4. 它是否必须每包携带业务上下文。
5. 它是否会显著增加串口带宽占用。
