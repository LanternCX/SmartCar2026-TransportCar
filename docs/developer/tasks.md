# 完赛路线任务清单

> 说明：当前正式基线采用单一 `src/`。`main.py` 单入口、分别烧录和按钮脚本分发属于下一轮主题，届时单开设计与任务推进。

> 我正在使用 writing-plans 思路来拆解执行任务。
>
> 本文件用于把“完赛方向”拆成可逐步推进的小任务。每个任务尽量做到半天内可完成、可验证、可复盘。
>
> 实现阶段执行细则、TDD 分层与内存装配规则已迁入 `using-rules` 私有参考页，本文件只保留任务路线与阶段目标。

## 0. 使用说明

- 每次只开一个任务，完成后再开下一个。
- 每个任务都要有“完成证据”（测试结果、视频、日志或记录）。
- 优先顺序：先稳定完赛，再提速。
- 任务状态建议：`未开始` / `进行中` / `已完成` / `阻塞`。

## 1. 阶段总览

> 说明：当前阶段先在单一 `src/` 基线上推进“主车感知与决策、辅车执行跟随”的最小闭环。3.0 入口适配和主车主动参与动作属于下一轮主题。

- 阶段 A：基础对齐（规则、接口、验证基线）
- 阶段 B：双车最小可用协同（能完成单次稳定搬运）
- 阶段 C：连续搬运（不重建阵型，连续完成多目标）
- 阶段 D：抗扰与恢复（异常下可恢复或可控退出）
- 阶段 E：提速优化（不降成功率前提下压时间）
- 阶段 F：赛前封板（参数冻结、流程冻结、应急预案）

---

## 阶段 A：基础对齐

### 目标

把“同一套规则、同一套目标、同一套验证方式”统一起来，避免后续返工。

### 任务

- [ ] A-01 对齐本项目方向文档，确认当前正式基线以 `docs/developer/strategy.md`、`docs/developer/tasks.md` 与 `docs/developer/control.md` 为主；涉及下一轮 3.0 入口适配时，再单开设计补充边界。
- [ ] A-02 在队内确认“稳定完赛优先”策略，不再并行推进冲成绩分支。
- [ ] A-03 对齐视觉实现与底盘协议边界（视觉代码可分开维护，车端协议统一）。
- [ ] A-04 对齐主辅角色：主车双摄决策与唯一状态机，辅车纯执行。
- [ ] A-05 固化“单次搬运成功”定义（什么算成功，什么算失败）。
- [ ] A-06 固化“连续搬运成功”定义（连续次数、是否允许人工干预）。
- [ ] A-07 固化“异常可恢复”定义（失联、卡住、目标丢失时的判定与处理结果）。
- [ ] A-08 制定统一记录模板（每次实测都记：版本、参数、结果、问题）。
- [ ] A-09 输出当前硬件条件清单（主车双摄、辅车标记、三串口分配、通信、执行能力）。
- [ ] A-10 固化灰度传感器在方案中的角色（边界检测与越线判定）。
- [ ] A-11 固化双 UART 持续接收 + 主车主动解析的视觉链路口径。
- [ ] A-12 固化视觉协议升级方向（单次查询对应单相机当前帧，可返回多条检测结果）。
- [ ] A-13 下一轮待规划：若要推进 3.0 入口适配，再单开任务把现有 `boot.py` 入口重写为 `main.py` 单入口 + 按钮长按脚本分发。
- [ ] A-14 固化当前底盘基础约束：主辅车默认维持自身方向闭环，主车当前不主动运动只是业务范围限制，不代表丢失基础运动能力。
- [ ] A-15 固化当前遥控口径：无线串口协议链路就是当前阶段遥控链路，`UART3` 控制链打通即视为遥控能力打通。

### 阶段验收

- 有统一口径文档可供新会话直接读取。
- 队内对成功标准无歧义。

## 阶段 B：双车最小可用协同

### 目标

先打通“单次稳定搬运闭环”。

### 任务

- [ ] B-01 打通主车到辅车的基本控制链路（可稳定下发动作目标）。
- [ ] B-02 打通辅车到主车的状态回传链路（至少包含忙闲、执行状态）。
- [ ] B-03 下一轮待规划：启动顺序与初始化流程若要切到 `main.py` 单入口、按钮脚本分发等新方案，应在单独设计批准后再改。
- [ ] B-04 按双 UART 持续回传、主车主动接收的方案重写视觉链路。
- [x] B-05 打通统一视觉协议下的多检测结果返回（单次查询可回多条消息）。
- [ ] B-06 固化“进入搬运前阵型已就绪”的判定条件。
- [ ] B-07 实现“主车唯一状态机 + 辅车执行”的阵型保持与横向搬运最小闭环。
- [ ] B-07a 让辅车在执行 `dx/dy` 随动时始终维持本地方向闭环，验收时同时检查“方向正确”和“朝向稳定”。
- [ ] B-07b 保留主车与辅车同等级的底盘基础能力边界，但当前阶段不把主车主动运动纳入业务验收。
- [ ] B-08 完成单目标搬运到越线的全流程联调。
- [ ] B-09 完成搬运后保持阵型，不强制重建。
- [ ] B-10 增加单次任务超时保护，避免无限等待。
- [ ] B-11 增加单次任务失败时的安全停机动作。
- [ ] B-12 按双 UART 持续接收、命令下发、最小状态回传和阶段切换重写最小测试用例。
- [ ] B-13 做 10 次单目标搬运测试并记录成功率。
- [ ] B-14 复盘失败样本，形成前 3 大失败原因列表。
- [ ] B-15 打通灰度传感器边界检测链路（可稳定触发、可稳定读取）。
- [ ] B-16 将“推到边界”判定纳入单次搬运闭环。

### 阶段验收

- 单目标搬运成功率达到可接受水平（队内自定阈值）。
- 失败时不会“死锁/死跑/失控”。

## 阶段 C：连续搬运

### 目标

在不重建阵型前提下连续完成多个目标。

### 任务

- [ ] C-01 打通“完成一次后直接找下一目标”的状态切换。
- [ ] C-02 实现连续任务中的目标切换判定（避免重复锁定已完成目标）。
- [ ] C-03 实现连续任务中的阵型保持检查（每次切目标前先判是否可继续）。
- [ ] C-04 实现连续任务中的中途异常转入策略（继续/跳过/退出）。
- [ ] C-05 做 2 连续目标搬运测试并记录结果。
- [ ] C-06 做 3 连续目标搬运测试并记录结果。
- [ ] C-07 统计连续搬运中断原因并分类（通信、视觉、执行、障碍）。
- [ ] C-08 针对最高频中断原因给出对应修正任务。
- [ ] C-09 增加连续任务场景的结果记录模板并开始人工复盘留证。
- [ ] C-10 形成连续搬运稳定版本里程碑。
- [ ] C-11 在连续搬运中验证灰度边界判定一致性。
- [ ] C-12 按双 UART 持续接收与单状态机切换方案重写连续搬运验证记录。

### 阶段验收

- 能稳定完成至少 2 连续搬运。
- 过程中无需人工重置阵型。

---

## 阶段 D：抗扰与恢复

### 目标

把“能跑”提升到“被干扰也能继续跑”。

### 任务

- [ ] D-01 增加通信短时抖动场景测试（模拟丢包/延迟）。
- [ ] D-02 增加通信中断场景测试（短断链与长断链）。
- [ ] D-03 增加目标临时丢失场景测试（可恢复）。
- [ ] D-04 增加卡住场景测试（可退出或可恢复）。
- [ ] D-05 增加障碍干扰场景测试（保持阵型优先）。
- [ ] D-06 定义并落地“失败后下一步动作”统一规则。
- [ ] D-07 对所有异常场景补现场确认记录（视频+记录）。
- [ ] D-08 整理异常码与故障分类清单，方便现场排查。
- [ ] D-09 制作“一页故障快速定位表”。
- [ ] D-10 完成一次完整“异常注入演练”。
- [ ] D-11 增加灰度传感器误触发/漏触发场景测试与恢复策略。
- [ ] D-12 增加单摄失效、持续回传中断与相机数据停滞场景测试与恢复策略。

### 阶段验收

- 关键异常下可恢复或可控退出。
- 不出现无边界等待和无响应状态。

---

## 阶段 E：提速优化

### 目标

在成功率不下降的前提下缩短总耗时。

### 任务

- [ ] E-01 建立基线耗时（单次、连续、异常恢复）。
- [ ] E-02 识别前三大耗时段（搜索、切换、搬运、绕障）。
- [ ] E-03 每次只优化一个耗时段，避免多变量同时变化。
- [ ] E-04 每次优化后做回归：成功率是否保持。
- [ ] E-05 优化目标切换延迟。
- [ ] E-06 优化横移搬运节拍。
- [ ] E-07 优化绕障额外时间。
- [ ] E-08 固化“提速后仍稳定”的参数组。

### 阶段验收

- 相比基线耗时显著下降。
- 成功率和可恢复性不下降。

---

## 阶段 F：赛前封板

### 目标

减少临场变更风险，保证比赛期可复制。

### 任务

- [ ] F-01 冻结可用版本（代码、参数、流程）。
- [ ] F-02 冻结启动流程与操作清单（谁先做什么）。
- [ ] F-03 准备 A/B 备份参数方案（稳妥版/激进版）。
- [ ] F-04 准备通信异常应急流程。
- [ ] F-05 准备视觉异常应急流程。
- [ ] F-06 准备执行异常应急流程。
- [ ] F-07 做完整彩排（含异常注入）。
- [ ] F-08 彩排后只做必要修复，不做大改。
- [ ] F-09 赛前最终确认：版本号、参数、硬件连接、日志开关。
- [ ] F-10 输出比赛日执行卡片（简明版）。

### 阶段验收

- 赛前版本稳定，流程可重复。
- 队员在压力下能按卡片快速执行。

## 2. 每周推进建议（可滚动）

- 周期 1：完成阶段 A + 阶段 B 前半。
- 周期 2：完成阶段 B 后半 + 阶段 C。
- 周期 3：完成阶段 D。
- 周期 4：完成阶段 E + 阶段 F。

> 若时间紧，优先顺序固定：B -> C -> D，再考虑 E。
