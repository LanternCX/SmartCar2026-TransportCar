# 完赛路线任务清单

> 说明：当前正式基线采用单一 `src/`，入口按 `main.py` 单入口 + `C8/C9` 长按脚本分发理解。更深层的 3.0 运行时整理另开设计与任务推进。

> 我正在使用 writing-plans 思路来拆解执行任务。
>
> 本文件用于把“完赛方向”拆成可逐步推进的小任务。每个任务尽量做到半天内可完成、可验证、可复盘。
>
> 实现阶段执行细则、TDD 分层与内存装配规则统一以 `using-rules` 私有参考页为准，本文件只保留任务路线与阶段目标。

## 0. 使用说明

- 每次只开一个任务，完成后再开下一个。
- 每个任务都要有“完成证据”（测试结果、视频、日志或记录）。
- 优先顺序：先稳定完赛，再提速。
- 任务状态建议：`未开始` / `进行中` / `已完成` / `阻塞`。

## 1. 阶段总览

> 说明：当前正式路线按“寻找态状态机集 + 搬运态状态机集”理解。`main.py` 继续作为单入口使用；本文件负责拆解项目演进顺序，不展开更深层的运行时拆分。

- 阶段 A：基础对齐（方向、角色、成功标准、硬件条件）
- 阶段 B：关键能力验证（高频通信、速度前馈、跟随可行性）
- 阶段 C：寻找态最小闭环（边线平移、主前辅后、主车搜索、辅车跟随）
- 阶段 D：搬运态最小闭环（找到物品、前后推、避障插入、越线确认）
- 阶段 E：完整路线闭环（左右推、角度分支、状态机切换、连续搬运）
- 阶段 F：稳定性与赛前收口（抗扰、提速、封板）

---

## 阶段 A：基础对齐

### 目标

把“项目总方向、角色分工、成功标准和硬件条件”统一起来，避免后续路线展开时反复返工。

### 任务

- [ ] A-01 对齐本项目方向文档，确认当前正式基线以 `docs/developer/strategy.md`、`docs/developer/tasks.md`、`docs/developer/control.md` 与 `docs/developer/vision.md` 为主。
- [ ] A-02 对齐总路线由“寻找态状态机集 + 搬运态状态机集”组成，并固化“前后推 + 左右推”两种搬运构型。
- [ ] A-03 对齐主辅角色：主车负责统一决策、目标搜索、状态切换和协同编排；辅车负责协同执行和状态回传。
- [ ] A-04 固化“单目标搬运成功”定义（什么算成功，什么算失败）。
- [ ] A-05 固化“连续搬运成功”定义（连续次数、是否允许人工干预）。
- [ ] A-06 固化“异常可恢复”定义（失联、卡住、目标丢失时的判定与处理结果）。
- [ ] A-07 制定统一记录模板（每次实测都记：版本、参数、结果、问题）。
- [ ] A-08 输出当前硬件条件清单（主车双摄、辅车标记、灰度传感器、串口分配、通信、执行能力）。
- [ ] A-09 固化灰度传感器在方案中的角色（边界检测与越线判定）。
- [ ] A-10 固化下一版视觉链路基线（当前仅保留主辅角色入口骨架，具体观测协议、查询口径与运行时消费路径随重写设计确定）。
- [x] A-11 正式入口采用 `main.py` 单入口 + `C8/C9` 长按脚本分发，`D8/D9` 承担车号识别职责。
- [ ] A-12 固化当前底盘基础约束：主辅车默认维持自身方向闭环，方向保持属于基础能力。
- [ ] A-13 固化当前遥控口径：无线串口协议链路就是当前阶段遥控链路，`UART3` 控制链打通即视为遥控能力打通。

### 阶段验收

- 有统一口径文档可供新会话直接读取。
- 队内对项目总路线、角色边界和成功标准无歧义。

## 阶段 B：关键能力验证

### 目标

先验证“主车到辅车高频通信 + 速度前馈”能否把双车跟随链路做硬，为后续两大状态机集提供基础能力。

### 任务

- [ ] B-01 打通主车到辅车的高频控制链路（可稳定下发连续动作目标）。
- [ ] B-02 打通辅车到主车的最小状态回传链路（至少包含忙闲、执行状态和最小健康信息）。
- [ ] B-03 固化速度前馈在路线中的定位：它属于正式能力，不是附属优化。
- [ ] B-04 固化速度前馈的最小输入输出边界，明确寻找相关跟随与搬运相关跟随都要接入前馈。
- [ ] B-05 先在寻找相关跟随场景验证“视觉跟随主车标记 + 速度前馈”的可行性。
- [ ] B-06 再在搬运相关跟随场景验证“物体观测 + 速度前馈”的可行性。
- [ ] B-07 记录“纯视觉跟随”和“加入速度前馈”两种情况下的差异，形成是否继续推进的判断依据。
- [ ] B-08 固化前馈验证通过标准（响应速度、稳定性、可重复性）和失败标准。
- [ ] B-09 为这一阶段补齐最小测试与留证方式（主机侧验证、板端联调记录、实测结论）。

### 阶段验收

- 能明确判断速度前馈是否足以增强双车跟随链路。
- 高速通信和前馈能力可作为后续状态机路线的基础能力继续使用。

---

## 阶段 C：寻找态最小闭环

### 目标

建立“从边线重新出发，到把双车带到可进入搬运的位置”为止的寻找态最小闭环。

### 任务

- [ ] C-01 实现边线起步后的平移避让，先绕开刚完成搬运的物体。
- [ ] C-02 建立主前辅后构型，并固化进入条件。
- [ ] C-03 打通辅车识别主车色标并完成跟随的最小闭环。
- [ ] C-04 打通主车寻找下一个物体的最小闭环。
- [ ] C-05 固化主车找到物体后进入角度关系分类状态的入口条件。
- [ ] C-06 固化分类状态的最小输出：判断由谁让位、是否需要绕行以及是否需要增加重排状态。
- [ ] C-07 固化同向分支下“主车让辅车”的进入条件与结束条件。
- [ ] C-08 固化完成让位或重排后，辅车向前步进配合并进入搬运态的切换判定。
- [ ] C-09 做寻找态最小闭环测试并记录成功率、耗时和中断原因。

### 阶段验收

- 双车能够从边线重新起步并稳定进入搬运前准备位置。
- 主车搜索与辅车跟随之间的协同关系稳定可重复。

---

## 阶段 D：搬运态最小闭环

### 目标

建立“找到物品后进入搬运、完成前后推、处理中途避障并完成越线确认”为止的搬运态最小闭环。

### 任务

- [ ] D-01 固化搬运态入口条件：物体找到、构型切入完成、可进入推进。
- [ ] D-02 实现前后推构型的最小闭环，完成直行协同推进。
- [ ] D-03 固化主车在搬运态中的目标：持续保持物体在主车推杆上并向目标位置推进。
- [ ] D-04 固化辅车在搬运态中的目标：保持协同支撑并避免物体碰到辅车推杆。
- [ ] D-05 在搬运流程中插入避障状态，并固化其进入条件和退出条件。
- [ ] D-06 打通灰度传感器边界检测链路，并把越线确认纳入搬运闭环。
- [ ] D-07 做单目标搬运全流程测试并记录成功率。
- [ ] D-08 复盘失败样本，形成前 3 大失败原因列表。

### 阶段验收

- 能稳定完成单目标的搬运态最小闭环。
- 失败时不会死锁、死跑或失控。

---

## 阶段 E：完整路线闭环

### 目标

补齐两种搬运构型、四类角度分支和两大状态机集之间的完整切换，形成连续搬运路线。

### 任务

- [ ] E-01 建立左右推构型，并固化其进入条件与退出条件。
- [ ] E-02 固化主车朝向相对目标方向的 `0 / 90 / -90 / 180` 四类分支入口与统一判定口径。
- [ ] E-03 在已有同向分支基础上，补齐四类角度关系各自的后续状态机分流策略。
- [ ] E-04 完成寻找态状态机集与搬运态状态机集之间的正式切换路径。
- [ ] E-05 打通“完成一次后继续找下一目标”的连续切换。
- [ ] E-06 做 2 连续目标搬运测试并记录结果。
- [ ] E-07 做 3 连续目标搬运测试并记录结果。
- [ ] E-08 统计连续搬运中断原因并分类（通信、视觉、执行、障碍、切换）。
- [ ] E-09 形成连续搬运稳定版本里程碑。

### 阶段验收

- 能稳定完成至少 2 连续搬运。
- 两大状态机集之间的切换稳定，不依赖人工重置。

---

## 阶段 F：稳定性与赛前收口

### 目标

在路线闭环基础上补齐抗扰、提速和赛前冻结，确保比赛期可复制。

### 任务

- [ ] F-01 增加通信短时抖动和中断场景测试（丢包、延迟、短断链、长断链）。
- [ ] F-02 增加目标丢失、相机数据停滞和单摄失效场景测试。
- [ ] F-03 增加卡住、障碍干扰和灰度误触发场景测试。
- [ ] F-04 定义并落地失败后的统一处理规则（继续、跳过、退出、停机）。
- [ ] F-05 建立基线耗时，识别搜索、切换、搬运和绕障的主要耗时段。
- [ ] F-06 每次只优化一个耗时段，并回归成功率是否保持。
- [ ] F-07 固化“提速后仍稳定”的参数组。
- [ ] F-08 冻结可用版本（代码、参数、流程、操作清单）。
- [ ] F-09 准备通信、视觉、执行异常的应急流程。
- [ ] F-10 做完整彩排（含异常注入）并输出比赛日执行卡片。

### 阶段验收

- 关键异常下可恢复或可控退出。
- 赛前版本稳定，流程可重复。

## 2. 每周推进建议（可滚动）

- 周期 1：完成阶段 A + 阶段 B。
- 周期 2：完成阶段 C + 阶段 D。
- 周期 3：完成阶段 E。
- 周期 4：完成阶段 F。

> 若时间紧，优先顺序固定：先完成 A，再按 B -> C -> D -> E -> F 推进。
