## Title
重构设备阶段为 stage2 smoke 与 stage3 人工调试

## Background / Issue
仓库原先把 `stage3` 实现成了通过 `mpy-cli` 上传探针再执行的自动观测脚本，这与当前开发目标不一致。新的目标是把自动化能力收束到 `stage2`，保证裸片环境最小运行不报错；把 `stage3` 重新定义为 `uart3` 上的人和 AI 在环调试流程，同时避免干扰 `uart6` 与 OpenArt 的正式链路。

## Change Unit
重构设备验证阶段边界，将自动化 smoke 收束到 Stage 2，并把 Stage 3 明确定义为 uart3 人工调试流程。

## Actions / Outcome
- Approach 1: 直接沿用旧 `run_device_observe.py` 作为 stage3 自动工具 -> 与 `uart6` 职责冲突，且不能反映人工调试流程。
- Approach 2: 仅改文档，不改脚本与测试 -> 名实不符，后续 agent 仍会误用旧入口。
- Final approach: 新增 `tools/run_stage2_smoke.py`，强化 `tools/stage2_smoke_probe.py`，把 `tools/run_device_observe.py` 降级为人工调试提示入口，同时把 query 回包切到来源串口 -> 自动化阶段和人工调试阶段职责重新对齐，`uart3` 调试链路与 `uart6` 正式链路分离。

## Lessons / Refinements
- 设备阶段不要把“自动化能做的 smoke”与“必须靠人观察的现场调试”混成一个 stage；自动化边界越清楚，人接管调试越顺畅。
- 诊断 query 需要按来源串口回包，否则文档里定义的调试链路会停留在概念上，无法真正落到板端使用。
