## Title
抽出 MinimalDiagnostics 并改为按 owner 组装诊断视图

## Background / Issue
`TransportCar` 的诊断查询仍通过整车对象聚合运行时状态, 与内存重构目标不一致。Task 4 要求把最小诊断面收口到显式 owner, 让 health/tick/vision 等查询只读取核心 owner、命令 owner、运动 owner 和视觉 owner, 避免继续把 `TransportCar` 当成诊断状态的唯一载体。

## Change Unit
抽出 MinimalDiagnostics，并把诊断查询改为按 owner 只读组装。

## Actions / Outcome
- Approach 1: 先为 `MinimalDiagnostics` 写失败测试 -> 新增 `tests/unit/services/test_minimal_diagnostics.py`, 先验证 facade 必须读取 core 最新状态而不是复制 `oom_count`, 并验证 `TransportCar.get_diagnostics_facade()` 返回新的最小诊断 owner
- Approach 2: 新建 `src/services/runtime/minimal_diagnostics.py` -> 引入 `_RuntimeOwnerView` 作为最小公共接口, 仅暴露 `DiagnosticsFacade` 需要的字段和 owner, 避免复制运行时状态
- Approach 3: 将 `TransportCar.get_diagnostics_facade()` 切到 `MinimalDiagnostics` -> 正式路径使用 `runtime_core + self/self/self` 组装 owner, 同时保留对旧 `__new__` 测试桩的兼容回退, 防止 host 回归测试因缺少 `runtime_core` 失败
- Final approach: 运行 `python3 -m pytest tests/unit/services/test_minimal_diagnostics.py tests/contract/services/commands/test_diag_queries.py -q` 与 `python3 -m pytest tests/unit/services/test_transport_car_diag_snapshots.py -q` -> 分别得到 `17 passed` 和 `15 passed`, 证明 Task 4 的最小诊断 owner 收口已通过目标 host 验证且未打破现有诊断查询回归

## Lessons / Refinements
- 诊断 facade 的真正依赖面比 `TransportCar` 小得多, 可以先用 owner view 收口读取接口, 再继续下沉命令、运动和视觉 owner
- 迁移到 owner-based 诊断时, 需要显式兼容 `TransportCar.__new__` 这类 host 测试桩, 否则会把架构迁移误伤为测试回归
- 以 `DiagnosticsFacade` 作为复用逻辑、以 `MinimalDiagnostics` 作为 owner 装配层, 可以减少改动面并保持 query handler 契约稳定
