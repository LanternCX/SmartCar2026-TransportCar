## Title
将视觉协议与视觉状态机从共同前缀平铺文件迁移为真正分包

## Background / Issue
在 `services.car` 分包完成后, `vision.protocol` 和 `vision.state_machine` 虽然已经做了职责下沉, 但实现仍以 `protocol_query.py`、`protocol_parse.py`、`state_machine_core.py` 这类共同前缀平铺文件存在。用户进一步指出, 这种写法本质上还是用前缀模拟命名空间, review 不通过, 必须改成真正分包并把规则写进编码规范。

## Change Unit
将视觉协议和状态机从共同前缀平铺模块迁移为真正分包，并同步更新布局约束。

## Actions / Outcome
- Approach 1: 直接把这两个文件从行数门禁中排除 -> gate 会变绿, 但 `vision/` 仍保留多职责 God module, 结构不统一
- Approach 2: 保留公开入口 `vision.protocol` / `vision.state_machine`, 但继续使用 `protocol_query.py` / `state_machine_core.py` 这类共同前缀平铺文件 -> 职责下沉了, 但 review 仍不接受, 因为命名空间仍由前缀模拟
- Final approach: 把 `vision.protocol` 迁移为 `src/vision/protocol/` 分包, 把 `vision.state_machine` 迁移为 `src/vision/state_machine/` 分包, 同时更新布局测试、MicroPython 兼容测试和编码规范 -> `python3 -m pytest tests/unit/test_services_package_layout.py tests/unit/services/test_vision_protocol.py tests/unit/services/test_vision_state_machine.py tests/unit/services/test_transport_car_vision_integration.py tests/unit/services/test_micropython_compatibility.py tests/contract/services/test_transport_runtime_protocol.py -q` 通过, `python3 -m pyright src/vision/protocol src/vision/state_machine src/vision/runtime.py src/services/car src/services/stage2_smoke/full.py src/script/remote_control.py tools/stage2_full_trace_probe.py tools/device_observe_probe.py` 为 `0 errors`, `tests/unit/test_src_runtime_file_sizes.py` 也通过

## Lessons / Refinements
- 行数 gate 可以适度放宽, 但职责拆分不应只靠 gate 驱动; 对协议和状态机这类高复杂度领域模块, 统一结构边界比机械压行数更重要
- 当一个领域拆成多个实现文件时, 共同前缀平铺文件只是过渡形态, 不能当成最终结构; 最终必须收拢为分包
