# 主车 UART3 速度转发实现计划

> 状态: archive
> **For agentic workers:** 必须使用 `superpowers:subagent-driven-development` 执行本计划, 按任务逐项落地并在每个任务后完成自检。

**目标:** 让主车角色层只响应 `UART3` 下行控制, 并把其中辅车已支持的 `vx / vy / omega` 速度字段经 `UART3` 上行转发给辅车, 同时保持主车本地控制链不变。

**架构:** 在 `vision/master/` 下新增一个与辅车角色层风格一致的主车角色运行时, 由它接管 `UART3` 读取边界、抽取速度字段、向辅车写出转发行, 再把原始命令继续交给共享底盘。主车当前阶段不接视觉、不接其他输入源、不做自主行控, 调试入口固定为单一 `UART3` 链路。

**技术栈:** Python / MicroPython 兼容运行时代码, pytest 单元测试, 当前 `vision/master/` 角色包结构, 现有 `UART3` 文本控制协议

## 任务 1: 先锁住主车角色层入口与 UART3 转发边界

**目标:** 先用失败测试固定主车入口外观和主车 `UART3` 转发规则, 防止实现时把范围写大。

- [ ] 在 `tests/unit/test_role_vision_layer_factory.py` 中更新主车入口断言, 让它要求 `vision.master.runtime.create_transport_car()` 返回主车角色运行时对象, 不再直接是共享底盘对象。
- [ ] 新建 `tests/unit/test_master_forward_runtime.py`, 补齐主车角色层最小行为测试。
- [ ] 为以下场景分别写失败测试:
  - 纯速度命令会被抽取并写到辅车链路, 原始整行仍继续交给主车共享底盘。
  - 混合命令只转发速度字段, 非速度字段不进入辅车链路。
  - 查询和非速度命令不会被转发。
  - 串口写出失败只记录最小错误, 不阻断控制周期。
  - 主车角色层当前不接视觉输入, 控制周期中不存在视觉分支装配。
- [ ] 运行定向测试, 保留“先失败”的证据。

## 任务 2: 实现主车角色层运行时与 UART3 接管

**目标:** 在 `vision/master/` 内建立与辅车侧风格一致的主车角色运行时, 由角色层接管 `UART3`。

- [ ] 新建 `src/vision/master/forward_runtime.py`, 以共享底盘为内核对象装配主车角色运行时外观。
- [ ] 在主车角色运行时里复用与辅车侧一致的最小外观:
  - 暴露 `wheel_states`
  - 暴露 `imu`
  - 转发 `mark_tick()`
  - 转发 `set_ticker()`
  - 在 `step()` 里先跑角色层周期, 再跑共享底盘周期
- [ ] 让主车角色层接管 `UART3`, 屏蔽共享底盘自身对同一串口的重复读取。
- [ ] 在主车角色层内部维护 `UART3` 未成行缓冲和最近一次错误文本。
- [ ] 保持主车当前阶段不创建、不读取、不装配任何视觉输入对象或视觉串口。

## 任务 3: 实现速度字段抽取、上行转发和原始命令透传

**目标:** 让主车角色层按 spec 固定的单链路规则完成“下行接收、上行转发”。

- [ ] 在主车角色层中实现速度字段识别, 只接受 `vx / vy / omega / w`。
- [ ] 对每一条完整命令行执行以下顺序:
  - 先按逗号拆分并抽取速度字段
  - 若有有效速度字段, 重新组织成单行文本写到 `UART3`
  - 无论是否发生转发, 都把原始整行继续交给主车共享底盘处理
- [ ] 查询、位置/角度目标、模式命令、系统命令和其他非速度内容一律不进入转发链。
- [ ] 混合命令采用“速度字段转发, 原始整行本地继续执行”的固定口径。
- [ ] 速度字段非法时不向辅车转发, 但主车本地仍继续按原始命令处理, 同时记录最小错误文本。
- [ ] 保持写出格式与辅车现有入口一致, 使用单行 `vx / vy / omega` 文本和 `\r\n` 结尾。
