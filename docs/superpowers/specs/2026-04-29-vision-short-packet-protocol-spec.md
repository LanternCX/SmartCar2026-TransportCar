## 背景

车端 `UART6` 视觉链路的正式协议为数据流短包。视觉端负责逐帧生成辅车需要的二维速度修正量, 车端负责消费最近一帧速度修正量并执行。

视觉仓库需要和车端正式协议保持一致: OpenART 通过 `UART(2)` 向车端 `UART6` 持续发送 `v` 短包。视觉侧目标识别、目标选择、阶段判断、控制量计算和逐帧发送节奏保持稳定, 本规格只定义协议表达与仓库口径收口。

## 目标

1. 保持 `main.py` 单文件运行时架构不变。
2. 保持 `UART(2)`、`115200` 波特率、`\r\n` 行尾和逐帧发送策略不变。
3. 将视觉端正式载荷定义为 `v,<vx>,<vy>`。
4. `UART6` 视觉链路只发送二维速度修正量, 不发送 `omega`。
5. 保持目标检测、候选目标选择、误差计算、死区、比例系数、限幅和无目标处理行为不变。
6. 保持无目标和保持区显式发送零量。
7. 同步更新测试、`README.md` 和 `docs/Protocol.md`, 让视觉仓库正式口径只指向短包协议。

## 非目标

1. 不修改车端运行时代码。
2. 不修改 OpenART 与 RT1021 的硬件连接、串口编号或波特率。
3. 不调整色块阈值、摄像头参数、目标选择算法或控制参数。
4. 不引入状态同步、确认包、事件回报或查询类报文。
5. 不发送 `o`、`s`、`a`、`r` 包。
6. 不保留 `key=value` 载荷的运行期兼容层。
7. 不把视觉仓库运行时代码拆分成多文件结构。

## 协议规格

### 串口边界

| 链路 | OpenART 侧 | RT1021 侧 | 用途 |
| :--- | :--- | :--- | :--- |
| 视觉主链路 | `UART(2)` | `UART6` | 发送视觉速度修正量 |

传输约定:

1. 编码使用 ASCII 单行文本。
2. 每条消息以 `\r\n` 结束。
3. 发送端每抓取一帧就发送一条当前帧结果。
4. 接收端按最近一帧结果执行, 视觉端不等待逐帧确认。

### 正式载荷

视觉端正式载荷固定为:

```text
v,<vx>,<vy>
```

字段语义:

| 位置 | 字段 | 类型 | 含义 |
| :--- | :--- | :--- | :--- |
| 1 | `v` | 字符 | 速度数据流短包类型 |
| 2 | `vx` | 浮点文本 | 车体系 x 方向视觉速度修正量 |
| 3 | `vy` | 浮点文本 | 车体系 y 方向视觉速度修正量 |

约束:

1. `v` 包只包含 `vx` 和 `vy` 两个数值字段。
2. `UART6` 视觉链路不发送第四个 `omega` 字段。
3. 零值输出为 `0`。
4. 接近零的数值按零值收敛规则输出为 `0`。
5. 数值文本保持紧凑格式, 不填充无意义尾零。
6. 每条载荷都必须能独立表达当前帧速度修正量。

合法示例:

```text
v,0.12,0
v,0,0
v,-0.8,0.45
```

## 运行时行为

### 控制链路

视觉侧运行时流程保持为:

1. 初始化串口与摄像头。
2. 抓取当前图像。
3. 提取色块候选目标。
4. 选择当前帧最优目标。
5. 计算横向误差与纵向误差。
6. 根据误差、死区和比例系数生成 `vx` / `vy`。
7. 将 `vx` / `vy` 编码为 `v,<vx>,<vy>` 并发送。

### 阶段输出

阶段只服务于视觉侧内部判断和主机侧行为测试, 不进入串口载荷。

| 场景 | 输出要求 |
| :--- | :--- |
| 无有效目标 | `v,0,0` |
| 保持区 | `v,0,0` |
| 仅横向超出死区 | `v,<vx>,0` |
| 仅纵向超出死区 | `v,0,<vy>` |
| 横向和纵向同时超出死区 | `v,<vx>,<vy>` |

控制量的符号、比例映射和限幅结果以当前行为为准。协议切换不得改变同一输入样例对应的 `vx` / `vy` 数值。

### 无目标与保持区

无目标和保持区都通过显式零量表达:

```text
v,0,0
```

视觉端不通过停发来表达静止, 也不依赖车端把缺包解释为零量。

## 文档收口

### `README.md`

需要明确:

1. 视觉端通过 `UART(2)` 向车端 `UART6` 发送速度数据流短包。
2. 正式格式为 `v,<vx>,<vy>`。
3. 无目标和保持区发送 `v,0,0`。
4. 视觉端负责识别、阶段判断和速度修正量生成。

### `docs/Protocol.md`

需要明确:

1. 视觉主链路是 `UART(2)` 到 `UART6`。
2. 消息为 ASCII 单行短包, 行尾为 `\r\n`。
3. `v` 包字段按位置解析。
4. `UART6` 视觉链路不发送 `omega`。
5. 高频数据流不逐帧确认。

文档和注释改动只做 Review 与规则检查, 不为文档文字单独编写测试。

## 验收标准

1. `main.py` 仍是唯一运行时入口。
2. 视觉端正式输出为 `v,<vx>,<vy>`。
3. `UART6` 视觉链路不发送 `omega`。
4. 无目标和保持区输出 `v,0,0`。
5. 同一误差输入对应的 `vx` / `vy` 数值保持不变。
6. 正式运行路径不生成 `key=value` 视觉载荷。
7. `README.md` 与 `docs/Protocol.md` 口径一致。
8. `python3 -m pytest tests/unit tests/contract -q` 通过。

## 需要 Review 的点

1. 是否接受 `UART6` 视觉链路固定发送三段式 `v,<vx>,<vy>`, 不带 `omega`。
2. 是否确认协议切换只改变载荷格式, 不调整视觉控制参数和行为。
3. 是否确认双轴同时超出死区时继续发送两个非零速度修正量。
