# 2026-04-08 辅车位置式跟随速度上限调整设计

> 状态: archive

## 背景

当前辅车位置式跟随链采用“主车持续刷新位置目标, 辅车在本地按位置误差做平移控制, 控制超时窗口保持 150ms 硬停”的结构。

最近串口联调暴露出的主要问题不是协议不能工作, 而是当前窗口内的有效位移偏小。当主车侧持续给出较大的位置目标时, 辅车虽然会在窗口内持续执行, 但由于当前位置式跟随的平移速度上限偏低, 单个有效窗口能走出的距离有限, 这会压缩主车视觉侧可用参数范围, 也会让联调时更依赖主车把目标量推得很大。

用户当前确认的约束如下:

1. 继续保留位置式跟随, 不改成时间式伪位置控制。
2. 继续保留 150ms 硬停边界, 不放宽超时窗口。
3. 不引入“误差越大越快”的新动态规则, 避免增加新的整定负担。
4. 优先解决“当前窗口内走不够远”的问题, 不重写整条控制方法。

## 目标

1. 在不改变位置式跟随主语义的前提下, 提高单个有效窗口内的可达位移。
2. 保持当前位置式在近距离阶段的可控感, 不把整条链路变成另一种控制方法。
3. 不扩大协议面, 不要求主车额外承担新的计算职责。
4. 不破坏速度模式、超时停机、显式停机和默认保头等已收口行为。

## 非目标

1. 本轮不引入新的跟随模式。
2. 本轮不把位置式控制切换为纯时间推进。
3. 本轮不新增按误差动态变化的速度规则。
4. 本轮不追求提高里程计的绝对精度。
5. 本轮不改主辅协议字段和报文结构。

## 问题归因

当前位置式跟随链的主要瓶颈不在于“是否持续执行”, 而在于“持续执行时允许的平移速度上限偏低”。

在当前结构里:

1. 主车持续刷新位置目标。
2. 辅车本地根据位置误差生成平移速度。
3. 平移速度会受到固定上限约束。
4. 若超出 150ms 没有收到新包, 辅车直接进入硬停或保护路径。

因此, 当位置目标较大时, 是否能在窗口里明显拉近距离, 主要取决于该固定上限是否足够高。若此时再同时改超时窗口、位置比例或引入新的动态调速规则, 会把“窗口长度”“最大速度”“近场收敛手感”三个问题混在一起, 提高联调难度。

## 设计决策

### 一、继续保留位置式本地闭环

位置式跟随仍然保持当前基本结构:

1. 主车发送位置式目标。
2. 辅车在本地按累计位置与当前目标之间的差值持续收敛。
3. 近距离阶段仍然依赖这条本地闭环自然减速与收口。

这样做的原因是: 用户明确认可位置式更容易控制。本轮的目的不是替换这条控制思路, 而是提高它在当前窗口内的有效输出能力。

### 二、继续保留 150ms 硬停边界

超时边界继续保持 150ms。

本轮不通过拉长窗口来换取更大的累计位移, 因为那样会把“跟随更快”与“陈旧目标保留更久”混成同一个现象, 不利于分辨真实改进点, 也会增加失去新视觉输入后的动作风险。

### 三、本轮只提高位置式平移速度上限

当前位置式跟随的平移速度上限继续保留为固定参数, 但数值上调。

本轮只动这一处的原因是:

1. 它直接决定远距离误差阶段的最大追赶能力。
2. 它不改变主协议和模式语义。
3. 它不会把位置式偷偷改造成另一种控制方式。
4. 它能把调参问题尽量收口到单一变量, 便于现场判断效果。

### 四、本轮不同时改位置比例项

虽然位置比例项同样会影响平移输出, 但本轮不和速度上限一起调整。

原因是:

1. 当前最明显的问题来自大误差阶段的追赶距离不足, 主要受速度上限限制。
2. 若同时修改比例项和速度上限, 将难以判断最终改善来自哪一项。
3. 先只改上限, 更容易观察近距离阶段是否已经出现明显变冲或难停的问题。

若这一轮完成后仍然确认“远距离够用, 但近距离手感不理想”, 再单独讨论第二个参数是否需要调整。

### 五、里程计继续保留为本地收敛参考

本轮不以“提高里程计绝对精度”为目标, 但也不把位置式改写为纯时间推进。

原因是:

1. 即使里程计不够精确, 它仍然能为本地收敛提供基本参考。
2. 若改成纯时间推进, 控制结果会更直接受电池状态、载荷和地面摩擦影响。
3. 位置式近场可控感的来源之一, 正是本地仍然知道自己“是否已经接近目标”。

## 影响范围

本轮设计只影响辅车位置式跟随链中的固定平移速度上限。

明确不应受影响的内容包括:

1. 速度模式入口与持续行为。
2. 超时停机边界。
3. STOP 与 DISARM 的真停机语义。
4. 默认保头与显式角速度例外规则。
5. 协议格式与外部字段语义。

## 验收标准

本轮完成后, 至少需要同时满足以下标准:

1. 在相同 150ms 有效窗口下, 位置式跟随的单窗口有效位移明显增加。
2. 近距离位置式收敛没有出现明显更冲、更难停的退化现象。
3. 速度模式语义与现有联调口径保持不变。
4. 超时、停机和保头行为不被连带改坏。
5. 主机侧回归能够证明本轮只调整位置式速度上限, 未扩大协议或模式语义。

## 验证建议

建议验证顺序如下:

1. 先做主机侧最小回归, 固定住位置式、速度模式和超时边界的基本语义。
2. 再做板端高频位置式串口测试, 对比同样窗口内的追赶距离。
3. 最后补做近距离收敛观察, 确认没有因为单纯提速而明显变差。

## 结论

本轮不追求把辅车位置式跟随重新设计成另一种控制系统, 而是以最小改动解决当前最明确的瓶颈: 固定窗口内的有效位移不足。为此, 设计选择保留位置式、保留 150ms 硬停、保留本地收敛参考, 只提高位置式平移速度上限, 以最小耦合成本换取更大的可用动态范围。
