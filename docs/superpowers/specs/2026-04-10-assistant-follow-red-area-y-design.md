# 2026-04-10 辅车跟随红色色块面积纵向控制设计

> 状态: archive
> 说明: 软件侧实现已完成; Vision 主机侧回归通过, 当前口径已切到只识别 red 且以面积误差驱动纵向控制。

## 背景

当前辅车主动跟随主线已经切到“辅车 OpenArt 直接输出 follow 请求, 辅车控制板沿用现有执行核心”的口径。

现有视觉控制里:

1. 目标识别仍同时包含 `red` 和 `green`。
2. 横向控制 `x` 仍按目标中心相对画面中心的位置误差生成。
3. 纵向控制 `y` 仍按目标在画面中的纵向位置误差生成。

用户新增的设计想法是:

1. 辅车摄像头为平放视角。
2. 纵向距离感更适合通过目标面积反映, 不再继续依赖画面中的上下位置。
3. 本轮只识别 `red` 色块。
4. `x` 方向控制保持当前设计, 不顺手重写整体跟随节奏。

因此, 这次设计不是重做整套跟随, 而是在保持左右控制和阶段节奏基本不变的前提下, 只把纵向控制依据从“位置”切换为“面积”。

## 目标

本轮设计只追求以下结果:

1. 视觉层只识别 `red` 色块。
2. 横向控制继续沿用当前中心偏差方案。
3. 纵向控制改成围绕目标面积的误差生成。
4. 目标面积先做成可调参数, 不在本轮写死最终实物值。
5. 红色色块丢失时, 辅车立即停下。

## 非目标

本轮明确不做以下事情:

1. 不重写横向控制逻辑。
2. 不重写整体阶段节奏。
3. 不把纵向控制升级成多段复杂策略。
4. 不在本轮确定最终上板调好的面积目标值。
5. 不扩展到除 `red` 之外的新目标识别策略。

## 用户已确认的设计边界

用户已经确认以下边界:

1. 这是一次“小改 y 方向”的变更, 不是整套跟随重做。
2. 面积到纵向控制采用目标面积误差方案。
3. 目标面积先作为可调参数保留。
4. 丢目标时立即停下。

另外, 在讨论中虽然提到“带死区的 P 环就好, 不带也可以”, 但从实际运行稳定性看, 面积信号天然比横向中心更容易抖动, 如果不设死区, 辅车在目标附近更容易前后小幅来回蹭动。因此本设计默认保留一个较小死区, 作为推荐方案的一部分。

## 设计方案

### 总体思路

新的跟随口径保持为:

1. `x` 继续由红色色块中心相对画面中心的横向偏差生成。
2. `y` 不再看纵向位置误差, 改为看红色色块面积相对目标面积的差值。
3. 当面积误差落入死区时, 认为前后距离已经合适, 不再输出纵向动作。
4. 当面积小于目标面积时, 说明目标偏远, 输出前进方向的纵向控制。
5. 当面积大于目标面积时, 说明目标偏近, 输出后退方向的纵向控制。

### 识别层收口

视觉层从当前“多颜色候选集合”收口为“只看 `red`”。

这样做的原因是:

1. 这次目标已经明确为只跟随红色色块, 保留其他颜色只会增加选择歧义。
2. 面积作为纵向距离依据时, 必须确保参与计算的是同一类目标, 否则目标切换会直接破坏前后控制稳定性。
3. 收口成单颜色后, 当前目标选择逻辑也可以保持更简单。

### 横向控制保持不变

横向控制不进入这轮设计范围, 继续使用现有方法:

1. 以目标中心相对画面中心的横向偏差生成 `x` 控制。
2. 继续保留现有横向死区与阶段节奏。
3. 不因为这次改纵向依据而改横向参数口径。

这条边界很重要, 因为它保证这次变更不会扩散成“重新调一整套跟随行为”。

### 纵向控制改为面积误差

纵向控制统一改成以下语义:

1. 先从当前红色色块提取面积值。
2. 用“当前面积 - 目标面积”得到面积误差。
3. 若面积误差绝对值不超过死区, 则 `y=0`。
4. 若面积误差超出死区, 则按一个较轻的比例系数生成 `y` 控制量。
5. 控制方向必须满足“面积偏小向前, 面积偏大向后”。

这里的目标不是追求非常激进的前后逼近, 而是让辅车在相机平放视角下, 用更符合实际距离感的信号完成前后跟随。

### 参数设计

本轮需要新增或替换为以下可调参数:

1. 目标面积参数: 表示期望跟随距离下的红色色块面积。
2. 面积死区参数: 表示认为前后距离已经足够接近的误差范围。
3. 面积比例参数: 表示面积误差映射到纵向控制量时的力度。
4. 纵向控制上限参数: 限制前后动作幅度, 防止面积抖动导致过冲。

其中, 目标面积不在本轮设计中写死具体数值, 只要求它以可调参数形式存在, 便于后续上板标定。

### 阶段行为

本轮不重写整体阶段节奏, 只替换纵向阶段的判据:

1. 目标无效时, 继续走无效输入路径, 立即停下。
2. 横向未对齐时, 继续优先做横向对齐。
3. 横向进入现有允许范围后, 再根据面积误差决定是否做纵向动作。
4. 横向已对齐且面积误差进入死区时, 认为当前跟随位置成立。

这样可以最大限度复用现有跟随节奏, 只把“前后是否到位”的判断信号换掉。

## 数据流

调整后的视觉到执行链路如下:

`红色色块识别 -> 提取中心与面积 -> 保持现有 x 生成方式 -> 用面积误差生成 y -> 输出 follow 请求`

其中:

1. `x` 仍表达左右方向的位置式控制。
2. `y` 改为基于面积误差的前后控制。
3. 输出格式不变, 仍对齐辅车执行侧当前已经支持的 `follow` 请求语义。

这样做的好处是, 辅车控制板不需要因为这次设计改协议入口或重写控制核心。

## 异常处理

本轮沿用现有保守安全口径, 并对面积方案补充以下要求:

1. 红色色块丢失时, 立即输出无效跟随并停下。
2. 不允许沿用上一拍面积结果继续盲走。
3. 面积异常跳变时, 仍要经过纵向控制上限约束, 避免单拍过大动作。
4. 无效输入、超时或坏包场景下, 辅车执行侧仍按原有安全规则停下。

## 测试与验证口径

本轮软件侧至少要验证以下内容:

1. 视觉层只保留 `red` 目标参与跟随。
2. 横向控制行为保持不变。
3. 面积误差在死区内时, 纵向输出为零。
4. 面积偏小时, 纵向输出方向为前进。
5. 面积偏大时, 纵向输出方向为后退。
6. 红色色块丢失时, 输出无效跟随并停下。
7. 输出格式继续与辅车执行侧现有 `follow` 请求兼容。

当前阶段只做软件侧验证与主机侧回归, 不把上板标定作为本轮完成前提。

## 实施范围

这次设计预计主要影响:

1. `SmartCar2026-Vision/main.py` 中颜色任务集合、目标特征提取与纵向控制生成。
2. `SmartCar2026-Vision/tests/unit/test_vision_protocol_rebuild.py` 中与纵向控制和颜色选择相关的测试。
3. 需要同步的协议或说明文档中, 对纵向控制依据的描述。

这次设计不应扩散到:

1. 车端执行协议重写。
2. 主车侧新功能设计。
3. 横向控制逻辑重做。
4. 多颜色协同目标策略。

## 推荐方案结论

在本轮范围下, 推荐采用:

1. 只识别 `red`。
2. `x` 保持原样。
3. `y` 采用“目标面积误差 + 小死区 + 轻比例 + 控制上限”的最小方案。
4. 目标丢失立即停下。
5. 目标面积先作为可调参数保留, 后续再通过上板标定收敛具体值。

这个方案最符合“只改 y 判据、不扩散范围、尽快形成可调闭环”的目标。
