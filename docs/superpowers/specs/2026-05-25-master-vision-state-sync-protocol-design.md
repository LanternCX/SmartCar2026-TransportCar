# 主车视觉状态同步协议结构设计

> 执行状态: Archive
> 关联计划: `docs/superpowers/plans/2026-05-25-master-vision-state-sync-protocol-plan.md`
> 适用范围: 当前车端仓库的主车 RT1021 角色运行入口、本车 `UART6` 主车视觉链路、主车状态机与视觉任务切换通信结构、附属视觉仓库主车 OpenART 入口

## 1. 目标

主车本车 `UART6` 视觉链路采用与辅车一致的任务切换思路: 由车端运行时向视觉端同步当前任务状态, 视觉端根据收到的状态与参数切换内部任务, 并按该任务的约定输出速度或可靠事件。

本次目标是统一主车和辅车的通信底层结构, 让主车视觉任务切换采用“状态同步驱动视觉任务”的正式语义。主车仍保留全局任务上下文能力, 避免过期视觉结果误触发当前状态。

## 2. 设计判断

辅车当前任务切换结构更清晰:

- 主车先向辅车底盘同步辅车子状态。
- 辅车底盘再向辅车视觉同步本地视觉任务。
- 视觉根据状态与参数决定输出速度或回报事件。
- 任务切换权属于车端状态机, 视觉不拥有全局任务切换权。

主车应采用同一类结构:

- 主车状态机仍决定全局任务阶段。
- 主车 RT1021 向主车 OpenART 同步视觉任务。
- 主车 OpenART 根据任务状态和参数切换搜索、对正或结束判定任务。
- 主车 OpenART 只输出速度或事件, 不拥有主车全局状态机。

## 3. 范围

### 3.1 做

- 调整主车 `UART6` 视觉任务同步语义, 使其表达“状态同步驱动视觉任务”。
- 保留主车视觉事件的上下文匹配能力, 防止过期事件影响当前任务。
- 统一主车与辅车在以下通信基础能力上的结构:
  - 按行读取。
  - 速度短包解析。
  - 可靠短包确认。
  - 可靠短包重发。
  - 重复包幂等处理。
  - 输入缓存上限与坏包处理。
- 明确主车视觉任务切换权属于主车 RT1021 状态机。
- 明确主车 OpenART 只按同步到的视觉任务输出速度或事件。
- 同步调整 `../SmartCar2026-Vision/master` 的主车 OpenART 入口, 使视觉端按状态同步任务切换内部视觉任务。
- 更新当前仓库协议、视觉和状态机说明。
- 补充行为测试与契约测试, 覆盖主车状态同步、重复同步、过期事件忽略、速度输出和事件回报。

### 3.2 不做

- 不修改硬件串口号、引脚、电平或接线事实。
- 不改变主车全局状态机的业务阶段。
- 不改变底盘控制核心、运动学、PID、编码器和 IMU 逻辑。
- 不把辅车强行改为主车 hook 格式。
- 不让视觉端维护主车全局状态机。
- 不新增串口链路。
- 主车视觉任务切换只保留一种正式语义。
- 不在正式代码中维护两套主车视觉任务切换语义。
- 不在 Spec 中写实现代码。

## 4. 目标语义

### 4.1 主车视觉任务同步

主车 RT1021 通过本车 `UART6` 向主车 OpenART 发送可靠状态同步短包。同步内容表达:

- 可靠包序号。
- 主车视觉任务上下文编号。
- 主车当前全局状态。
- 当前目标。
- 当前视觉任务参数。

主车 OpenART 收到合法同步后:

- 返回确认包。
- 只在更新的上下文或重复上下文下处理该任务。
- 对重复同步包重复确认, 不重复执行任务进入副作用。
- 对较早上下文只确认, 不回退视觉任务。

### 4.2 主车视觉输出

主车 OpenART 根据当前同步任务输出两类内容:

- 数据流速度包: 用于搜索、对正或结束判定过程中的主车平移速度。
- 可靠事件包: 用于目标找到、对正完成或结束判定满足。

速度包不携带任务名、阶段名、有效位或调试字段。事件包必须能被主车 RT1021 判定是否属于当前任务上下文。

### 4.3 上下文能力

主车保留上下文编号。上下文编号用于区分不同主车视觉任务, 不是辅车子状态同步中的简单序号。

上下文编号的作用:

- 匹配视觉事件是否属于当前主车任务。
- 让过期事件可以被确认但不触发状态推进。
- 让重复事件可以被确认但不重复推进状态。

## 5. 与辅车结构的对应关系

| 维度 | 辅车 | 主车目标结构 |
| --- | --- | --- |
| 任务决策方 | 主车全局状态机 | 主车全局状态机 |
| 中间运行时 | 辅车 RT1021 | 主车 RT1021 |
| 视觉任务同步 | 辅车 RT1021 -> 辅车 OpenART | 主车 RT1021 -> 主车 OpenART |
| 视觉任务输入 | `state/target/arg` | `context/state/target/arg` |
| 视觉速度输出 | `v,<vx>,<vy>` | `v,<vx>,<vy>` |
| 视觉事件输出 | `r,<seq>,<event>,<value>` | `r,<seq>,<context>,<event>,<value>` |
| 过期事件防护 | 依赖当前子状态 | 依赖当前上下文 |

该结构统一的是任务切换模型, 不是把主车和辅车的事件载荷完全做成同一格式。

## 6. 主车状态切换流程

### 6.1 搜索任务

主车进入搜索任务时:

1. 主车状态机创建新的视觉任务上下文。
2. 主车 RT1021 向主车 OpenART 同步搜索状态、目标和搜索参数。
3. 主车 OpenART 确认后进入搜索任务。
4. 主车 OpenART 持续输出搜索速度。
5. 搜索满足条件后, 主车 OpenART 回报目标找到事件。
6. 主车 RT1021 只接受当前上下文中的目标找到事件。

### 6.2 搬运入口对正任务

主车进入搬运入口对正任务时:

1. 主车状态机创建新的视觉任务上下文。
2. 主车 RT1021 向主车 OpenART 同步对正状态、目标和对正参数。
3. 主车 OpenART 确认后进入对正任务。
4. 主车 OpenART 输出对正速度。
5. 对正满足条件后, 主车 OpenART 回报对正完成事件。
6. 主车 RT1021 只接受当前上下文中的对正完成事件。

### 6.3 搬运结束判定任务

主车进入搬运结束判定任务时:

1. 主车状态机创建新的视觉任务上下文。
2. 主车 RT1021 向主车 OpenART 同步结束判定状态、目标和判定参数。
3. 主车 OpenART 确认后进入结束判定任务。
4. 主车 OpenART 可继续输出视觉速度。
5. 结束条件满足后, 主车 OpenART 回报到达事件。
6. 主车 RT1021 只接受当前上下文中的到达事件。

## 7. 协议边界

### 7.1 保留的正式包类型

主车视觉链路继续使用正式短包类型:

- `v`: 视觉速度数据流。
- `s`: 状态同步可靠短包。
- `a`: 可靠确认短包。
- `r`: 可靠事件短包。

`o` 包只作为观测或诊断包, 不作为主车搜索控制主线。

### 7.2 主车视觉同步包

主车视觉同步包表达主车视觉任务, 包含上下文编号。字段语义应在 `docs/developer/protocol.md` 中只维护一套正式说明。

### 7.3 辅车状态同步包

辅车状态同步包保持轻量结构, 不携带主车视觉上下文编号。辅车的子状态同步仍服务辅车本地任务切换, 不被强行改造成主车视觉上下文包。

## 8. 运行时结构

### 8.1 共享通信能力

主车和辅车应共用以下基础能力:

- 串口按行读取和缓存管理。
- 速度短包解析与命令限幅。
- 可靠包发送节流。
- 待确认包重发。
- 重复包确认。
- 环形序号先后判断。

共享能力不持有主车或辅车业务状态机, 只提供通信机制。

### 8.2 主车角色层

主车角色层负责:

- 根据主车状态机输出创建视觉任务同步。
- 发送或重发当前待确认视觉同步。
- 接收主车视觉确认。
- 接收主车视觉速度并写入共享底盘。
- 接收主车视觉事件并按当前上下文交给主车状态机。
- 忽略或只确认不属于当前上下文的过期事件。

### 8.3 主车视觉端

主车 OpenART 负责:

- 接收主车 RT1021 同步的视觉任务。
- 根据状态和参数切换视觉内部任务。
- 输出 `v,<vx>,<vy>` 速度。
- 在任务完成时输出带上下文的可靠事件。
- 不维护主车全局状态机。

主车 OpenART 修改范围位于 `../SmartCar2026-Vision/master`。视觉仓库作为当前车端仓库的附属仓库维护, 协议和任务切换语义以当前车端仓库 Spec 和开发文档为准。

## 9. 测试策略

### 9.1 契约测试

契约测试覆盖:

- 主车视觉状态同步包的格式化与解析。
- 主车视觉确认包的格式化与解析。
- 主车视觉事件包的格式化与解析。
- 辅车状态同步包保持现有格式。
- 主车视觉包与辅车状态同步包不会互相误解析。

协议层实现改动前必须先完成行为测试基线盘点。若主车车端、辅车车端或主车视觉端的行为测试不足, 先补齐测试, 再调整实现。

### 9.2 主车运行时行为测试

主车运行时测试覆盖:

- 进入搜索任务时发送主车视觉状态同步。
- 收到视觉确认后清理待确认同步。
- 未收到确认时按可靠间隔重发同步。
- 重复确认不会重复推进状态。
- 视觉速度只在允许视觉速度的状态写入底盘。
- 当前上下文事件触发主车状态机。
- 过期上下文事件被确认但不触发主车状态机。
- 重复事件被确认但不重复触发主车状态机。
- 状态切换时清理上一任务的视觉速度缓存。

### 9.3 辅车回归测试

辅车回归测试覆盖:

- 辅车仍通过 `state/target/arg` 切换本地视觉任务。
- 辅车重复同步包只确认, 不重复执行进入状态副作用。
- 辅车速度融合规则保持稳定。
- 辅车找物体与对正事件仍按当前子状态解释。

### 9.4 视觉仓库测试

视觉仓库测试覆盖:

- 主车 OpenART 接收状态同步后切换视觉任务。
- 主车 OpenART 对重复同步只确认, 不重复执行进入任务副作用。
- 主车 OpenART 对较早上下文只确认, 不回退当前视觉任务。
- 主车 OpenART 速度输出仍为 `v,<vx>,<vy>`。
- 主车 OpenART 事件输出携带当前上下文。
- 主车 OpenART 事件确认按可靠序号清理待确认事件。

### 9.5 文档检查

文档检查覆盖:

- `docs/developer/protocol.md` 只描述当前正式协议。
- `docs/developer/vision.md` 清楚区分主车视觉任务同步和辅车子状态同步。
- 文档不使用历史性口吻。
- 文档只维护一种正式主车视觉任务切换语义。

## 10. 验收标准

- 主车视觉任务切换语义与辅车一致: 车端同步任务, 视觉按任务输出速度或事件。
- 主车仍能用上下文编号防止过期视觉事件影响当前状态。
- 主车和辅车共用通信底层机制, 读行、重发、确认和速度解析逻辑只有一个正式维护入口。
- 附属视觉仓库主车 OpenART 入口按状态同步任务切换内部视觉任务。
- 辅车现有任务切换、速度融合和事件回报行为保持稳定。
- 主车视觉搜索、对正和结束判定行为保持稳定。
- 当前仓库单元测试与契约测试通过。

## 11. 风险与约束

- 视觉仓库与车端仓库需要在同一轮开发中保持协议语义一致, 否则车端协议结构改变后无法完成联调。
- 主车状态机与视觉事件的上下文匹配必须保持严格, 否则过期事件可能误触发当前任务。
- 共享通信层不能引入重型常驻对象或复杂动态分配, 避免增加板端内存压力。
- 行为测试应覆盖过期事件、重复同步和重复事件, 避免只验证正常路径。
- 板端联调前需要确认主车 OpenART 与 RT1021 双端协议已同步。
