# 主辅统一绕行模式 Spec

> 执行状态: Archive  
> 创建日期: 2026-05-04  
> 范围: 在共享底盘中新增主辅统一绕行模式, 用单一半径倍率驱动主车与辅车绕行, 保持主车流程前后行为不变

## 目标

在当前主辅协同流程中, 为主车和辅车提供同一套共享底盘绕行模式。

这次任务的本质, 是在共享底盘里新增一个全新的运动解算模式。

该模式对外只暴露“目标角度 + 半径倍率”两个输入。角色层不再直接以 `x / y / omega` 作为绕行调参接口, 而是把半径倍率交给共享底盘内部解算。共享底盘继续沿用旧 `rear only` 模式的角速度目标链路生成 `omega_cmd`, 再基于目标半径语义解出本次需要的线速度 `v_cmd`, 最后把这组线速度和角速度交给现有底盘控制链, 完成最终绕行。

本次改动的重点是统一绕行控制语义, 不是扩展新的状态机主线。主车寻找、停辅车、主车绕行、辅车找物体、辅车绕行这一整条流程顺序保持不变, 只替换主车和辅车在“绕行时怎么动”的底层实现。

## 当前基线

当前工作区已经回退到干净基线, 后续实现必须从这份基线重新开始, 不默认继承任何已经回退的 orbit 行为改动。

当前基线中的相关事实如下:
- 主车已经存在自身绕行流程, 状态机主线为 `IDLE -> SEARCH_OBJECT -> ORBITING -> IDLE`。
- 主车当前进入 `ORBITING` 时, 通过共享底盘的旧绕行入口执行本车绕行。
- 这个旧入口本质上是当前主车绕行基准, 但它不是本轮新模式本体。
- 辅车当前只支持 `ASSISTANT_IDLE`、`ASSISTANT_FOLLOW`、`ASSISTANT_APPROACH_OBJECT`, 还没有正式接入绕行子状态。
- 辅车当前在 `ASSISTANT_APPROACH_OBJECT` 阶段, 负责向本地视觉同步状态、接收本地命中回报, 再通过现有可靠链路向主车回报 `TARGET_FOUND`。
- 当前共享底盘对角色层暴露的是通用速度目标和旧的主车绕行入口, 还没有主辅统一的专用绕行模式入口。

这份 Spec 的作用, 就是在这份干净基线之上重新定义“统一绕行模式应该是什么”, 避免后续执行时丢失上下文。

## 设计动机

这次重写的动机不是“再加一个能动起来的模式”, 而是把绕行的调参语义收束成一个可执行、可理解、可落地的单参数接口。

当前问题有四层:
- 主车和辅车如果沿用不同绕行模式, 后续调参和联调会分裂成两套口径。
- 如果把绕行直接暴露成 `x / y / omega` 三个量, 调参维度过多, 很难映射到你真正关心的“绕行半径”这个物理直觉。
- 如果直接把“半径”当成真实物理长度, 就会被迫引入当前阶段并不希望引入的底盘几何模型。
- 当前旧 `rear only` 绕行只能提供单一体感半径, 不能直接表达可变半径绕行需求。
- 当前新模式如果不明确保留旧 `rear only` 的角速度目标链路, 后续实现时就容易再次退回到“双变量手调”的错误方向。

因此本轮设计的目标是:
- 用同一套模式统一主车和辅车绕行。
- 对外把调参接口收束成“目标角度 + 半径倍率”。
- 用主车旧绕行体感作为 `1.0` 的单位半径基准, 给新模式一个可对照的调参锚点。
- 保留旧 `rear only` 模式的角速度目标行为, 只把“固定半径”扩成“可变半径”。
- 在不引入真实几何模型的前提下, 让“半径倍率变大, 体感绕行半径变大”成为稳定成立的行为语义。
- 用这套新模式完整替代旧 `rear only` 绕行用途。

## 本轮不采用的方向

为了避免后续执行再次走偏, 本轮明确不采用以下方向:

- 不采用“主车继续旧模式、辅车单独新模式”的拆分方案。
- 不采用只给辅车加绕行状态、主车不切换到底层统一模式的方案。
- 不采用把绕行控制直接暴露成 `x / y / omega` 外部调参接口的方案。
- 不采用把新模式命名为 `rear only` 的方案。
- 不采用通过底盘半径、轮距、车体尺寸去换算真实物理半径的方案。
- 不采用“角度目标 + 手调横移速度”的双自由度调参方案。

这几条不是实现细节偏好, 而是本轮设计边界。

## 模式定义

新增一个共享底盘专用绕行模式。

该模式:
- 不是 `rear only` 模式。
- 不是普通速度模式。
- 不是把 `x / y / omega` 暴露给角色层的调参模式。
- 是一个专门服务绕行的独立运动解算模式。

该模式的对外输入固定为:
- `target_angle_deg`: 本次绕行目标角度。
- `radius_scale`: 本次绕行半径倍率。

共享底盘在每个控制拍中根据当前角度误差和半径倍率:
1. 先沿用旧 `rear only` 模式的角速度目标链路生成 `omega_cmd`。
2. 再根据 `radius_scale` 和单位半径基准解出当前需要的线速度 `v_cmd`。
3. 再把这组线速度和角速度送入现有底盘控制链。
4. 最后复用现有三轮逆运动学得到轮速输出。

这个模式的定位, 不是保留 `rear only` 再额外补一个新分支, 而是作为 `rear only` 绕行能力的正式扩充与替代。

## 单位半径基准

`radius_scale = 1.0` 定义为主车当前旧 `rear only` 绕行体感的单位半径基准。

这个基准只用于统一新模式的调参语义:
- `1.0` 表示与主车当前旧绕行基准相同量级的体感半径。
- 大于 `1.0` 表示更大的绕行半径。
- 小于 `1.0` 表示更小的绕行半径。

这里的“半径”是工程调参语义, 不是实际物理长度。
本次实现不引入主车底盘半径、辅车底盘半径、轮距或车体几何尺寸计算, 只保留单参数半径倍率接口, 让主辅差异通过参数调整吸收。

单位半径基准的使用方式固定为:
- 旧 `rear only` 模式提供角速度目标行为和 `1.0` 基准语义。
- 新模式在 `radius_scale = 1.0` 时, 应尽量贴近旧 `rear only` 的单位半径体感。
- 新模式在 `radius_scale` 改变时, 只改变由半径语义解出的线速度部分, 不改变旧角速度目标链路本身。

## 运动学口径

- 车体系 `x` 表示左右方向。
- 车体系 `y` 表示前后方向。
- 新绕行模式内部只使用车体系 `x` 方向的伴随平移和车体系旋转量。
- 车体系 `y` 在新绕行模式中固定为 `0`。

角色层不直接写入绕行用的 `x / y / omega`。
角色层只写入目标角度和半径倍率。
共享底盘内部负责沿用旧角速度目标链路生成 `omega_cmd`, 再把半径倍率解成线速度 `v_cmd`, 然后进入现有底盘控制链。

## 解算约束

新绕行模式的解算满足以下要求:
- 半径倍率和转动量必须通过单一模式内部耦合解算, 不把两个独立调参量暴露给外层。
- 目标绕行半径必须先被解算为线速度, 再与旧 `rear only` 角速度目标链路生成的 `omega_cmd` 一起交给底盘执行。
- `omega_cmd` 的目标行为必须与旧 `rear only` 模式保持一致。
- 半径倍率增大时, 体感绕行半径单调增大。
- 角度误差减小时, 绕行输出同步收敛。
- 达到目标角度容差后, 本地停止输出。
- 解算结果最终仍复用现有三轮逆运动学, 不单独维护第二套轮速分配链路。

本次 Spec 不要求在文档中固定具体公式, 只固定输入语义、输出边界和行为要求。
实现时可以在共享底盘内部采用单独 solver, 但 solver 对角色层必须保持“角度目标 + 半径倍率”的单参数接口。
该 solver 的职责是把“目标半径语义”收敛成“需要的线速度”, 并与旧角速度目标链路生成的 `omega_cmd` 组成最终控制输入, 再交由底盘执行。

## 参数

| 参数 | 当前建议配置 | 含义 |
| --- | --- | --- |
| `MASTER_ORBIT_TARGET_DEG` | `90` | 主车绕行目标角度 |
| `MASTER_ORBIT_RADIUS_SCALE` | `1.0` | 主车绕行半径倍率, 作为单位半径基准 |
| `ASSISTANT_ORBIT_TARGET_DEG` | `-90` | 辅车绕行目标角度 |
| `ASSISTANT_ORBIT_RADIUS_SCALE` | `1.25` | 辅车绕行半径倍率 |

所有参数统一放在 `src/config/params.py`。
测试与运行时代码都动态读取参数模块当前值, 不在行为逻辑和测试断言中写死具体配置值。

## 对外暴露接口

本轮对外接口分两层:

### 共享底盘接口

共享底盘对角色层新增一个统一绕行模式入口。

该入口的职责固定为:
- 接收目标角度。
- 接收半径倍率。
- 切换到底盘内部统一绕行模式。
- 在后续控制拍中自行完成“沿用旧角速度目标链路 + 半径 -> 线速度”的解算、收敛和停止。

该入口对外只接受以下输入语义:
- `target_angle_deg`
- `radius_scale`

该入口不对角色层暴露:
- 绕行专用 `x`
- 绕行专用 `y`
- 绕行专用 `omega`
- 任何底盘几何参数

### 角色层接口

主车和辅车角色层都不直接写绕行专用速度量。

角色层只负责:
- 选择进入绕行的时机。
- 读取各自的角度参数和半径倍率参数。
- 调用共享底盘统一绕行模式入口。
- 保持现有状态同步与 ACK 行为。

角色层不负责:
- 在角色层自己解算半径到速度的关系。
- 在角色层自己维护第二套轮速分配。
- 在角色层同时调 `x / y / omega`。

## 主车行为

主车主线流程不变:
- `IDLE -> SEARCH_OBJECT -> ORBITING -> IDLE`
- 主车找到物体后仍先让辅车 `IDLE`
- 收到辅车 `IDLE` ACK 后仍进入主车绕行
- 主车绕行完成后仍下发 `ASSISTANT_APPROACH_OBJECT`

本次只替换主车绕行阶段的底层控制方式:
- 主车进入 `ORBITING` 时, 不再调用旧的 `rear only` 绕行入口。
- 主车改为调用新的共享底盘绕行模式入口。
- 主车绕行目标角度和半径倍率分别从 `MASTER_ORBIT_TARGET_DEG` 与 `MASTER_ORBIT_RADIUS_SCALE` 读取。
- 主车绕行完成判据仍沿用“达到目标角度后本地停止”的现有收口语义。

主车前后行为不变的含义固定为:
- 状态切换顺序不变。
- 进入和退出绕行的触发时机不变。
- 主车绕行完成后给辅车下发 `ASSISTANT_APPROACH_OBJECT` 的行为不变。
- 主车收到辅车 `TARGET_FOUND` 后再下发辅车绕行同步的行为不变。

## 辅车行为

辅车保留 `ASSISTANT_ORBIT` 子状态, 由主车通过 `UART8` 同步驱动。

辅车收到 `ASSISTANT_ORBIT` 同步后:
- 回复 ACK。
- 清空 `UART8` 前馈速度缓存。
- 清空 `UART6` 视觉速度缓存。
- 清空本地找物体相关待发送项。
- 写入共享底盘统一绕行模式入口。
- 绕行期间忽略 `UART8` 与 `UART6` 的速度输入。
- 达到目标角度后本地停止输出。
- 停止后不发送绕行完成回报。
- 停止后保持 `ASSISTANT_ORBIT` 子状态, 等待主车后续同步。

辅车绕行目标角度和半径倍率分别从 `ASSISTANT_ORBIT_TARGET_DEG` 与 `ASSISTANT_ORBIT_RADIUS_SCALE` 读取。

## 内部调用链

为了避免执行时只看到局部改动而丢失全貌, 本轮内部调用链固定如下:

### 主车调用链

1. 主车状态机按现有流程进入 `ORBITING`。
2. 主车角色运行时读取 `MASTER_ORBIT_TARGET_DEG` 与 `MASTER_ORBIT_RADIUS_SCALE`。
3. 主车角色运行时调用共享底盘统一绕行模式入口。
4. 共享底盘内部统一绕行 solver 先沿用旧 `rear only` 角速度目标链路生成 `omega_cmd`。
5. 共享底盘再根据 `MASTER_ORBIT_RADIUS_SCALE` 解出线速度 `v_cmd`。
6. 共享底盘再把结果送入现有三轮逆运动学。
7. 共享底盘在达到角度容差后本地停止。
8. 主车状态机按现有完成判据继续推进到后续 `ASSISTANT_APPROACH_OBJECT` 同步。

### 辅车调用链

1. 辅车收到主车下发的 `ASSISTANT_ORBIT` 同步。
2. 辅车角色运行时先 ACK。
3. 辅车角色运行时清空两路速度缓存和本地待发送项。
4. 辅车角色运行时读取 `ASSISTANT_ORBIT_TARGET_DEG` 与 `ASSISTANT_ORBIT_RADIUS_SCALE`。
5. 辅车角色运行时调用共享底盘统一绕行模式入口。
6. 共享底盘内部统一绕行 solver 先沿用旧 `rear only` 角速度目标链路生成 `omega_cmd`。
7. 共享底盘再根据 `ASSISTANT_ORBIT_RADIUS_SCALE` 解出线速度 `v_cmd`。
8. 共享底盘再把结果送入现有三轮逆运动学。
9. 共享底盘在达到角度容差后本地停止。
10. 辅车本地保持 `ASSISTANT_ORBIT` 子状态, 等待主车后续同步。

### 责任边界

这条调用链中各层职责固定为:
- 参数层负责存放目标角度和半径倍率。
- 角色层负责状态编排、ACK 和入口调用。
- 共享底盘负责沿用旧角速度目标链路、解算线速度、接入逆运动学和停止收口。
- 协议层只负责同步和 ACK 字段解析, 不负责绕行控制逻辑。

## 主辅同步链路

本次保留当前主辅同步链路语义:
1. 辅车启动后按现有规则跟随主车。
2. 主车找到物体后下发 `ASSISTANT_IDLE`。
3. 主车完成本车绕行后下发 `ASSISTANT_APPROACH_OBJECT`。
4. 辅车在找物体阶段收到本地视觉命中事件后, 按现有可靠回报链路回报 `TARGET_FOUND`。
5. 主车收到辅车 `TARGET_FOUND` 回报后, 回复 ACK, 并下发 `ASSISTANT_ORBIT`。
6. 辅车收到 `ASSISTANT_ORBIT` 后进入统一绕行模式。
7. 辅车完成本地绕行后停止输出, 等待后续同步。

其中:
- 不新增主车全局状态。
- 不新增辅车绕行完成回报。
- 主车不等待辅车绕行完成。
- `ASSISTANT_ORBIT` 继续使用 `state=3`, `target=1`, `arg=0`。

## 运行边界

- 不新增硬件串口、引脚或接线事实。
- 不修改 OpenART 视觉识别算法。
- 不新增辅车绕行完成回报。
- 不新增主车全局状态。
- 不引入主车底盘半径、辅车底盘半径、轮距或车体几何尺寸计算。
- 不把绕行接口扩成 `x / y / omega` 外部调参接口。
- 不改写 `UART3` 上游速度控制语义。
- 不在本轮改开发文档。

## 验收标准

- 当前错误方向的 orbit 代码已回退, 工作区回到干净基线。
- 共享底盘存在单独的统一绕行运动解算模式入口。
- 该入口对外只接收目标角度和半径倍率。
- 角色层不直接以 `x / y / omega` 作为绕行调参输入。
- 共享底盘会继续沿用旧 `rear only` 的角速度目标行为。

- 主车进入 `ORBITING` 时调用统一绕行模式, 不再调用旧 `rear only` 绕行入口。
- 主车绕行前后状态切换顺序不变。
- 主车绕行完成后的后续动作不变。

- 主车和辅车到达目标角度后都会本地停止输出。
- 主机侧单元测试和契约测试通过。

## 自检

- 本 Spec 聚焦同一套共享底盘绕行模式及其主辅接入。
- 本 Spec 不包含代码。
- 本 Spec 不依赖未确认硬件事实。
- 本 Spec 不把旧 `rear only` 继续当成新模式名。
- 本 Spec 明确把本轮任务定义为“新增统一绕行运动解算模式, 用它替代旧 `rear only` 绕行用途”。
- 本 Spec 保留单参数半径倍率接口, 避免把绕行调参扩成两个自由变量。
