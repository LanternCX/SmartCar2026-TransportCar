# 主车轮速回归滤波替换为一阶低通设计

## 背景

当前主车在接入视觉后仍然会在板端运行一段时间后触发内存分配失败。虽然最新栈顶仍落在 `uart.py` 的输入接收位置, 但沿主车热路径继续往下看, 轮速滤波链中的双窗口线性回归仍然是一块持续运行、持续维护窗口状态的重负担。

当前主车轮速滤波链为:

1. 尖峰压制。
2. 差分限幅。
3. 双窗口线性回归预测。

其中前两段主要负责抑制毛刺和跳变, 最后一段负责在跟手和稳态之间折中, 但它需要持续维护长短两个窗口, 并在每拍做回归计算。这一段在板端并不是唯一内存风险来源, 但属于明显的热路径高负担点。

用户本轮明确要求先从滤波入手, 把当前双窗口线性回归滤波替换成与现有效果接近的一阶低通滤波, 并且已经确认以下边界:

1. 这轮只改主车。
2. 这轮只替换轮速链中的回归段。
3. 效果目标是折中版本, 不追求极端稳态或极端响应。
4. 外部参数口径先尽量保持不变, 不把本轮扩大成参数体系重写。

## 当前问题归纳

### 一、双窗口回归在热路径里持续维护可变窗口状态

当前实现每拍都要把新样本分别推进长窗和短窗, 再做一次预测融合。这意味着:

1. 长窗和短窗都要长期保存多拍历史。
2. 每拍都要更新两份窗口内容。
3. 每拍都要重新计算回归结果。

这套链路在主机侧未必显得昂贵, 但在板端热路径中属于值得优先减负的部分。

### 二、这轮不能顺手推翻整条轮速滤波链

当前轮速滤波链的前两段已经承担了明确职责:

1. 尖峰压制负责把单拍毛刺压回局部中位水平。
2. 差分限幅负责阻止跳边和误码直接拉坏后续控制量。

若本轮把整条链一起重做, 改动面会迅速扩大到“重新定义轮速滤波策略”, 这和用户当前要求的“只先换回归段”不一致。

### 三、外部参数口径不能在这轮一起翻新

当前外部入口已经暴露了 `LONG_WINDOW`、`SHORT_WINDOW` 等参数。若本轮顺手把它们全部改成新的低通参数口径, 会带来以下问题:

1. 主车运行时装配一起变动。
2. 现有测试和调参口径一起变动。
3. 本轮从“替换内部实现”扩大成“重写外部滤波参数接口”。

因此本轮更合适的方向不是“重新命名全部参数”, 而是“先在内部把旧参数折算成一阶低通强度”。

## 目标

本轮设计必须同时达成以下目标:

1. 把主车轮速滤波链中的双窗口回归段替换为一阶低通段。
2. 保留尖峰压制和差分限幅两段现有职责。
3. 让主车轮速滤波输出继续保持“不过分发散、不过分拖”的折中效果。
4. 明显减少运行期为回归窗口维护而保留的跨周期状态和每拍计算负担。
5. 尽量保持外部参数入口不变, 不把本轮扩大为参数体系重写。

## 非目标

本轮明确不做以下事情:

1. 不修改辅车滤波链。
2. 不重写主车整条轮速滤波链。
3. 不修改姿态低通或航向保持链。
4. 不调整 PID、运动学、协议或视觉状态机语义。
5. 不顺手建立新的全局状态容器或新的 owner 层。

## 方案比较

### 方案一：只替换主车回归段, 外部参数口径保持不变

保留当前“尖峰压制 -> 差分限幅 -> 最后一段滤波”的结构, 只把最后的双窗口回归改成一阶低通, 并在内部把旧参数折算成等效低通强度。

优点:

1. 改动最小。
2. 直接命中当前热路径最重的滤波段。
3. 不会把这一轮扩成整条控制链重整。

缺点:

1. 外部参数名和内部真实实现暂时不完全一致。
2. 低通效果只能追求接近当前折中版本, 不能等价复刻双窗口回归。

结论: 这是本轮推荐方案。

### 方案二：主车整条轮速滤波链一起简化

同时调整尖峰压制、差分限幅和回归段, 统一重写成新的轻量链路。

优点:

1. 长期结构更统一。

缺点:

1. 范围明显扩大。
2. 很难再把问题收在“回归段替换”这一件事上。

结论: 这轮不采用。

### 方案三：主辅两车同类滤波一起统一

把主车和辅车同类轮速滤波都一起换成一阶低通。

优点:

1. 两边滤波语义保持一致。

缺点:

1. 和用户明确要求的“只改主车”冲突。
2. 会显著扩大回归面。

结论: 这轮不采用。

## 核心设计

### 一、主车轮速滤波链仍保留三段结构

本轮改完后, 主车轮速滤波链仍然保留三段:

1. 尖峰压制。
2. 差分限幅。
3. 一阶低通。

也就是说, 本轮不是“删掉前两段只留低通”, 而是只把最后那段更重的回归预测替换掉。

### 二、一阶低通只保留最小跨周期状态

新的最后一段不再保存长窗、短窗和时间戳窗口, 只保留一阶低通真正需要的最小跨周期状态, 让运行期每拍只推进固定的少量数值。

这正是本轮对内存和热路径最有价值的地方。

### 三、旧参数先折算成等效低通强度

为了不把这一轮扩大成参数体系重写, 这轮保留现有参数入口, 但内部增加一层折算规则, 把当前窗口参数换算成低通强度。

这样做的目的不是长期保持这种映射, 而是让本轮能以最小改动先把热路径减轻。

### 四、效果目标是“接近当前折中版本”

本轮验收不以“输出数值逐拍完全等于旧回归滤波”为目标, 因为一阶低通和双窗口回归本来就不是同一类滤波。

本轮真正追求的是:

1. 输出仍然平滑。
2. 对尖峰仍然不敏感。
3. 响应不明显变拖。
4. 主车运行时装配和轮速环主线不被带坏。

## 涉及范围

### 一、主要修改文件

1. `src/master/ctrl/filters.py`
   - 删除主车轮速链对双窗口回归的依赖。
   - 改为一阶低通实现, 并增加旧参数到低通强度的内部折算。

2. `src/master/motion_runtime.py`
   - 保持主车滤波链装配位置不变。
   - 只在必要处调整装配接线, 让新滤波段进入运行时。

3. `tests/unit/master/test_stability_baseline.py`
   - 补主车轮速滤波链的一阶低通行为边界测试。

4. `tests/unit/master/test_motion_runtime.py`
   - 补主车运行时仍能正常装配和使用轮速滤波链的验证。

### 二、明确不修改的区域

1. `src/assistant/` 全部主线。
2. `src/master/ctrl/attitude.py`。
3. `src/master/ctrl/pid.py`。
4. `src/master/vision/` 全部主线。
5. 主车外部协议语义。

## 验收标准

本轮完成后, 至少要满足以下标准:

1. 主车轮速滤波链不再依赖双窗口回归对象。
2. 主车轮速滤波输出仍然是稳定浮点结果, 且尖峰输入不会原样直通。
3. 主车运行时仍能正常装配滤波链并完成轮速闭环主线。
4. 相关主机测试通过, 没有把主车其他主线语义带坏。
5. 板端后续验证时, 可以继续观察这次替换是否对长期运行稳定性有正贡献。

## 后续边界

若这轮替换完成后, 板端内存问题仍然明显存在, 后续应继续按热路径优先级往下收, 但不属于本设计范围:

1. 再评估串口输入链和视觉整理链是否仍是主要分配热点。
2. 再评估是否需要把外部滤波参数正式改成新的低通口径。
3. 最后才考虑是否要把辅车的同类滤波一起统一。
