# 主辅车方向闭环基础能力与视觉随动主线修正规范

## 背景

上一版运行收口设计 `docs/superpowers/specs/2026-03-30-visual-follow-runtime-closure.md` 已经把“主车不动、视觉控辅车随动”这条主线的运行收口、参数归位和板端留证写成了新的核心目标，但在底盘基础能力定义上仍然缺了一条关键前提：

**所有福来轮底盘都必须默认具备自身方向闭环能力。**

这不是后续增强项，也不是“如果实现路径刚好经过再接入”的可选能力，而是福来轮底盘稳定运行的基础条件。若没有自身方向闭环补偿，底盘即使收到了 `dx/dy` 指令，也无法稳定地按预期方向运行，最终会把“主车视觉控辅车随动”这条主线降级成“收到控制后有动作，但运动方向与姿态不稳定”的假闭环。

因此，本设计不是改变主线目标，而是修正主线定义：

1. 主车当前阶段仍然不主动运动。
2. 主车当前阶段仍然只对辅车下发二维 `dx/dy` 控制。
3. 但**所有车默认维持自身方向闭环**，这是底盘基础能力。
4. 尤其是辅车，在执行 `dx/dy` 随动时，**方向闭环必须始终开启**，不能作为后补项。
5. 主车当前虽不主动运动，但底盘基础控制能力必须与辅车同等级，至少包括速度控制命令接收能力与方向闭环稳定能力。

## 与上一版运行收口 spec 的关系

本设计是对 `2026-03-30-visual-follow-runtime-closure.md` 的强制修正，而不是新开一条并行目标线。

### 继续沿用的部分

以下内容保持不变：

1. 当前唯一业务目标仍然是“主车静止、视觉控辅车随动”。
2. 主车仍然只根据双路视觉输出辅车二维随动控制。
3. 当前阶段仍然不恢复主车主动运动。
4. 当前阶段仍然不恢复灰度主线。
5. 运行收口、参数归位、板端 smoke、HIL 留证、内存留证仍然是本轮必做项。

### 本设计新增并收紧的部分

本设计新增以下硬约束：

1. **所有车的底盘层默认维持自身方向闭环。**
2. **方向闭环是底盘基础能力，不允许再被写成“当前主线未启用”。**
3. **辅车执行 `dx/dy` 随动时，方向闭环必须始终开启。**
4. **主车当前虽不主动运动，但主车底盘层默认也维持自身方向闭环能力，只是当前阶段不主动给自己下运动目标。**
5. **主车底盘基础控制层必须保留与辅车同等级的通用运动能力，包括速度控制命令接收能力。**

## 核心结论

本轮主线应该按下面这句话重新理解：

**主车当前不主动给自己下运动目标，只通过视觉给辅车下发二维随动控制；主辅车底盘都默认维持自身方向闭环，辅车在这个前提下执行 `dx/dy` 随动。**

因此，以下说法都不再成立：

1. “当前阶段只要能收到 `dx/dy` 并让辅车动起来，就算执行链闭合。”
2. “偏航相关参数当前主线未启用，可以先不接入。”
3. “方向闭环可以等主线跑通后再补。”

## 目标

本轮新增目标如下：

1. 把方向闭环明确纳入主辅车底盘基础能力定义。
2. 让辅车当前主线执行链始终经过方向闭环补偿，而不是裸着执行 `dx/dy`。
3. 让当前主线参数迁移清单中，方向闭环相关参数从“状态项”升级为“必须接入项”。
4. 让板端 smoke 与 HIL 留证能明确观察到“随动时仍维持自身朝向稳定”这一现象。
5. 让主车底盘基础控制层保留和辅车同等级的通用运动能力，但不把主车主动运动本身纳入当前业务验收。

## 非目标

本轮仍然不做以下内容：

1. 不把主车改成主动运动。
2. 不让主车给辅车下发外部角度目标。
3. 不恢复当前主线无关的 Legacy 行为模式。
4. 不把“方向闭环基础能力”扩展成主车当前阶段主动走轨迹或主动对准目标。

## 基础约束

### 一、所有车默认维持自身方向闭环

这是本设计最核心的新增硬约束。

含义如下：

1. 主车底盘层默认具备自身方向闭环能力。
2. 辅车底盘层默认具备自身方向闭环能力。
3. 当前阶段主车虽然不主动运动，但主车底盘层默认也维持自身方向闭环，只是不进入主动运动业务目标。
4. 当前阶段辅车执行随动时，方向闭环必须参与控制输出。
5. 主车底盘控制层必须保留通用速度控制命令接收能力，不能因为当前主线不让主车主动运动，就把这层能力删掉。

### 二、主车不发角度目标，不代表辅车没有方向闭环

当前主线保持：

1. 主车只发 `dx/dy`
2. 主车不发角度目标
3. 主车不负责替辅车算外部角度目标

但辅车必须：

1. 在本地维持自身当前朝向稳定
2. 在这个前提下执行 `dx/dy` 随动

也就是说，方向闭环是辅车执行层内部必须始终存在的补偿，不是主车额外下发的外部业务指令。

### 三、方向闭环必须被视为底盘基础能力，而不是业务可选项

因此，本轮所有与“当前主线是否接入方向闭环”相关的表述都必须按以下口径重写：

1. 不是“若当前实现真实经过再接入”。
2. 而是“当前主线默认必须经过”。

## 对上一版参数迁移定义的修正

上一版 spec 中，偏航相关参数被列为：

1. 不纳入本轮“必须迁完”清单
2. 只需要在新位置标注状态

这与当前底盘基础约束冲突，本轮必须修正。

### 必须升级为当前主线必须接入的参数

以下参数从现在开始不再允许只标记状态，必须迁入新位置并进入真实运行行为：

1. `YAW_KP`
2. `YAW_KI`
3. `YAW_I_MAX`
4. `AUTO_OMEGA_MAX`

### 当前主线必须迁入并被真实读取的参数清单

当前主线参数清单应修正为固定包括：

1. `FOLLOW_TIMEOUT_MS`
2. `FOLLOW_CONTROL_KP_X`
3. `FOLLOW_CONTROL_KP_Y`
4. `FOLLOW_CENTER_DEADZONE_PX`
5. `CONTROL_TICK_MS`
6. `FOLLOW_OUTPUT_LIMIT`
7. `PID_MAP["m"]`
8. `PID_MAP["l"]`
9. `PID_MAP["r"]`
10. `SPEED_FILTER_WINDOW`
11. `SPEED_DIFF_MAX_DELTA`
12. `GYRO_LPF_ALPHA`
13. `YAW_KP`
14. `YAW_KI`
15. `YAW_I_MAX`
16. `AUTO_OMEGA_MAX`

### 参数口径补充

这里的“被真实读取”必须按以下口径理解：

1. 不是只把参数放进文件。
2. 不是只在运行时构造对象时抄成成员变量。
3. 而是方向闭环相关参数必须真实影响当前主线的控制输出或限幅行为。

## 对执行链定义的修正

### 主车侧

主车当前阶段仍然只做：

1. 视觉读取
2. 双路选路
3. 当前目标判断
4. 输出辅车二维跟随语义

主车当前阶段不负责：

1. 替自己生成主动运动目标
2. 替辅车下发外部角度目标

但主车底盘层默认也维持自身方向闭环，只是当前阶段不主动给自己下运动目标，也不把主车主动运动作为本轮验收内容。

同时，主车底盘基础层必须保留：

1. 通用速度控制命令接收能力
2. 自身方向闭环稳定能力
3. 与辅车同等级的底盘基础控制边界

也就是说，主车当前阶段是“业务上不主动运动”，而不是“底盘层不具备运动能力”。

### 辅车侧

辅车当前阶段必须形成以下真实执行链：

1. 接收主车发来的 `dx/dy`
2. 维持自身方向闭环
3. 在方向闭环补偿下执行二维随动
4. 丢失、超时或无效时停住
5. 对外回传最小状态

只有在这条链路成立时，才允许说“辅车真实执行链闭合”。

## 对板端现象定义的修正

板端不再只观察“辅车有没有动”，而要观察：

1. 辅车是否朝正确平移方向随动。
2. 辅车在随动过程中是否持续保持当前朝向，不出现持续自旋。
3. 辅车在连续跟随期间是否没有持续偏航漂移到新的稳定朝向。

这里的判定口径固定为当前阶段可直接观察的板端现象，不在本轮额外引入新的数值阈值门槛。

也就是说：

1. “有输出”不等于“执行链闭合”。
2. “电机有反应”不等于“已达到当前主线要求”。
3. 必须观察“随动 + 朝向稳定”同时成立。

## 对 smoke / HIL / review 门禁的修正

### smoke 必须新增的观察项

1. 辅车收到跟随后是否进入随动状态。
2. 随动过程中是否持续保持当前朝向，不出现持续自旋。
3. 超时或丢失后是否停止且不继续自旋。

### HIL 必须新增的记录项

1. 随动时是否持续保持当前朝向。
2. 是否出现持续自旋。
3. 是否出现持续偏航漂移到新的稳定朝向。

### review 门禁必须修正为

这次 review 除了保留上一版的 4 个顺序门禁外，还必须新增第 5 个门禁：

1. **先看主辅车能不能直接作为独立根目录烧录运行。**
2. **再看整条主线链路是否真正闭合。**
3. **再看当前主线参数是否完整归位。**
4. **再看内存留证是否支持“更优”结论。**
5. **最后看主辅车底盘是否默认维持自身方向闭环，且辅车随动时是否始终维持该闭环。**

这里的“更优”只允许按上一版运行收口 spec 中已经固定的内存留证口径判断，不允许临时改义。

并且在结构 review 时，必须额外回答：

1. 主车底盘基础控制层是否仍具备通用速度控制命令接收能力。
2. 主车当前不主动运动，是否只是业务验收范围限制，而不是能力缺失。

若第 5 项不能回答“是”，则当前主线不得视为通过，即使前面 4 项都满足，也只能算“结构和收发链路更完整”，不能算“当前主线运行收口完成”。

## 分阶段实施建议

1. 先修订现有运行收口 spec 与 plan 中所有把方向闭环写成可选项的地方。
2. 先补方向闭环相关失败测试，再补实现。
3. 让辅车方向闭环真实进入执行链，而不是只存在参数入口和对象构造中。
4. 再补板端 smoke 与 HIL 的方向稳定观察项。
5. 最后再做内存留证，因为只有主线定义修正后，内存对比才有意义。

## 结论

这份设计修正的不是业务目标，而是底盘基础约束。对福来轮底盘而言，方向闭环不是增强项，而是稳定运行的基础能力；同样，主车底盘基础控制层也不能因为当前阶段不主动运动，就丢失与辅车同等级的通用运动能力。当前主线必须被重新定义为：主车当前不主动给自己下运动目标、只发二维随动控制；但主辅车底盘都默认维持自身方向闭环，且主车保留通用速度控制命令接收能力，辅车在这个前提下执行随动。因此，上一版把偏航相关参数写成“当前主线未启用”的口径必须撤销，并改成当前主线必需接入项。只有这样，后续的实现、测试、板端现象和留证口径才不会继续把“能动”误判成“能稳定运行”。
