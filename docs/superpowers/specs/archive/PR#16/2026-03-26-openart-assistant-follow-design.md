# OpenArt 辅车跟随最小闭环设计

## 1. 背景

当前仓库已经长出了 `src/master` 与 `src/assistant` 两套最小运行时骨架, 但该骨架对应的目标是“先完成运行时拆分与最小协议打通”。

这与当前真正需要落地的目标并不一致。

当前阶段的真实目标不是完赛全链路, 也不是完整恢复旧系统的全部任务语义, 而是先打通一个最小但真实可验证的控制闭环:

- 主车通过 OpenArt 识别辅车上的目标
- OpenArt 直接输出“目标相对目标点的误差”
- 主车基于该误差高频遥控辅车
- 辅车持续闭环响应, 实现对主车视觉目标的稳定跟随

当前阶段的验收范围固定为:

- 跟随能力按单路 OpenArt 可工作作为最小通过条件
- 系统结构必须同时保留双路 OpenArt 接入能力, 不允许写成只能单路扩展的死结构

因此, 当前设计的第一优先级不再是“继续最小化运行时外壳”, 而是把对跟随闭环真正关键的控制能力保留下来, 并把非关键外围压缩到最小。

本 spec 是当前阶段的专项闭环设计, 用于收敛“OpenArt 引导的辅车跟随”主线, 不替代长期总方向文档。

## 2. 当前目标

本阶段只解决以下问题:

1. 主车接收 OpenArt 输出的目标误差
2. 主车将误差转换为高频位置式控制量
3. 辅车持续闭环执行该控制量
4. 在不依赖复杂状态机的前提下, 实现视觉引导的稳定跟随

补充边界:

- 当前最小闭环按单路视觉验收
- 当前实现结构按双路视觉接入保留

本阶段不要求:

- 恢复完整完赛状态机
- 恢复双车全任务协同语义
- 恢复所有旧查询面与兼容层
- 依赖视觉直接估计角度

## 3. 设计原则

本设计以以下事实为前提:

### 3.1 角度闭环可靠

经实测, 角度控制链在以下条件下可稳定工作:

- 合理的零漂校准
- 合适的滤波
- 四元数积分
- 动态计算控制周期

因此, 角度控制不依赖视觉角度观测, 也不依赖 AprilTag 角度求解。

### 3.2 `xy` 积分不可靠, 但 `xy` 位置式控制仍然必要

经实测, `xy` 位置积分存在以下问题:

- 编码器仅 8 线, 单圈脉冲数过低
- 福来轮结构不工整, 容易打滑
- 轮径存在测量误差

因此, `xy` 位置积分不能当作高精度位置真值, 但仍可作为位置式控制链中的内部控制量, 用于多次小步修正误差。

这里必须明确:

- `xy` 位置环的意义是“位置式控制阶数对齐”, 不是“高精度定位”
- 不应因此把 `xy` 控制退化为速度式控制

### 3.3 视觉闭环与状态机分离

视觉闭环需要高频运行, 状态机天然更偏低频、阶段式和带锁语义。

因此:

- 当前跟随主线不能被状态机卡住
- 状态机不进入当前高频跟随主闭环
- 后续若需要状态机, 只作为更高层的阶段组织与异常收敛框架

## 4. 系统边界

### 4.1 主车 `master`

当前阶段主车只承担以下职责:

- 通过两条独立视觉链路 `UART6` 与 `UART8` 主动接收 OpenArt 持续回传的目标误差
- 维护高频视觉闭环
- 将误差映射为辅车位置式控制量
- 通过 `UART3` 高频发送给辅车

在当前阶段范围内:

- 允许先以单路 OpenArt 完成最小闭环
- 但接收层、协议层和控制入口必须保留双路接入位置

当前阶段主车不承担以下职责:

- 完整任务状态机
- 完整完赛策略调度
- 复杂双相机仲裁策略
- 视觉角度求解

### 4.2 辅车 `assistant`

当前阶段辅车只承担以下职责:

- 接收主车发送的高频位置式控制量, 至少包含 `xy` 与角度两个维度
- 在本地持续运行底层闭环
- 输出最小执行状态
- 提供停机与安全保护

当前阶段辅车不是“离散动作任务执行器”, 而是“持续闭环响应的被控底盘”。

### 4.3 OpenArt

当前阶段 OpenArt 承担以下职责:

- 识别辅车目标
- 在 OpenArt 侧计算目标点与当前观测之间的误差
- 通过 `UART6` / `UART8` 持续回传误差结果给主车

当前阶段范围说明:

- 最小验收时可只接入一路 OpenArt
- 最终结构上仍按双路 OpenArt 定义链路与接口

主车接收的核心输入不是原始图像点, 而是已经整理过的目标误差量。

这里还需要明确一条协议边界:

- 当前阶段移除之前视觉链路中的轮询式协议
- 不再以 `?frame=...` 这类轮询查询作为当前跟随主线前提
- 改为沿用 `main` 分支方向, 由 OpenArt 持续回传视觉结果
- 当前视觉链路采用主动接收式, 由主车分别消费 `UART6` 与 `UART8` 上的持续数据流
- `UART6` 与 `UART8` 是两条独立视觉链路, 对应最终方案中的两个正交 OpenArt
- `UART3` 当前专用于主车到辅车的遥控通信, 不再预留独立调试串口语义

## 5. 必须完整保留的控制能力

### 5.1 速度环

速度环必须保留以下能力:

- `legacy` 中仅用于前馈的现有参数辨识链路
- 参数辨识结果仅用于前馈控制
- 原有 `PID` 参数语义、控制算法与手动调参方式

速度环明确不做的事情:

- 不新增 `PID` 参数辨识
- 不把 `PID` 调参逻辑替换成新的自动辨识逻辑

### 5.2 角度控制链

角度控制链必须保留以下能力:

- 零漂校准
- 滤波
- 四元数积分
- 动态控制周期计算
- 基于该姿态估计的连续角度控制

角度控制链在当前目标下按“两串”处理:

- 角度估计
- 角度控制

这里必须明确:

- 角度主控制量同样坚持位置式 / 角度误差式表达
- 不以角速度式控制量作为主链路语义

当前不要求:

- 视觉角度误差参与主闭环
- AprilTag 角度方案进入当前主线

### 5.3 `xy` 位置式控制链

`xy` 控制必须保持位置式控制思路, 原因如下:

- OpenArt 输出的是目标点误差
- 该误差天然适合落在位置式控制量上
- 位置式链路更容易与视觉误差阶数对齐
- 即使积分不准, 也可通过多次小步修正逐步收敛

这里的关键约束是:

- `xy` 位置环的内部积分量仅作为控制量, 不作为高精度定位依据
- 不允许因为积分不准而把主链路改成速度式闭环

### 5.4 视觉误差到控制量的映射

当前阶段视觉误差到控制量的映射直接采用 P 环。

也就是说:

- OpenArt 输出目标相对目标点的误差
- 主车按误差直接做 P 环映射
- P 环输出作为发给辅车的位置式控制量

当前阶段不额外引入更复杂的视觉控制器层级。

为避免实现时再次出现符号歧义, 当前专项方案固定如下:

- `err_x > 0` 表示应朝车体系 `x+` 方向修正
- `err_y > 0` 表示应朝车体系 `y+` 方向修正
- 角度链不依赖视觉误差, 当前 `d_angle` 默认由主车角度链给出, 无额外视觉角度输入时可为 `0`

## 6. 主辅通信语义

当前阶段主车到辅车传递的不是“必须逐条完成的离散位移任务”, 而是:

- 高频更新的位置式控制量, 至少包含 `xy` 与角度两个维度

当前阶段主车到辅车高频控制报文固定收敛为如下格式:

```text
follow=1,seq=<seq>,valid=<0|1>,dx=<dx>,dy=<dy>,d_angle=<da>
```

其中:

- `seq` 用于去重和丢弃倒退旧包
- `valid=1` 表示当前拍存在有效跟随目标, `valid=0` 表示当前拍无有效目标
- `dx` / `dy` 单位固定为米, `d_angle` 单位固定为度
- `dx/dy/d_angle` 都按车体系位置式控制量解释
- 该报文语义是“持续闭环输入”, 不是“离散动作任务”
- 主车在高频链路上持续刷新该报文, 不等待上一条“执行完成”
- 辅车若检测到 `seq` 倒退或重复, 应丢弃旧包
- 辅车若在控制超时窗口内未收到新包, 应进入保持或安全停车策略
- 当 `valid=0` 时, 主车不再输出伪造误差, 而是显式通知辅车进入当前约定的无目标策略

当前专项方案将无目标策略固定为:

- 主车发送 `follow=1,seq=<seq>,valid=0,dx=0.000,dy=0.000,d_angle=0.000`
- 辅车进入保持策略, 若持续超时则进入安全停车

辅车对该量的处理语义是:

- 持续闭环响应
- 不把每条消息当作一条独立任务
- 不依赖“执行完成再处理下一条”的加锁语义作为最终形态

这意味着当前协议设计必须服从以下约束:

- 协议应服务高频更新
- 协议语义应服务闭环控制, 而不是动作队列
- 若阶段性联调需要低频保护措施, 也只能作为临时手段, 不能成为最终设计前提
- 视觉输入链路应服务持续回传, 不应重新引入轮询式节拍依赖

## 7. 状态机定位

当前阶段状态机不进入主闭环, 但需要保留一个可继续扩展的框架位置。

原因如下:

- 当前目标只是跟随最小闭环
- 你计划后续重设计状态机
- 当前先把高频视觉闭环和底层控制链打通更重要

因此, 当前阶段对状态机的要求仅为:

- 不阻塞高频视觉闭环
- 不阻塞主辅高频控制链
- 结构上允许后续重新接入

## 8. 对现有 `master` / `assistant` 的判断

现有最小运行时骨架可以保留的内容包括:

- 目录拆分方式
- 启动入口与应用壳结构
- 最小安全保护壳
- 最小串口与协议组织思路

但以下内容不能视为当前目标的完成态:

- 将辅车视为离散命令执行器
- 只保留极薄的主车运动输出壳
- 将跟随逻辑简化为低频字符串命令拼装
- 让状态机替代高频视觉闭环

换句话说, 当前骨架可作为宿主, 但当前控制主链必须重建到新的目标口径上。

## 9. 第一版实现范围

第一版只实现当前最小闭环所必需的内容:

- OpenArt 侧目标误差计算
- 主车误差接收与高频发送
- 辅车位置式控制量接收
- 保留并接入现有角度估计 + 角度控制两串
- 辅车底层连续闭环
- 最小状态回传与安全保护

第一版视觉范围固定为:

- 验收以单路 OpenArt 跟随闭环打通为通过条件
- 代码结构必须预留 `UART6` / `UART8` 双路接入
- 双路预留只允许停留在接口与装配边界层, 不得提前长出双份常驻解析链、双份缓存、双份 owner 或双路融合负担, 除非该部分已经直接进入当前验收链路

第一版默认频率与超时预算固定为:

- 每路 OpenArt 持续回传目标 `>= 20 Hz`
- 主车到辅车 `follow=1,...` 控制链目标 `>= 50 Hz`
- 辅车状态回传目标 `10 Hz`
- 辅车控制超时窗口默认 `150 ms`

第一版不实现:

- 完整状态机
- 完整完赛策略
- 视觉角度链
- 非当前目标必需的外围协议和诊断能力

## 10. 验收方式

当前阶段的最终验收采用人工验收。

本 spec 不预先写死数值化阈值, 但验收结论必须只围绕一个问题:

- 当前方案能否实现“一个 OpenArt 识别辅车上的目标, 主车遥控辅车跟随主车”的最小闭环

## 11. 设计决策 Q&A

### 为什么当前跟随主线坚持位置式控制, 不改成速度式控制？

因为当前视觉侧输出的是目标点误差, 该误差天然更适合作为位置式控制量进入主链路。

这里的关键不是 `xy` 积分非常准确, 而是:

- 位置式控制更容易和视觉误差阶数对齐
- 即使 `xy` 内部积分不准, 也可以通过多次小步修正逐步收敛
- 若直接退化为速度式主链路, 会破坏当前已经确认的控制语义

### 视觉误差当前如何映射到控制量？

当前阶段直接使用 P 环。

原因是当前目标是先快速建立最小真实闭环, 而不是在视觉侧再叠加额外复杂控制层。

因此当前主线约定为:

- OpenArt 给出误差
- 主车直接对误差做 P 环
- P 环输出进入辅车位置式控制链

其中误差符号直接与车体系控制方向对齐:

- `err_x > 0 -> dx > 0`
- `err_y > 0 -> dy > 0`

### 为什么当前角度控制不依赖视觉角度？

因为此前尝试过视觉角度方案, 例如 AprilTag, 但帧率不足, 不适合当前主线。

另一方面, 经实测只要满足以下条件, 角度链本身已经足够稳定:

- 零漂校准
- 合适滤波
- 四元数积分
- 动态控制周期计算

因此当前角度主链路应保持:

- 不依赖视觉角度
- 不把视觉角度方案放进主闭环
- 继续按位置式 / 角度误差式表达角度控制量

### 为什么当前状态机不进入主闭环？

因为当前目标是先打通高频视觉跟随闭环, 而状态机天然更偏低频、阶段式和带锁语义。

如果让状态机直接进入当前主线, 会更容易把阶段锁和离散任务语义带回高频控制链, 反而削弱当前最关键的跟随能力。

因此当前阶段的正确分工是:

- 视觉闭环负责高频误差修正
- 状态机只保留后续重设计所需的框架位置

### 为什么当前视觉链路要移除轮询式协议？

因为当前主线要服务高频误差闭环, 视觉输入链路必须尽量平滑、持续和低阻塞。

此前轮询式协议更适合多相机选择、显式取帧和阶段式视觉消费场景, 但不适合作为当前最小跟随闭环的默认入口。

因此当前阶段应改为:

- OpenArt 通过 `UART6` / `UART8` 持续回传视觉结果
- 主车主动接收并持续消费该数据流
- 不把“主车主动查询一帧”当作当前主线前提

### 为什么当前串口边界改成 `UART6` / `UART8` 做视觉, `UART3` 做遥控？

因为当前方案已经不再走单串口轮询式视觉链路, 而是转向持续回传式视觉输入。

在这个前提下, 串口边界应直接服务当前最小跟随闭环:

- `UART6` / `UART8` 用于接收视觉持续回传
- `UART3` 用于主车到辅车的遥控通信
- 当前不再单独保留调试串口语义
- `UART6` 与 `UART8` 分别承接两个正交 OpenArt 的独立输入, 不再混成单串口轮询语义

这样可以减少旧方案残留边界对当前实现的干扰, 让视觉输入链与遥控链职责更直接。

### 为什么当前验收按单路, 但结构仍要保留双路？

因为当前目标是先打通“跟随”这条最小真实闭环, 单路 OpenArt 已经足够完成这一阶段验收。

但最终方案仍然明确依赖两个正交 OpenArt, 所以当前实现不能为了先跑通单路, 把接口、接收层和控制入口写死成只能单路工作的结构。

因此当前阶段的固定口径是:

- 验收按单路
- 结构保留双路

## 12. 需要沉淀的项目经验

以下经验不是临时聊天结论, 后续必须进入项目长期知识资产:

- 角度链可靠, 前提是零漂校准 + 合适滤波 + 四元数积分 + 动态控制周期
- 视觉角度方案当前不进入主线
- `xy` 编码器积分不可靠, 但 `xy` 位置式控制仍然必要
- 视觉闭环与状态机必须分离
- 速度环保留前馈参数辨识, 不辨识 `PID`
- OpenArt 优先在视觉侧直接输出目标误差, 而不是把原始图像量完全推给主控侧解释
- 当前跟随主线视觉协议改为持续回传, 不沿用轮询式取帧协议
- 当前串口边界改为 `UART6` / `UART8` 负责视觉输入, `UART3` 负责遥控通信
- 两个正交 OpenArt 分别走独立视觉链路, 不再按单串口轮询方案组织输入
- 当前视觉误差到控制量直接采用 P 环映射

这些内容后续需要同步沉淀到:

- 相关 memory
- 开发文档 / Q&A
- 相关 skill 参考页

## 13. 实现前仍需确认的信息

当前 spec 的控制边界已经比较清楚, 但在真正进入实现前, 仍有几项信息需要在板端联调中继续确认:

- 辅车状态回传字段在实际板端调试时是否需要再增减
- 当前频率预算在真实设备上是否能稳定达成

它们不再阻塞实现方向, 但进入板端联调前需要做一次留证确认。

## 14. 结论

当前阶段的正确方向不是“继续扩张最小运行时外壳”, 而是:

- 以现有 `master` / `assistant` 骨架为宿主
- 把控制主线重建为“OpenArt 误差 -> 主车高频位置式控制 -> 辅车连续闭环响应”
- 保留真正可靠且被实测证明有效的控制能力
- 将状态机暂时降到框架层, 避免阻塞当前最小跟随闭环落地

这份 spec 的核心目的, 是把项目主线从“运行时最小化优先”重新对齐为“跟随闭环成立优先”。
