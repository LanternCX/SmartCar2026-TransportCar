# 短包协议运行时架构重构 Spec

执行状态：Archive  
创建日期：2026-04-29  
关联协议：`docs/developer/protocol.md`  
前置提交：`a6bca53 refactor(protocol): migrate runtime to short packet protocol`

## 1. 目标

运行时串口入口采用短包协议原生架构。`UART3`、`UART8`、`UART6` 的输入按 `v/s/a/o/r` 包类型分发，协议解析结果以结构化对象进入角色层和底盘控制层。

本次目标：

1. 运行时串口入口只接受 `docs/developer/protocol.md` 定义的短包。
2. 删除等号命令解析、字段注册路由和字段集合驱动的运行路径。
3. 底盘控制层提供结构化控制入口，不接收串口命令文本。
4. 主车和辅车角色层不生成等号命令文本，也不把短包改写成命令字符串。
5. `vx/vy/omega` 只作为协议字段说明和控制物理量名称使用，不作为串口命令 key、路由 key 或模式切换 key。
6. 测试只验证短包协议行为、结构化控制入口和必要的控制语义。
7. 协议迁移不改变底盘行为；除输入格式从等号命令变为短包外，同一速度、位置、角度、复位和安全停止意图应产生同等控制状态。
8. 本次采用完整替换策略，运行主线中不保留等号命令架构、兼容入口、空壳转接或字段集合驱动路径。

## 2. 架构原则

### 2.1 串口协议边界

串口输入的一行文本先进入短包解析器。解析结果只有两种去向：

- 合法短包：交给对应包类型处理器。
- 非法或未定义输入：丢弃或记录最小错误信息。

串口入口不提供等号命令解析能力。正式运行链路不接受 `key=value` 输入。

### 2.2 控制入口边界

底盘控制层接收结构化控制意图，不接收协议文本。控制入口按职责表达：

- 速度目标入口：接收车体系平移速度和可选角速度。
- 状态目标入口：由状态同步上下文驱动。
- 控制清理入口：用于状态切换时清理目标、复位局部控制状态或进入安全停止。

控制入口不关心串口来源、分帧格式或包类型字符。

### 2.3 状态与控制意图边界

串口正式协议只扩展 `docs/developer/protocol.md` 已定义的 `v/s/a/o/r` 短包。位置、角度、复位和安全停止等底盘控制意图通过底盘内部结构化控制入口表达，不新增串口字段、等号字段或别名包类型。

`s/a` 包只表达同步上下文和确认结果。完整比赛状态机动作不在本次重构中通过串口协议展开。

底盘内部控制行为需要保持一致：同一控制意图进入结构化入口后，应得到与当前可用测试电路一致的速度目标、位置目标、角度目标、复位结果和安全停止结果。

### 2.4 物理量命名边界

`vx/vy/omega` 可以出现在以下位置：

- `docs/developer/protocol.md` 中 `v,<vx>,<vy>[,<omega>]` 的字段定义。
- 短包解析结果中的字段名。
- 运动学、控制计算和测试断言中的物理量名称。

`vx/vy/omega` 不应出现在以下位置：

- 串口命令文本。
- 命令路由注册 key。
- 模式切换字段集合。
- 运行时用于模拟协议输入的等号字符串。

## 3. 范围

### 3.1 做

- 完整替换运行时协议入口，不保留等号命令架构、兼容入口或空壳转接。
- 删除 `src/command/router.py` 的运行时使用路径。
- 删除 `src/command/commands/` 中面向等号命令注册的处理器。
- 删除或改写 `src/command/policy.py` 中依赖字段集合的模式切换接口。
- 在 `core.runtime.TransportCar` 中建立结构化控制入口。
- 修改 `TransportCar._handle_uart_line()`，只处理短包解析结果。
- 修改主车角色层，使 `UART3` 输入、`UART8` 转发和 `UART8` 回传处理都通过短包分发完成。
- 修改辅车角色层，使 `UART8/UART6` 输入和 `UART8` ACK 回写都通过短包分发完成。
- 保留短包解析模块，但让它只负责解析和格式化，不承担业务状态。
- 改写测试，使正常路径不再构造 `key=value` 串口输入。
- 保留必要的拒绝用例，证明 `key=value` 不属于正式协议。
- 全量清理正式文档、代码注释和测试说明中的等号协议运行口径。

### 3.2 不做

- 不改变硬件串口号、引脚、电平或接线事实。
- 不改运动学公式、PID 参数和底盘方向定义。
- 不实现完整比赛状态机。
- 不实现 `o` 包业务消费。
- 不做板端实机联调；本次先完成主机侧行为测试。
- 不新增兼容入口、别名入口或自动降级路径。
- 不新增位置、角度、复位或安全停止的串口字段。
- 文档和注释迁移不写行为测试，只做规则检查和 Review。

## 4. 测试场景基线

本次重构以当前主辅跟随测试环境作为核心行为基线。

测试环境：

- 主车作为前车，通过 `UART3` 接收电脑发送的遥控速度。
- 主车本地执行遥控速度，同时通过 `UART8` 向辅车发送速度前馈。
- 辅车作为后车，通过视觉识别主车色标。
- 辅车把 `UART8` 速度前馈与 `UART6` 视觉速度修正融合，形成最终底盘速度。
- 主车和辅车底盘控制行为与当前可用测试电路保持一致。

验收关注点：

- 协议入口格式改变后，主车遥控行为保持一致。
- 主车到辅车的速度前馈行为保持一致。
- 辅车视觉闭环修正行为保持一致。
- 前馈加视觉融合后的跟随效果保持一致。
- 测试结论以整车行为和最终跟随效果为准，不能只以解析函数或局部调用通过作为完成依据。

## 5. 目标结构

### 5.1 协议解析层

`src/vision/serial_protocol.py` 保持纯解析职责：

- 解析 `v/s/a/o/r`。
- 格式化 `v/s/a/r`。
- 判断环形 `seq` 新旧关系。
- 不读取串口。
- 不调用底盘控制。
- 不持有运行时状态。

### 5.2 角色运行时层

主车角色层职责：

- 从 `UART3` 读取上游短包。
- 对 `v` 包调用底盘结构化速度入口。
- 通过 `UART8` 转发 `v` 包。
- 在 `step()` 周期发送待确认 `s` 包。
- 通过 `UART8` 接收 `a` 包完成确认。
- 通过 `UART8` 接收 `r` 包并记录最近事件。

辅车角色层职责：

- 从 `UART8` 接收主车速度前馈和状态同步。
- 从 `UART6` 接收视觉速度修正。
- 对两路 `v` 包按当前融合规则生成结构化速度目标。
- 对 `UART8` 的 `s` 包记录同步上下文并回复 `a`。
- 不让 `UART6` 处理状态同步。

### 5.3 底盘控制层

`TransportCar` 对角色层提供结构化入口：

- 接收速度目标。
- 接收控制目标清理或复位请求。
- 查询当前控制状态供诊断快照使用。

底盘控制层内部可以继续使用适合控制算法的字段和变量，但不把这些字段暴露成串口协议或命令路由协议。

## 6. 数据流

### 6.1 主车速度链路

```text
UART3 line -> parse_short_packet -> v packet -> TransportCar speed target
                                      -> UART8 v packet
```

链路中不出现等号命令文本。

### 6.2 辅车速度链路

```text
UART8 line -> parse_short_packet -> v packet -> feedforward source
UART6 line -> parse_short_packet -> v packet -> vision source
feedforward source + vision source -> TransportCar speed target
```

`UART8` 可以提供角速度。`UART6` 只贡献平移速度。

### 6.3 状态同步链路

```text
Master state sync request -> UART8 s packet
Assistant UART8 line -> parse_short_packet -> s packet -> sync context -> UART8 a packet
Master UART8 line -> parse_short_packet -> a packet -> clear pending sync
```

重复 `s` 包只重复确认，不重复应用。较早同步编号不回退本地上下文。

## 8. 测试策略

### 8.1 行为等价测试原则

本次重构必须用行为测试证明底盘行为保持稳定。测试关注输入意图和控制结果，不关注旧命令路由的实现细节。

应覆盖的行为：

- 速度目标：`v` 包进入后，底盘当前速度目标、角速度目标和目标轮速计算语义保持一致。
- 结构化控制入口：位置、角度、复位和安全停止由内部控制意图进入底盘，不通过串口字段进入底盘。
- 速度限幅：短包速度值进入后，沿用当前限幅边界。
- 平移速度与角度目标共存：平移速度更新不清除当前角度目标。
- 角速度更新：显式角速度更新清除当前角度目标。
- 位置目标切换：状态同步或结构化控制意图进入位置目标时，平移速度目标按当前控制规则退出。
- 复位与安全停止：复位、停止和电机清零行为保持可观测结果一致。
- 主辅速度融合：`UART8` 前馈与 `UART6` 视觉修正的融合规则保持一致。

测试命名应表达业务行为，不表达旧字段路由过程。等号文本只能作为拒绝用例出现。

### 8.2 RED 测试

先写或改写失败测试，覆盖核心测试场景基线和模块边界。每个行为改动都要先看到失败，再进入实现。

覆盖范围：

- 主车接收电脑遥控速度短包后，本地底盘速度目标与当前行为一致。
- 主车接收电脑遥控速度短包后，`UART8` 速度前馈与当前前馈语义一致。
- 辅车接收 `UART8` 前馈和 `UART6` 视觉修正后，融合结果与当前行为一致。
- 视觉修正只贡献平移速度，角速度来源仍按链路职责处理。
- 输入缺包时保持当前最新值语义，不把缺包解释成零量。
- 显式零速度包能清理对应速度来源。

模块边界覆盖：

- `TransportCar._handle_uart_line()` 对 `key=value` 输入无正式行为。
- 角色层速度链路不生成等号命令文本。
- 主车 `UART3` 输入 `v` 包后直接调用结构化速度入口。
- 辅车 `UART8/UART6` 输入 `v` 包后直接调用结构化速度入口。
- 状态同步、ACK、事件记录仍按短包工作。
- 命令路由相关模块不再作为运行时依赖。

### 8.3 GREEN 实现

实现必须围绕已失败的行为测试推进。每完成一个行为点，先让对应测试变绿，再进入下一项。

按边界逐步替换：

1. 建立底盘结构化控制入口。
2. 让主车角色层只依赖短包和结构化入口。
3. 让辅车角色层只依赖短包和结构化入口。
4. 移除等号命令路由模块和对应测试。
5. 收紧契约测试，防止等号输入重新进入正式路径。

### 8.4 SDD Review 要求

本次实现按 Subagent-Driven Development 执行时，每个任务必须包含两类 Review：

1. 行为 Review：检查主辅跟随测试场景的行为是否保持一致，重点看遥控输入、速度前馈、视觉修正、速度融合和最终底盘目标。
2. 架构 Review：检查运行时入口是否真正采用短包分发和结构化控制入口，不能把短包转换成等号命令文本，也不能保留命令路由作为运行时主线。

Subagent 的审查提示必须明确：测试结论以整车跟随链路和底盘行为为准，局部协议解析通过不能单独作为完成依据。

### 8.5 文档与注释 Review

文档、注释和测试说明文本不使用 TDD，不为文档和注释改动新增测试。迁移完成后由 subagent 做专项 Review：

- 检查正式文档是否只描述 `v/s/a/o/r` 短包协议。
- 检查代码注释是否没有把等号文本描述成正式串口入口。
- 检查测试说明是否没有把等号命令描述成正常运行路径。
- 检查文档和注释是否只描述当前事实。

### 8.6 验证命令

主机侧最小验证：

```text
python3 -m pytest tests/unit tests/contract -q
```

本次不要求板端验证。若后续进入板端路径，需要另行记录上传、导入、最小诊断和现场观测结果。

## 9. 验收标准

- 串口运行入口只接受 `v/s/a/o/r` 短包。
- 正常路径中没有 `key=value` 串口输入、输出或内部适配文本。
- 主车和辅车速度链路都通过结构化速度目标进入底盘。
- 主车 `UART8` 状态同步和事件记录保持可用。
- 辅车 `UART8` 状态同步、ACK、重复确认和同步编号判断保持可用。
- `UART6` 只贡献视觉平移速度。
- 命令注册路由不再参与运行时主线。
- 测试不把等号命令作为正常行为固定下来。
- `vx/vy/omega` 只作为物理量和协议位置字段存在。
- 本地单元测试和协议契约测试通过。
- 行为测试证明底盘速度、位置、角度、复位、安全停止和主辅融合语义没有因协议入口重构而改变。
- 主车电脑遥控、`UART8` 速度前馈、辅车色标视觉跟随和前馈加视觉融合链路保持当前测试电路的可用行为。
- Subagent Review 明确检查行为等价和短包原生架构两条线。
- 文档、注释和测试说明文本不把等号协议描述成正式运行口径。
