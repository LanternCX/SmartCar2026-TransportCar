## 1. 目标

把当前运行时代码全量迁移到 `docs/developer/protocol.md` 定义的串口协议。正式运行链路只保留短包协议，不保留键值速度字段、车端通用查询或其他历史协议入口。

本次目标：

1. 让 `UART3`、`UART8`、`UART6` 的速度链路使用 `v,<vx>,<vy>[,<omega>]`。
2. 让 `UART8` 作为主辅双向链路承载速度前馈、状态同步、确认和事件回报。
3. 让辅车识别 `s,<seq>,<state>,<target>,<arg>` 并回复 `a,<seq>`。
4. 让辅车按幂等规则处理重复同步包，并忽略旧同步包。
5. 让主车提供最小状态同步发送能力，能重复发送待确认同步包，并在收到 ACK 后停止发送。
6. 让主车记录 `r,<seq>,<event>,<value>`，但不在本次实现完整业务状态机。
7. 删除键值速度字段、车端通用查询和查询响应格式化等历史协议实现。

## 2. 当前代码现状

当前代码仍保留历史协议路径：

- 主车从 `UART3` 接收 `vx=...`、`vy=...`、`omega=...` 等键值速度字段。
- 主车把键值速度字段或 `angle=...` 转发到 `UART8`。
- 辅车从 `UART8` 和 `UART6` 消费键值速度字段。
- 运行时代码仍保留 `?health/?pos/?imu/?enc/?motor/?tick/?lock` 等车端通用查询路径。
- 当前没有完整实现 `v/s/a/o/r` 短包解析、状态同步 ACK、同步幂等和事件回报记录。

这些历史协议路径不作为正式可用路径保留。

## 3. 范围

### 3.1 做

- 新增轻量串口短包解析能力，覆盖 `v/s/a/o/r`。
- 将速度输入和速度转发全量迁移到 `v` 短包。
- 删除键值速度字段作为正式运行入口。
- 协议层不得把 `v` 短包转换成旧键值命令字符串来复用历史链路。
- 在辅车 `UART8` 接收侧处理 `s` 状态同步包。
- 辅车收到有效 `s` 包后通过 `UART8` 回写 `a` 确认包。
- 辅车对同一 `seq` 的重复 `s` 包只重复 ACK，不重复应用状态。
- 辅车对旧 `seq` 的 `s` 包不回退本地同步上下文。
- 主车运行时提供状态同步请求入口，并通过 `UART8` 发送待确认同步包。
- 主车通过 `UART8` 收到匹配 `a` 包后结束本次同步等待。
- 主车通过 `UART8` 收到 `r` 包后记录最近事件，交给后续状态机扩展使用。
- 删除车端通用状态查询入口、查询处理器和查询专用测试。
- 删除查询响应格式化工具中只服务通用查询的能力。

### 3.2 不做

- 不设计完整业务状态机。
- 不改变比赛路线、阶段策略或状态跳转规则。
- 不新增串口号、引脚或接线假设。
- 不实现完整 TCP 协议，只实现轻量同步、确认、重发和幂等。
- 不实现 `o` 包的具体业务消费；本次只建立解析和契约边界。
- 不把高频速度包扩展成冗长键值结构。
- 不做板端真实联调；本次先完成主机侧行为测试。

## 4. 删除范围

- 删除或改写通用查询相关测试，包括 `?health`、未知查询回复、query handler 注册、query response 格式等断言。
- 删除或改写键值速度字段相关测试，包括 `vx=...`、`vy=...`、`omega=...`、`angle=...`、`w=...` 作为串口速度协议入口的断言。

- 改写辅车融合测试，使其验证 `v` 短包输入，而不是键值速度字段输入。

- 不删除非查询命令处理器，除非它们只服务历史串口速度协议。
- 不删除共享底盘内部控制能力，但控制入口需要从短包解析结果直接接入，不能继续依赖旧键值命令字符串。

## 5. 设计

### 5.1 协议解析边界

新增一个纯解析模块，负责：

- 判断一行文本是否为 `v/s/a/o/r` 短包。
- 解析字段数量、数值类型和基础范围。
- 格式化 `v`、`s`、`a`、`r` 短包。

该模块不直接依赖硬件、不读取串口、不修改运行时状态。

### 5.2 `v` 速度短包

格式：

```text
v,<vx>,<vy>[,<omega>]
```

规则：

- `vx` 和 `vy` 必填。
- `omega` 可选。
- 数值必须是有限浮点数。
- 速度幅值沿用当前运行时代码的速度限幅规则。
- `UART3` 使用 `v` 包承载上位机给主车的速度控制。
- `UART8` 使用 `v` 包承载主车给辅车的速度前馈。
- `UART6` 使用 `v` 包承载辅车视觉给辅车的速度修正。
- `UART8` 的 `omega` 可以进入辅车最终旋转输入。
- `UART6` 即使收到 `omega`，也只贡献 `vx/vy`。
- 非 `v` 的键值速度文本不作为正式速度协议入口。
- `v` 短包解析后应以结构化速度值进入运行时，不得格式化成 `vx=...`、`vy=...`、`omega=...` 再交给旧命令路由。

### 5.3 `s/a` 状态同步短包

`s` 包格式：

```text
s,<seq>,<state>,<target>,<arg>
```

`a` 包格式：

```text
a,<seq>
```

辅车处理规则：

- 新 `seq`：更新本地同步上下文，回复 ACK。
- 相同 `seq`：只回复 ACK，不重复应用状态。
- 旧 `seq`：忽略，不回退上下文。

`seq` 按 `0` 到 `255` 环形编号处理。ACK 通过 `UART8` 回传给主车。

### 5.4 `r` 事件回报短包

格式：

```text
r,<seq>,<event>,<value>
```

主车处理规则：

- 通过 `UART8` 接收并记录最近一次事件回报。
- 不直接触发全局状态跳转。
- 后续状态机实现可读取该记录做决策。

### 5.5 `o` 观测包

格式：

```text
o,<seq>,<x>,<y>,<value>
```

本次只实现解析和契约测试，不接入具体业务消费。业务消费前必须先确认链路职责和字段含义。

### 5.6 主车状态同步发送

主车运行时新增最小同步入口：

- 调用同步请求入口后生成新 `seq`。
- 在同步完成前，`step()` 周期内通过 `UART8` 写出当前 `s` 包。
- 通过 `UART8` 收到匹配 `a,<seq>` 后清除待确认同步。
- 收到不匹配 ACK 时忽略。

本次先不实现复杂重发间隔和失败超时，只实现“重复发送直到 ACK”的基础行为。

## 6. 测试策略

- 纯解析测试覆盖 `v/s/a/o/r` 的合法和非法输入。
- 速度链路测试覆盖 `v` 短包从 `UART3`、`UART8`、`UART6` 进入运行时。
- 辅车同步测试覆盖新同步、重复同步和旧同步。
- 主车同步测试覆盖同步请求、重复发送、ACK 完成和事件记录。
- 协议契约测试确认短包格式作为正式运行时入口存在。
- 删除或改写通用查询相关测试，确保运行时代码不再维护 `?health/?pos/?imu/?enc/?motor/?tick/?lock` 等正式查询入口。
- 删除或改写键值速度字段相关测试，确保测试不继续锁定历史速度协议。

## 7. 验收标准

- `UART3`、`UART8`、`UART6` 的速度运行链路使用 `v` 短包。
- 键值速度字段不再作为正式串口速度入口保留。
- `s` 包能让辅车更新本地同步上下文并回复 ACK。
- 重复 `s` 包不重复应用状态。
- 旧 `s` 包不回退本地同步上下文。
- 主车能通过 `UART8` 发送 `s` 包，并在收到匹配 ACK 后停止发送。
- 主车能通过 `UART8` 记录 `r` 包。
- 通用查询处理器、查询路由和查询回复格式化能力已删除。
- 本地单元测试和协议契约测试通过。
- 没有任何历史协议实现继续作为正式可用路径保留。
- 没有新增硬件事实假设，没有恢复查询主线，没有引入旧协议兼容层。

## 8. Review 强约束

- 运行时代码必须全量迁移到 `docs/developer/protocol.md` 的短包协议。
- 不保留任何历史实现作为正式可用路径。
- 不用“兼容旧链路”“临时保留”“历史格式”解释旧代码残留。
- 如果旧实现只服务旧协议，应删除；如果某个工具函数仍有新协议用途，应改名或改写到新语义下。
- 测试只能验证新协议行为和必要的非协议底盘行为，不能继续固定旧协议入口。
- Review 必须检查实现中不存在 `v` 短包到旧键值命令字符串的适配层。
- 正式协议文档、代码和测试必须同口径。
