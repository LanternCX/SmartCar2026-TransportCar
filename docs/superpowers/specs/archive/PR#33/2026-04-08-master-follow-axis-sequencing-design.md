# 2026-04-08 主车跟随轴向分阶段状态机设计

> 状态: archive

## 背景

当前主车最小跟随主线里, 视觉状态机只有 `MARKER_MISSING / CENTER_HOLD / TRACKING` 三态。只要进入 `TRACKING`, 决策层就会同时计算并下发 `x` 与 `y` 两个方向的跟随量。

最近联调确认了一个更高优先级的现实约束: 车辆在 `x` 与 `y` 两个方向上的耦合较强, 同时下发双轴控制量会放大干扰, 不利于稳定对正。用户已经明确要求把当前主线改成分阶段控制:

1. 先对正 `x`
2. `x` 未进入允许范围前, `y` 必须归零
3. 只有 `x` 已进入当前允许范围后, 才允许处理 `y`
4. 如果处理 `y` 的过程中 `x` 再次偏出允许范围, 必须立刻回到先对正 `x`
5. 这个切换职责必须由主车状态机承担, 不能散落在决策层里

## 目标

1. 把“先对正 `x`, 再对正 `y`”收口为主车状态机的正式阶段规则。
2. 保持当前主车分层边界: 状态机负责阶段切换, 决策层负责根据阶段生成输出。
3. 在不改辅车协议与辅车内部控制语义的前提下, 让主车只在当前阶段下发单轴控制量。
4. 尽量复用现有最小主线框架, 不把这轮改动扩大成更重的长期状态机迁移。

## 非目标

1. 本轮不改辅车协议字段与辅车解析逻辑。
2. 本轮不改头对头方向换算规则。
3. 本轮不新增 `x` / `y` 死区参数, 继续沿用当前中心死区作为横向与纵向的进入判据。
4. 本轮不恢复 `ALIGN_ANGLE / ORBITING / PUSHING / RETURNING` 等更重的长期阶段。
5. 本轮不同时引入双阈值、延迟回退或防抖计数规则。

## 现状问题

当前链路的主要问题不是“主车不会停”, 而是“主车一旦进入跟随阶段, 就默认双轴一起发”。这会带来两个直接后果:

1. 当 `x` 还没有收住时, `y` 的推进会继续扰动横向对正。
2. 即使 `x` 已短暂进入允许范围, 只要随后又被 `y` 带偏, 当前三态状态机也没有“立刻退回只修 `x`”的正式阶段表达。

因此, 这轮真正要修的不是单个比例值, 而是当前最小主线的阶段表达能力不足。只要状态机仍然把这两件事合并成一个 `TRACKING`, 决策层就很难稳定地表达“先横向, 再纵向”的控制顺序。

## 设计决策

### 一、把 `TRACKING` 拆成 `ALIGN_X` 与 `ALIGN_Y`

主车视觉状态机从当前三态改成四态:

1. `MARKER_MISSING`
2. `CENTER_HOLD`
3. `ALIGN_X`
4. `ALIGN_Y`

其中:

1. `ALIGN_X` 表示当前优先收口横向误差, 纵向输出必须归零。
2. `ALIGN_Y` 表示横向已经进入允许范围, 当前允许继续收口纵向误差。

这样做的原因是: 用户已经明确要求“切换要由状态机管理”。既然切换本身是正式行为, 就不应继续藏在决策层的临时判断里。

### 二、横向完成判据继续沿用当前中心死区

本轮不新增横向专用阈值。

状态机继续沿用当前中心死区作为“`x` 是否已进入允许范围”的判据。这样做的原因是:

1. 用户已经明确要求沿用当前死区。
2. 这能把本轮改动收口在阶段逻辑, 不同时扩大到参数整定。
3. 若后续联调再确认当前死区不适合横向阶段切换, 可以在下一轮单独讨论横向专用阈值。

### 三、`ALIGN_Y` 期间一旦 `x` 再偏出死区, 立刻退回 `ALIGN_X`

本轮不引入连续几拍确认或防抖回退。

状态机在 `ALIGN_Y` 期间只要发现 `x` 再次偏出当前死区, 就立即回到 `ALIGN_X`。这样做的原因是:

1. 用户已经明确要求“立刻回到 `x`”。
2. 当前更重要的是先证明阶段职责正确, 而不是先引入额外平滑规则。
3. 若后续现场确认边界附近抖动明显, 再单独讨论是否需要滞回或拍数判据。

### 四、决策层只根据阶段输出单轴控制量

本轮继续保持现有分层:

1. 状态机决定当前阶段。
2. 决策层读取阶段并生成主车对辅车的跟随输出。

各阶段输出规则固定为:

1. `MARKER_MISSING`: 不驱动跟随
2. `CENTER_HOLD`: 不驱动跟随
3. `ALIGN_X`: 只输出 `x`, 强制 `y=0`
4. `ALIGN_Y`: 只输出 `y`, 强制 `x=0`

这样可以保持当前结构最小变化: 状态机不直接生成控制量, 决策层也不再自行决定“此时先发哪一轴”。

## 影响范围

本轮设计只影响主车最小跟随主线中的阶段表达和对应输出规则。

明确应受影响的部分:

1. `src/master/vision/state_machine.py` 中的阶段集合与切换逻辑。
2. `src/master/vision/decision.py` 中对不同阶段的单轴输出选择。
3. 主车侧相关单元测试。

明确不应受影响的内容:

1. 辅车协议格式与辅车解析行为。
2. 头对头方向换算。
3. 当前中心死区参数值。
4. 主车无目标、保持和基础状态回包链路。

## 验收标准

本轮完成后, 至少需要同时满足以下标准:

1. 当 `x` 偏差超出当前死区时, 主车只给辅车下发横向控制量, `y` 为 `0`。
2. 当 `x` 已进入当前死区、但 `y` 仍未进入时, 主车只给辅车下发纵向控制量, `x` 为 `0`。
3. 当处于 `ALIGN_Y` 时, 若 `x` 再次偏出当前死区, 状态机立即切回 `ALIGN_X`。
4. 当 `x` 与 `y` 都进入当前死区时, 主车进入 `CENTER_HOLD`。
5. 主车侧相关回归通过, 且不需要修改辅车代码来适配本轮变更。

## 验证建议

1. 主机侧先用单元测试固定状态切换与单轴输出行为。
2. 板端联调时优先观察:
   1. 横向未收住时是否仍会出现明显纵向推进
   2. 纵向推进过程中横向一旦漂出是否会立刻停止纵向并回到横向对正
   3. 两轴都收住后是否能稳定进入保持态
