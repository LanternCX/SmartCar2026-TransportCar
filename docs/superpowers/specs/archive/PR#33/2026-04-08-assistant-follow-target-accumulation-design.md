# 2026-04-08 辅车高频跟随目标累计设计

> 状态: archive

## 背景

当前辅车位置式跟随链在收到每一包有效跟随命令时, 会把本包 `dx/dy` 先按当前车体朝向转到世界坐标, 再直接用“当前位置 + 本包偏移”覆盖 `follow_target_world`。

这套做法有一个明显前提: 主车发来的每一包都被当成一次新的完整相对目标, 而不是连续高频控制流中的增量输入。用户当前已经明确指出, 现在控制频率较高, 不应再把这条链路理解成“上一段完成后再接下一段”的离散动作更新。用户希望保留高频连续控制语义, 取消这类离散覆盖感, 并让目标位置直接按新包持续累加。

在进一步对齐代码后, 当前辅车链路里真正相关的行为有两类:

1. 超时保护: 若长期收不到新包, 进入保护或停机路径。
2. `seq` 去重: 若包序号重复或倒退, 直接忽略旧包。

用户已经确认本轮边界如下:

1. 保留超时保护。
2. 保留 `seq` 前进检查, 不把重复包也拿来累计。
3. 第一个有效包仍从当前位置起算。
4. 后续有效包改为在上一次目标位置上继续累加。
5. 收到 `valid=0`、停机或超时时, 立刻清掉累计目标。

## 目标

1. 让辅车高频跟随链把连续输入解释为逐包累计的目标增量, 而不是每包覆盖一次完整目标。
2. 保持当前高频连续控制主语义, 不把控制链拉回离散任务式动作语义。
3. 不扩大到主车协议、主车发包格式或辅车本地位置闭环之外的其它路径。
4. 在不引入额外兼容层的前提下, 保留当前超时与旧包去重保护。

## 非目标

1. 本轮不改主车协议字段、主车发包频率或主车坐标语义。
2. 本轮不去掉 `seq` 前进检查。
3. 本轮不放宽超时边界, 也不取消超时停机语义。
4. 本轮不改辅车位置式本地闭环的解算方法。
5. 本轮不引入新的模式、额外锁语义或新的防抖策略。

## 现状问题

当前实现里, 每个有效包都会按当前里程重新覆盖 `follow_target_world`。这意味着:

1. 高频输入流里, 后一包不会承接前一包已经建立的目标积累关系。
2. 主车若持续下发小步长修正, 辅车看到的是一连串“从当前时刻重新定义一次目标”的覆盖动作, 而不是连续累计的增量意图。
3. 这会把高频控制流的真实语义削弱成一连串短离散目标, 不利于用户当前想要的连续推进手感。

因此, 本轮真正要修的不是保护机制本身, 而是有效包如何更新 `follow_target_world` 的语义。只要目标仍然按“当前里程 + 本包偏移”覆盖, 高频跟随链就仍然带着离散动作感。

## 设计决策

### 一、保留超时保护与 `seq` 去重

本轮不把“取消离散覆盖感”理解成“取消所有保护”。

保留这两条行为的原因是:

1. 超时保护仍然是高频控制链的安全边界, 与目标累计语义并不冲突。
2. 一旦改成逐包累计, 重复包的风险会更大, 因为它不再只是重复执行同一个目标, 而是会把同一段位移再累计一遍。
3. 因此, `seq` 前进检查应继续保留, 让高频链在连续控制的同时仍能屏蔽旧包与重复包。

### 二、第一个有效包从当前位置起算, 后续有效包在上一次目标上继续累计

目标位置更新改成以下规则:

1. 若当前还没有累计目标, 则把本包位移按当前朝向转到世界坐标后, 加到当前位置上, 作为首个 `follow_target_world`。
2. 若当前已经存在累计目标, 则把本包位移按当前朝向转到世界坐标后, 继续加到现有 `follow_target_world` 上。

这样做的原因是:

1. 这才符合用户要求的“目标位置直接累加”。
2. 这能让高频输入流表现为连续推进, 而不是每包重新定义一次独立目标。
3. 它仍然保留当前位置式本地闭环, 只是改变目标更新方式, 不改后续误差收敛方法。

### 三、累计仍然以当前包到来时的朝向解释本包增量

本轮不改“本包位移先按当前朝向转到世界坐标”这一层解释方式。

原因是:

1. 用户当前明确要求的是改目标累计语义, 不是同时重写位移坐标解释方式。
2. 若这一轮同时改累计基准和朝向解释时机, 将难以分辨最终手感变化来自哪一层。
3. 先只改“覆盖”与“累计”的语义边界, 更容易在联调中观察真实效果。

### 四、`valid=0`、停机与超时都要立刻清掉累计目标

本轮不保留跨停机、跨无效段的旧累计目标。

原因是:

1. 用户已经明确要求在这些条件下立刻清掉累计目标。
2. 一旦进入 `valid=0`、停机或超时, 继续保留旧累计目标容易让下一段控制继承陈旧意图。
3. 这类清理语义与当前安全边界一致, 能避免累计目标跨阶段泄漏。

## 影响范围

本轮设计只影响辅车位置式跟随链中 `follow_target_world` 的更新语义与相关回归。

明确应受影响的部分:

1. `src/assistant/motion_runtime.py` 中有效跟随包如何写入 `follow_target_world`。
2. 辅车单元测试中对累计目标、重复包处理和清理时机的行为预期。

明确不应受影响的内容:

1. 主车发包协议与主车状态机。
2. 辅车 `seq` 去重。
3. 辅车超时保护与停机语义。
4. 辅车位置误差到速度输出的本地闭环解算。

## 验收标准

本轮完成后, 至少需要同时满足以下标准:

1. 第一个有效跟随包会从当前位置建立累计目标。
2. 后续前进的新 `seq` 有效包会在现有目标上继续累计, 而不是覆盖成“当前位置 + 本包偏移”。
3. 重复包或倒退旧包不会被再次累计。
4. 收到 `valid=0`、停机或超时后, 累计目标会被立即清掉。
5. 辅车相关回归通过, 且主车协议与主车侧代码无需改动。

## 验证建议

1. 主机侧先用单元测试固定“首包建目标、后续包累计、重复包不累计、无效/停机/超时清理目标”的行为。
2. 板端联调时优先观察:
   1. 高频连续小步长输入下, 辅车是否表现出更连续的目标推进感
   2. 重复包或旧包是否仍会被拦掉, 避免额外位移被重复累计
   3. 一旦失去目标或触发停机, 旧累计目标是否会被正确清掉
