# 辅车控制模式一致性修复设计

## 背景

当前主辅控制链已经完成两项收口：

1. 主车到辅车的正式高频控制协议已经统一成短键值文本格式。
2. 辅车已经具备普通跟随模式与 `m=1` 速度模式两个协议入口。

但在最近联调与代码复核中，暴露出两个会直接影响实车效果的问题：

1. 速度模式只在收包当拍按速度目标执行，后续周期没有继续保持该速度目标。
2. 朝向保持虽然在单拍入口里存在，但“哪些模式必须持续启用朝向保持”的规则没有被收口成单一明确语义。

这两个问题会导致现场出现明显的控制落差：

1. 第一拍看起来有响应，后续拍又退回错误路径。
2. 三轮全向底盘在非理想机械条件下失去持续朝向修正后，平移会迅速漂移，导致“命令方向正确但实车跑不稳”。

当前阶段的目标不是继续扩大协议功能面，也不是同时重做单位标定，而是先把“控制模式的持续性与一致性”修好，让链路行为重新符合联调预期。

## 目标

本轮设计只追求以下目标：

1. 让普通跟随模式在收包后和后续周期中保持一致行为。
2. 让 `m=1` 速度模式在收包后和后续周期中保持一致行为。
3. 明确并固化“只要不是显式角速度控制，就持续启用朝向保持”的规则。
4. 保持当前统一短协议风格，不重新引入旧协议或新增第二套协议风格。
5. 用最小改动修复当前控制链行为，不在本轮混入单位重标定、运动学重写或主车视觉比例重整。

## 非目标

本轮明确不做以下事情：

1. 不在本轮修正普通模式 `x/y` 的物理单位标定。
2. 不在本轮修改主车视觉误差到控制量的比例来源。
3. 不在本轮重做三轮底盘运动学模型。
4. 不在本轮新增新的协议家族或新的调试串口链路。
5. 不把主车控制节拍、视觉链路节拍或串口硬件问题混入本轮修复范围。

## 现状问题归纳

### 问题一：速度模式缺少跨周期持续性

当前 `m=1` 速度模式在收包当拍会进入直接速度控制入口，但后续周期仍沿用普通 `follow_active` 的公共 tick 路径。该公共路径默认按“已有位置目标”继续解算平移量，而速度模式本身并没有位置目标，因此后续周期会丢失原本应持续保持的速度目标。

这意味着：

1. 速度模式不是“持续速度模式”，而是“单拍速度命令”。
2. 只要没有更高频持续重发，同一条速度指令在后续周期会迅速退化。

### 问题二：朝向保持规则没有在模式层显式收口

从当前代码片段来看，普通跟随模式与速度模式在入口拍都会调用朝向修正，但没有把“哪些模式必须持续带朝向保持”收口成单一模式规则。

这会导致：

1. 入口拍与后续拍可能行为不一致。
2. 后续维护时容易误以为某个模式不需要持续打角度环。
3. 现场联调时很难快速判断“是模式问题还是角度环问题”。

## 设计原则

### 原则一：模式持续性必须优先于入口即时性

实车控制链不能只在“收包当拍”表现正确，必须在后续周期继续维持当前模式的核心控制目标。也就是说：

1. 普通跟随模式要持续维护位置目标。
2. 速度模式要持续维护速度目标。

### 原则二：朝向保持是全向底盘基础能力，不是附加优化

对于当前三轮全向底盘，朝向稳定不是锦上添花，而是基本可用性的前提。因此本轮将朝向保持提升为模式公共规则：

1. 普通跟随模式默认持续启用朝向保持。
2. 速度模式默认持续启用朝向保持。
3. 空闲保持阶段继续启用朝向保持。
4. 只有显式角速度控制时，才由手动角速度接管转向输出。

### 原则三：模式语义要单一，不靠隐式状态猜测

后续周期不能仅通过 `follow_active` 这种宽泛状态去推断当前应走哪条控制路径，而应显式区分当前运行模式。否则不同模式会在周期推进时落到错误分支。

## 控制模式设计

### 模式一：普通跟随模式

协议入口：

```text
f=1,s=106,v=1,x=0.12,y=-0.06
```

语义：

1. `s` 是普通跟随模式的递增序号。
2. `v=1` 表示当前拍有有效目标位置控制量。
3. `x/y` 表示车体系相对控制目标，后续仍按当前普通模式口径解释。

运行规则：

1. 收包时更新当前跟随目标。
2. 后续周期继续基于该目标进行位置控制。
3. 周期内持续叠加朝向保持。

### 模式二：速度模式

协议入口：

```text
f=1,m=1,x=0.10,y=-0.05
```

语义：

1. `m=1` 表示进入速度模式。
2. 速度模式不要求序号字段。
3. 此时 `x/y` 分别解释为车体系横向、纵向速度目标。

运行规则：

1. 收包时写入当前速度目标。
2. 后续周期继续保持该速度目标，直到被新命令覆盖、显式停机或超时停机。
3. 周期内持续叠加朝向保持。

### 显式角速度控制的定位

本轮不把“显式角速度控制”定义成第三种独立平移模式，而是把它定义成覆盖在当前平移模式之上的“转向来源”。

也就是说：

1. 平移模式仍然只有两种：普通跟随模式、速度模式。
2. 转向来源有两种：自动朝向保持、显式角速度控制。

规则：

1. 当当前命令显式给出非零角速度时，转向来源切到显式角速度控制。
2. 当显式角速度不再提供或回到近零阈值时，转向来源回到自动朝向保持。
3. 无论转向来源如何变化，当前平移模式本身不应被改写。
4. 因此不存在单独的“显式角速度模式”；它始终附着在“普通跟随模式”或“速度模式”之上。

## 状态与周期推进设计

### 需要补充的最小状态

为了避免不同模式在周期推进时落到同一条错误路径，本轮需要让辅车运行时显式持有“当前控制模式”的最小状态。该状态只服务于周期分发，不引入额外业务语义。

至少需要能区分两类状态：

1. 当前平移模式
2. 当前转向来源

其中：

1. 平移模式至少需要能区分：无激活、普通跟随、速度模式。
2. 转向来源至少需要能区分：自动朝向保持、显式角速度控制。

### 周期分发规则

后续周期不再只看 `follow_active`，而要结合当前控制模式做分发：

1. 普通跟随模式 -> 继续按位置目标解算平移。
2. 速度模式 -> 继续按当前速度目标输出平移。
3. 无激活模式 -> 只保留零平移加朝向保持或停机行为。

转向来源在平移模式之后单独决定：

1. 自动朝向保持 -> 输出自动角度修正。
2. 显式角速度控制 -> 输出手动角速度。

因此：

1. “普通跟随 + 自动朝向保持”是当前默认控制形态。
2. “速度模式 + 自动朝向保持”是调试速度模式的默认控制形态。
3. “普通跟随 + 显式角速度控制”与“速度模式 + 显式角速度控制”都应在周期层合法存在。

### 超时与停机规则

本轮不改变超时总原则，但要保证两种模式行为一致：

1. 普通模式超时 -> 清目标、停机、保持超时状态。
2. 速度模式超时 -> 清速度目标、停机、保持超时状态。
3. 显式 `HOLD` / `STOP` / `DISARM` 进入后，不允许旧模式残留在后续周期中继续生效。

## 协议设计约束

本轮协议侧只做必要约束，不再扩大：

1. 正式高频控制仍统一使用键值短协议。
2. 普通模式必须继续使用 `f=1,s=...,v=...,x=...,y=...`。
3. 速度模式必须使用 `f=1,m=1,x=...,y=...`。
4. 旧长协议与旧短 CSV 协议继续保持移除状态，不重新恢复兼容层。
5. 调试确认回包格式本轮不作为主优化目标，只要求能区分普通模式与速度模式命令已被接受。

## 测试与验收口径

### 自动化验证

本轮至少需要覆盖以下自动化行为：

1. 普通模式收包后，后续周期继续输出普通模式控制。
2. 速度模式收包后，后续周期继续输出速度模式控制。
3. 普通模式和速度模式都持续叠加朝向保持。
4. 显式角速度输入时，转向来源应从自动朝向保持切到手动角速度。
5. 显式角速度撤销后，应回到当前平移模式对应的自动朝向保持。
6. 超时后两种模式都能正确停机并清空模式状态。
7. 旧协议仍明确拒绝，不恢复兼容层。

### HIL 验收

本轮 HIL 验收只回答“控制模式持续性是否恢复”，不回答单位标定是否完成。

至少需要确认：

1. 发送一条普通模式命令后，车不会只在第一拍动一下再退化。
2. 发送一条速度模式命令后，车会持续保持平移，而不是第一拍后平移消失。
3. 两种模式下车辆朝向都能持续被拉回，不再明显跑偏。

本轮 HIL 不新增显式角速度联调入口，因此“显式角速度接管转向、撤销后恢复自动朝向保持”的行为只要求保留自动化覆盖，不作为本轮 HIL 必验项。

## 风险与控制

### 风险一：模式状态新增后影响现有停机逻辑

控制方式：

1. 所有停机与超时路径都必须显式清空当前控制模式。
2. 用自动化测试覆盖 `HOLD`、`STOP`、超时和重置里程场景。

### 风险二：速度模式与普通模式继续共用宽泛状态导致回归

控制方式：

1. 本轮不再依赖“只有 `follow_active` 一个开关”来推断后续周期路径。
2. 模式状态必须成为周期分发依据的一部分。

### 风险三：把单位标定问题误归咎为模式问题

控制方式：

1. 本轮 spec 明确不处理单位重标定。
2. 实现和验收报告必须把“模式持续性修复”与“单位标定待处理”分开描述。

## 后续计划入口

待本设计经用户确认后，下一阶段实施只围绕以下最小内容展开：

1. 为辅车运行时增加最小模式状态。
2. 修正速度模式的跨周期持续行为。
3. 收口“角度保持默认启用、显式角速度例外”的规则。
4. 补回归测试与 HIL 留证。

本轮完成后，如仍要继续处理“位置模式实际单位与实车不符”的问题，应另开新的设计文档，不与本轮控制链修复混做一轮。
