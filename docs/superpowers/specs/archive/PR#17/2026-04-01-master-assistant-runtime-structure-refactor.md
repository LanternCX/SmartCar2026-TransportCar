# 主辅运行时结构清晰化重构规范

## 背景

上一轮实现已经把主辅两侧的板端主链、入口和联动链路大体接回主线, 但 review 暴露出一个新的核心问题:

**当前仓库不是单纯“还有功能没做完”, 而是“结构边界本身不清楚”, 已经开始误导维护者、静态分析器和后续 Agent。**

这类问题如果不先处理, 后续继续补功能只会把结构堆得更厚:

1. 常量、状态、控制、运行时 owner、状态机混在一起。
2. 一些文件名和目录名看起来像分层, 实际只是转手导出或语义重复。
3. LSP / Pylance 会被入口自举和重复命名模块误导, 进而诱导出没有必要的兜底导入。
4. 低价值结构测试在保护“当前目录长什么样”, 而不是保护真正重要的行为边界。

本规范的目标不是做一次“目录美化”, 而是把主辅运行时结构改成真正清楚、稳定、可读、对静态分析友好的形态。

## 本轮 review 收口

本轮 review 的 9 条意见统一收口如下:

1. `config` 与 `runtime_params` 的边界没有写清, 需要按“硬件事实”与“运行参数”重新划清。
2. `vision_ingress.py`、`vision_state_machine.py` 这类重复入口壳没有必要, 应删除。
3. `status.py`、`decision.py` 这类文件中, 真实被主链使用的要保留并补清楚注释; 只做转手导出的要删除。
4. `main.py` 的层层装配需要收薄, 只保留板端根目录直烧所需的最小入口逻辑。
5. 结构必须对 LSP / Pylance 友好, 不再继续制造误导静态分析的假问题。
6. 低价值测试要具体评估后删除, 不引入新的结构性约束噪音。
7. 注释必须按仓库规则重写, 重点说明职责、边界和保留原因。
8. `stability/` 命名不准确, 应按职责并回控制相关目录。
9. `ctrl/` 现在过散, 跨周期状态不应继续混在控制层里; 如果保留状态收口, 应明确进 `state/`。

## 目标

本轮必须同时达成以下目标:

1. 把全局常量、跨周期状态、单周期控制、整周期运行时、状态机这几类概念显式拆开。
2. 删除会制造重复概念的壳文件和壳目录, 不再用文件名模拟分层。
3. 让主辅运行时代码对 LSP / Pylance / Agent 都保持直接、稳定、可理解的导入语义。
4. 保持主辅板端根目录直烧语义不退化。
5. 在不改变业务目标的前提下, 让目录职责、文件职责和 owner 语义重新清楚。
6. 清理低价值结构测试, 只保留真正保护行为和边界的测试。
7. 按仓库注释规则补齐保留文件的职责说明。

## 非目标

本轮不做以下内容:

1. 不改变主车和辅车当前业务职责。
2. 不为了“统一架构”重新引入新的总控角色运行时。
3. 不为了兼容旧代码继续保留 import fallback。
4. 不为了静态分析器去写兜底导入或假对象。
5. 不做与这轮结构收口无关的大范围功能扩展。
6. 不改辅车当前最小状态回传契约, 只允许整理承载位置和调用边界。

## 核心边界

### 一、常量边界

1. `config.py` 只保留硬件真值、板级事实和部署相关固定常量。
2. `runtime_params.py` 只保留运行策略、阈值、控制周期、比例系数、超时和限幅参数。
3. 不允许再把硬件事实和运行策略混写在一个入口里。

### 二、状态边界

1. 跨周期状态必须单独收口, 不继续伪装成控制层边界。
2. 状态对象只负责保存状态、规范状态字段和必要的序列化。
3. 状态对象不承担控制计算、硬件访问和整周期调度。
4. 如果状态相关逻辑足够独立, 应明确进入 `state/` 目录。

### 三、控制边界

1. `ctrl/` 只保留单周期控制计算、控制算法和与控制直接相关的工具。
2. 控制层可以读当前状态, 但不拥有跨周期状态 owner。
3. 控制层不负责协议调度、硬件总装配和长期状态收口。
4. `stability/` 中仍有价值的计算能力, 应并回控制层按职责命名。

### 四、运行时边界

1. `motion_runtime.py` 和 `app.py` 这类整周期 owner 只负责装配、调度和主链编排。
2. 运行时 owner 必须明确谁持有状态、谁调用控制、谁接硬件、谁对外输出。
3. 运行时 owner 不再通过额外壳文件制造二次入口。

### 五、状态机边界

1. 状态机只保留阶段切换语义。
2. 状态机不承载跨周期 owner 语义。
3. 状态机不承担与其概念无关的控制、协议或硬件职责。

## 结构约束

### 一、删除重复概念

以下类型一律视为优先清理对象:

1. 与包目录同义的外层壳文件, 如 `decision.py`、`vision_ingress.py`、`vision_state_machine.py` 这类只做转手导出的文件。
2. 名字像分层、实际只做别名转发的文件。
3. 不能解释“为什么必须单独存在”的边界文件。

### 二、入口最小化

1. `main.py` 只保留板端根目录直烧所需的最小自举、按键分支和主循环入口。
2. 不再保留为了测试或静态分析绕出来的多层装配中转。
3. 如果某层装配不能解释其独立价值, 应合并回更自然的 owner。

### 三、静态分析友好

1. 主线运行时代码保持直接导入。
2. 不保留 import fallback。
3. 不保留会误导 LSP / Pylance 的重复命名壳文件。
4. 除板端根目录直烧所必需的最小自举外, 不使用不必要的动态模块技巧。
5. 结构应让 Agent 和静态分析器都能直接看懂依赖方向。

## 测试与注释约束

### 一、测试约束

1. 删除只保护“目录存在”“模块可 import”“壳文件还能转手导出”的低价值测试。
2. 保留并补强以下测试:
   - 板端根目录入口语义
   - 关键行为边界
   - 协议语义
   - 状态序列化语义
   - 控制和运行时 owner 的关键约束
3. 重构产生的行为变化必须先有失败测试。

### 二、注释约束

1. 保留文件的注释必须说明职责、边界和保留原因。
2. 被保留的状态对象、运行时 owner 和状态机, 注释必须写清楚谁在使用、跨几个周期以及为什么不应并到别处。
3. 不再写复述文件名、类名、函数名的空注释。

## 本轮优先修改点

1. 先写一份结构收口测试, 让重复概念和错误边界先暴露出来。
2. 删除主车重复入口壳文件, 并把相关测试改到真实目录入口上。
3. 把 `config.py` 和 `runtime_params.py` 的边界通过代码和测试一起收口, 不再只停留在文字定义。
4. 收薄主辅 `main.py` 的装配层级。
5. 把辅车跨周期状态从当前松散位置明确收口, 视实际情况进入 `state/`。
6. 把真实状态机文件纳入边界梳理和测试验证, 证明状态机职责没有继续外溢。
7. 把 `stability/` 中仍有价值的能力并回控制相关目录, 并同步清理测试。
8. 删掉低价值结构测试, 补足保留文件的职责注释。

## 完成标准

1. 代码中不再存在会制造重复概念的主线壳文件。
2. `main.py` 装配层明显收薄, 且板端根目录语义保持成立。
3. 常量、状态、控制、运行时、状态机的边界可以被清楚说明。
4. LSP / Pylance 不再被当前结构诱导出明显错误导入路径。
5. 低价值结构测试被移除, 保留测试仍能保护关键行为边界。
6. `config.py` 与 `runtime_params.py` 的职责边界有对应测试保护。
7. 状态机边界有对应测试保护, 不接受只靠目录调整视为完成。
8. 保留文件的注释达到仓库规则要求。
9. 触及主辅入口或运行时 owner 的改动, 必须完成板端最小验证并留证。
10. 板端验证必须可复核, 不能只凭串口输出判通过。
11. 最小内存留证必须可复核, 且能说明本轮保留对象的唯一归属与必要性。
