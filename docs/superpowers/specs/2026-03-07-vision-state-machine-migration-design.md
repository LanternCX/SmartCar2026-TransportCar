# 视觉状态机迁移设计文档

## 背景

`../SmartCar2026-Vision/main.py` 当前将视觉识别、状态机跳转和底盘串口编排全部放在 OpenArt 端。当前仓库 `src/services/transport_car.py` 已经具备完整的姿态、里程计、位置模式和命令路由能力，因此更适合承接状态机与动作编排。用户要求 OpenArt 端仅回传图像识别得到的目标点 `x,y`，其余逻辑迁移到主控端，同时尽量保持重构前后车辆行为一致。

## 目标

1. 将 Vision 仓库中的状态机跳转迁移到当前仓库。
2. 仅将 `UART6` 上的纯 `x,y` 双键包视为视觉观测输入。
3. 保留现有 `dx/dy/d_angle` 位置式控制效果。
4. 保留现有外部命令链路和 `command_lock` 语义，避免破坏既有协议与测试。
5. 为视觉连续跟踪增加一条内部无阻塞控制链路，避免高帧率串口数据因硬锁等待造成卡顿。

## 非目标

- 不修改 OpenArt 仓库代码。
- 不重定义全局协议中所有 `x/y` 的语义；仅对 `UART6` 上的纯 `x,y` 视觉包做专用解释。
- 不移除现有手动控制、调试控制和位置锁定功能。

## 设计决策

### 1) 双链路并存

- 保留现有外部命令链路：`UART3/UART6 -> CommandRouter -> cmd_*.py -> _finalize_route() -> command_lock`。
- 新增视觉内部链路：`UART6 纯 x,y 包 -> vision_protocol -> vision_state_machine -> 内部相对目标 -> 现有位置/姿态控制环`。
- 视觉链路不直接走现有 `cmd_dx/cmd_dy/cmd_d_angle`，避免高频连续包被解释为一次性增量并累积过冲。

### 2) 视觉协议边界

- 仅将 `UART6` 上恰好只包含 `x=...,y=...` 两个键的消息视为视觉观测。
- 其他消息仍走既有 `CommandRouter`。
- 视觉观测只保留“最新一帧”，不排队，避免通信积压导致闭环延迟。

### 3) 状态机迁移范围

- 迁移状态：`IDLE`、`ALIGN_ANGLE`、`ALIGN_DIST`、`ALIGN_DX`、`ORBITING`、`PUSHING`、`RETURNING`、`DONE`。
- 迁移判定：死区判断、回退逻辑、丢目标回空闲、推行/返回阶段切换。
- 不迁移 OpenArt 端 `send_cmd_sync()`、`wait_until_idle()`、`?lock/?pos` 串口往返逻辑，改为直接读取本机 `heading_est`、`odometry` 与本机状态字段。

### 4) 适度加锁策略

- 现有 `command_lock` 保持不变，用于外部一次性相对位移、绝对位置、模式切换和调试命令。
- 视觉链路不使用 `command_lock` 进行每帧阻塞等待。
- 视觉链路增加两类轻量保护：
  - 控制权保护：视觉状态机活跃时，`UART6` 上的纯视觉包优先占用视觉控制通道。
  - 状态切换保护：使用滞回和稳定帧计数抑制视觉噪声造成的频繁跳转。

### 5) 内部控制意图模型

- 视觉状态机输出结构化控制意图：`dx_body`、`dy_body`、`d_angle_deg`、`rear_only_mode`、`active`。
- 每个 5ms 周期根据当前 `odometry` 和 `heading_est` 将该相对意图转换为本周期绝对目标 `x/y/angle`。
- 这样既保留 `dx/dy/d_angle` 风格的跟踪效果，又不会把连续观测当成外部一次性增量命令累加。

### 6) 推行与返回行为

- `push_angle` 采用主控侧固定参数，放在 `src/config/params.py`。
- `PUSHING` 阶段保持固定推行角，叠加一个固定前向 `dy` 偏置与小幅 `dx` 纠偏。
- 推行结束不再依赖 `?lock`，改为通过里程计累计推行距离 `PUSH_DISTANCE_M` 判定。
- `RETURNING` 阶段持续跟踪 `push_angle + 180`，以角度容差判定完成。

## 模块划分

### `src/services/vision_protocol.py`

- 负责解析视觉输入与管理观测时效。
- 提供：
  - 视觉包识别与解析。
  - 最新观测缓存。
  - 观测超时判定。

### `src/services/vision_state_machine.py`

- 负责状态机跳转与视觉控制意图计算。
- 提供：
  - 状态常量与运行时上下文。
  - 单步状态推进函数。
  - 相对控制意图转本周期绝对目标的辅助函数。

### `src/services/transport_car.py`

- 作为集成层，负责：
  - 在 `_process_uart()` 中接入视觉协议解析。
  - 在控制周期中驱动视觉状态机。
  - 在视觉激活时优先使用视觉控制意图。
  - 保持现有手动命令链路可用。

## 风险与缓解

1. 风险：视觉链路与现有 `last_cmd` 混用导致模式污染。
   - 缓解：增加“当前激活控制源”与视觉专用 `rear_only_mode` 叠加逻辑，不直接覆盖手动状态。
2. 风险：视觉噪声导致状态在 `ALIGN_*` 之间抖动。
   - 缓解：加入稳定帧计数与滞回阈值。
3. 风险：频繁串口处理影响 5ms 周期。
   - 缓解：串口解析留在主循环非中断路径，控制周期仅消费缓存观测。
4. 风险：推行距离仅靠时间会漂移。
   - 缓解：改用里程计累计距离判定。

## 验收标准

- `tests/unit` 新增视觉协议、视觉状态机和控制意图转换测试并通过。
- 既有 `tests/contract` 保持通过，证明老命令链未被破坏。
- `TransportCar` 集成后，`UART6` 纯 `x,y` 视觉包可以驱动状态机流转。
- HIL 文档补充视觉连续跟踪、丢目标、`reset` 中断和绕行切换场景。
