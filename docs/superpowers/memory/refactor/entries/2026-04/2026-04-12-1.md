## Title
将当前正式入口从 `boot.py` 收口为 `main.py` 并切换到按钮长按脚本分发

## Background / Issue
当前仓库恢复到单一 `src/` 之后，正式入口仍然沿用 `boot.py`，并继续借用 `D8` 参与脚本分发。但用户已经明确要求 `D8/D9` 只保留车号识别语义，入口层需要尽快与这条边界对齐，同时本轮只允许做路口层重构，不顺手扩大到运行时主链、控制链或通信链。

## Change Unit
把当前仓库的正式入口从 `src/boot.py` 收口为 `src/main.py`，将脚本分发切换为 `C8/C9` 长按，并同步补齐最小入口测试和正式方向文档，让“当前正式基线到底用什么入口”重新变成单一口径。

## Actions / Outcome
- 新增 `src/main.py` 并删除 `src/boot.py` -> 当前正式入口从旧软启动分发切到单一 `main.py`
- 入口层改为基于 `KEY_HANDLER` 的 `C8/C9` 长按判定 -> 脚本分发不再占用 `D8/D9` 车号识别语义
- 保持 `script/remote_control.py`、`script/pid_identify.py`、`script/calibrate_gyro.py` 原样复用 -> 本轮改动面被限制在入口层, 没有顺手改动脚本主体
- 新增入口层单测并改写布局测试 -> `main.py` 存在、`boot.py` 移除、长按分发规则和 `KEY_HANDLER` 约束都被主机侧保护网锁住
- 同步 `docs/developer/strategy.md`、`docs/developer/tasks.md`、`docs/developer/control.md` -> 后续新会话不会再把 `main.py` 误判为“下一轮主题”

## Lessons / Refinements
- 当用户明确要求“只做入口层重构”时，最稳妥的做法是先用入口测试钉死边界，再改入口文件本身，避免顺手把运行时主链一起带动。
- 对这类板端入口切换，文档口径同步和代码切换同样重要；如果只改代码不改正式文档，后续会话很容易继续沿旧基线讨论。
