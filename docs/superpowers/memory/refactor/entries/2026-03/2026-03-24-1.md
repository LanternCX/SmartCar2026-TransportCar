## Title
将 skill 私有正文迁入对应 skill 并补齐 reference-sync 维护边界

## Background / Issue
仓库里的 Skill 文档归属长期不一致：`mpy-cli` 完整手册仍留在根 `docs/`，OpenArt 协议也还漂在 `docs/Protocol.md`，而 `reference-sync` 只表达“正文在 docs”，没有单独维护来源登记和维护清单。与此同时，Git 提交流程里还缺少“默认禁止 agent 自动追加 `Co-authored-by`”的明确规则，导致提交规范和用户约束出现偏差。

## Change Unit
把 Skill 私有正文迁回对应 Skill，自此由 `reference-sync` 专门维护来源与清单，并补齐 git-workflow 的提交尾注禁令。

## Actions / Outcome
- Approach 1: 继续让 `mpy-cli` 与 OpenArt 协议停留在根 `docs/`，仅补几条跳转说明 -> 归属边界依旧混乱，正式正文与维护信息仍然耦合
- Approach 2: 将 `mpy-cli` 手册迁入 `.agents/skills/mpy-cli-tool/references/mpy-cli-manual.md`，将 OpenArt 协议迁入 `.agents/skills/using-rules/references/openart-protocol.md`，并删除根 `docs/` 的旧路径 -> Skill 入口与正式正文归属一致，历史文档同步收口到新落点
- Final approach: 为 `.agents/skills/reference-sync/` 新增 `references/source-registry.md` 与 `references/maintenance-checklist.md`，把来源、正式落点和维护检查项集中管理，同时在 `.agents/skills/git-workflow/SKILL.md` 明确默认不追加 `Co-authored-by` -> 文档维护边界清楚，提交规范与用户要求对齐

## Lessons / Refinements
- Skill 私有正文一旦被长期放在根 `docs/`，后续入口、维护信息和历史文档会一起漂移；应尽早把正式正文迁回归属 Skill
- `reference-sync` 更适合只承接来源登记和维护清单，不应再兼任正式正文容器

## Integration Summary
该变更把 `mpy-cli`、OpenArt 协议和 `reference-sync` 的职责重新对齐为“Skill 持有正式正文、reference-sync 持有维护信息”的稳定结构，并同步把 git-workflow 的尾注规则收口到与用户约束一致的口径。
