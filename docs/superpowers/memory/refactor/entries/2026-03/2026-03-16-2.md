## Title
抽出命令、运动和视觉 owner 并固化内存评审门禁

## Background / Issue
在 `RuntimeCore` 与 `MinimalDiagnostics` 之后, `TransportCar` 仍然直接持有命令装配、底盘控制链和按角色装配的视觉栈, 这会继续放大编排层常驻状态并让低内存 review 缺少硬门禁。实施计划的 Task 5-8 要求继续把最小 query、motion owner、vision owner 和 memory review 规则从 `TransportCar` 中拆出并固化。

## Change Unit
继续抽出命令、运动和视觉 owner，并把内存评审门禁正式固化到规范与文档。

## Actions / Outcome
- Approach 1: 先为 `MinimalCommandRuntime` 写失败测试 -> 新增 `tests/unit/services/test_minimal_command_runtime.py`, 锁定最小 query surface 和 full command 激活路径, 再让 `TransportCar.apply_command()` 改为委托 `command_runtime.activate_full_commands()`
- Approach 2: 抽出 `MotionRuntime` -> 新增 `src/services/runtime/motion_runtime.py`, 收口 `imu`、电机、编码器、轮组状态和 `ChassisController`, 再让 `TransportCar` 通过 `motion_runtime` 暴露 `chassis_state` / `chassis_controller`, 保持现有测试与脚本兼容
- Approach 3: 抽出 `VisionRuntimeService` -> 新增 `src/services/runtime/vision_runtime_service.py`, 把主/辅车视觉装配从 `TransportCar` 下沉为 role-aware owner, 主车才创建 runtime + coordinator, 辅车只保留禁用协调器
- Final approach: 更新 `AGENTS.md`、`.agents/skills/code-standards/SKILL.md`、`.agents/skills/code-standards/README.md` 和 `docs/developer/memory-review.md` -> 将最小内存占用指标、A / B / C / D / E 分类、禁止 import-time 自动装配和评审证据要求正式落盘, 并通过 `python3 -m pytest --collect-only -q` 完成文档自检

## Lessons / Refinements
- 对 `TransportCar` 这类历史编排对象, 最稳妥的迁移路径是“先抽 owner, 再保留实例级兼容 facade”, 不要一次性删除所有运行时入口
- `__getattr__` 式实例兼容比重新加回 class-level compatibility property 更安全, 因为不会破坏“类上不再暴露旧字段”的约束测试
- memory review 文档必须和 agent 规范同步更新, 否则评审时很容易又退回“结构更清晰即可”的软标准
