## Title
重写双车协同搬运路线的正式开发文档口径

## Background / Issue
项目开发文档中的正式口径仍然把路线理解为单一路径协同推进，和当前新的项目判断不一致。新的判断已经收敛为：项目总路线由寻找态状态机集和搬运态状态机集组成，搬运至少包含前后推和左右推两种构型，主车和辅车都参与运动，高速通信与速度前馈属于关键能力，近期的速度前馈验证只是整条演进路线中的一个阶段。需要把这些判断统一写进正式开发文档，避免后续实现和讨论继续被旧口径带偏。

## Change Unit
重写 `docs/developer/strategy.md`、`docs/developer/tasks.md`、`docs/developer/control.md` 和 `docs/developer/vision.md`，让项目总方向、演进路线、控制判断和视觉职责统一表达新的双车协同搬运路线。

## Actions / Outcome
- 重写 `docs/developer/strategy.md` -> 把项目总路线收口为“寻找态状态机集 + 搬运态状态机集”，并写清前后推、左右推、主辅共同运动和关键能力定位。
- 重写 `docs/developer/tasks.md` -> 把近期速度前馈验证放回整体演进路线中，形成从基础对齐、关键能力验证到完整路线闭环和赛前收口的阶段任务。
- 重写 `docs/developer/control.md` -> 把控制侧判断改为围绕高速通信、速度前馈和状态切换展开，补齐“为什么必须这样做”的正式解释。
- 重写 `docs/developer/vision.md` -> 把视觉职责收口为按阶段服务不同对象，明确寻找态与搬运态的视觉输入重点不同。

## Lessons / Refinements
- 当项目判断已经从局部调参升级为路线重规划时，需要同时收口 `strategy`、`tasks`、`control` 和 `vision`，不能只改其中一份文档。
- 近期最想验证的能力要放进演进路线的对应阶段，不能直接覆盖整条路线本身。
