## Title
完成当前视觉协议生效文档与代码事实的基线收口

## Background / Issue
当前仓库代码中的视觉协议事实已经收口到 `UART6` 单路输入与单行 `x=<x>,y=<y>` 文本观测, 但规则文档、开发文档和位于根目录的旧设计文档仍混杂着双路输入、`v/s`、完整框字段、`camera_id/category` 与多检测结果等口径。继续保留这些入口文档会让后续会话、评审和实现决策反复被旧方案带偏, 因而需要把当前生效文档统一到代码现状, 并把失效设计移出根目录。

## Change Unit
完成当前视觉协议生效文档的整轮收口: 把规则入口正文与 `docs/developer/*` 统一到 `UART6` + `x=<x>,y=<y>` + 单向观测口径, 清理沿革式表述, 归档两份停留在根目录的旧视觉设计文档到 `archive/PR#25/`, 同步修正文档契约测试与引用路径, 使后续阅读入口重新回到与当前代码事实一致的基线。

## Actions / Outcome
- 收口规则与开发文档口径 -> 当前生效文档统一按 `UART6`、单行 `x=<x>,y=<y>`、`obs_x/obs_y` 和主控单向消费观测来描述视觉链路。
- 清理现状正文中的旧方案残留 -> 双 UART、`v/s`、完整框字段、`camera_id/category`、多检测结果和多处沿革式写法不再混入当前事实入口。
- 归档旧视觉设计文档 -> 两份 2026-04-06 视觉最小文本协议文档移入 `docs/superpowers/*/archive/PR#25/`, 根目录入口不再把它们保留成当前生效方案。
- 同步验证入口 -> `tests/contract/test_openart_protocol_doc_contract.py` 改为校验当前正式视觉协议正文, 全量 `pytest` 通过。

## Lessons / Refinements
- 当生效文档是后续会话的主要事实入口时, 文档收口必须与契约测试一起同步, 否则旧测试会反向把正文拉回失效口径。
- 归档核对应该优先按文件路径验证, 不要用会同时命中文本说明和 archive 内容的正文搜索命令代替文件存在性检查。
