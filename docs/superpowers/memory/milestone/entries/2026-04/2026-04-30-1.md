## Title
完成 PR#61 短包通信协议与状态机前置边界收口

## Background / Issue
后续状态机开发需要稳定的通信入口和清晰的仓库职责边界。车端运行时、主辅车链路、OpenART 视觉链路和相关测试需要围绕同一套通信语义收口，同时视觉仓库 Harness 管理职责需要归入当前仓库的 Mono Repo 组织方式，避免状态机开发继续依赖分散入口。

## Change Unit
PR#61 形成一个完整的状态机前置里程碑：设计并落地短包通信协议口径，覆盖 UDP 报文和 TCP 报文两种通信方式的统一语义；车端运行时切换到短包协议入口；主车前馈、辅车视觉跟随和融合链路按新协议重新对齐；视觉侧协议说明、部署辅助、测试组织和 spec/plan 归档同步收口。

## Actions / Outcome
- 设计短包通信协议并更新协议文档 -> 车端运行时、主辅车链路和视觉链路具备统一通信语义，可承接 UDP 报文与 TCP 报文两种通信方式
- 运行时入口改为围绕 `v/s/a/o/r` 短包分发 -> 正式运行链路只面对新的协议入口，状态机接入点更集中
- 清理旧命令注册、路由、参数查询和相关测试 -> 正式链路避免旧命令系统与新短包协议并存
- 对齐主车前馈、辅车视觉跟随和前馈融合链路 -> 主车、辅车、OpenART 视觉端的数据职责在文档和测试中保持一致
- 清理视觉仓库 Harness 管理边界并适配 Mono Repo -> 视觉侧协议迁移计划和相关管理信息由当前仓库统一追溯
- 增加部署辅助脚本并更新 README -> 本地部署入口更直接，联调前准备步骤更集中
- 归档 PR#61 相关 3 组 spec/plan -> 本次通信协议与运行时迁移过程可追溯

## Lessons / Refinements
- 状态机开发前要先固定通信语义和仓库职责边界，否则状态机会同时吸收协议歧义、仓库分散和测试入口漂移
- 协议迁移不应只改解析代码，必须同步处理运行时入口、主辅链路、视觉链路、文档、测试和归档
- 旧协议入口清理应与新协议落地同批完成，避免后续联调在两套入口之间误判问题来源
