## Title
切换主辅正式通信链路到 UART8

## Background / Issue
当前仓库刚把主辅双侧角色运行时收口到统一协同链路，但正式口径、运行时代码和测试都把主辅通信固定在 `UART3`。现场已经确认本轮主辅通信接线改为 `UART8`，而主车上游控制入口仍保持 `UART3`，若继续保留旧口径，会让主车转发、辅车接收和联调文档长期按错链路理解。

## Change Unit
把当前阶段主辅正式通信链路从 `UART3` 切到 `UART8`，同时保持主车 `UART3` 上游控制入口不变；同步收口主车转发运行时、辅车跟随运行时、主机侧测试以及开发文档和规则入口，使代码、规则和联调口径重新保持一致。

## Actions / Outcome
- 把主辅正式通信链路改为 `UART8`，并同步调整主车转发与辅车接管运行时 -> 主辅协同控制走统一 `UART8` 链路，主车上游控制继续保留在 `UART3`
- 保持辅车 `UART6` 本地视觉输入边界不变，只替换主辅通信口 -> 跟随闭环结构不扩面，只改正式通信接线口径
- 补齐单元测试、契约测试、开发文档和规则入口 -> 代码事实、测试验证和联调说明重新对齐到“`UART3` 上游控制 + `UART8` 主辅通信”边界

## Lessons / Refinements
- 涉及串口职责切换的改动，必须同时维护运行时代码、测试、开发文档和规则入口，否则后续联调会继续按旧链路排查
- 涉及双车通信改口时，必须先区分上游控制入口和主辅通信口，不要把主车接上游命令的链路一并迁走
