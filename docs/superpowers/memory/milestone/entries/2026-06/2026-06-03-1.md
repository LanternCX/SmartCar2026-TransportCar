## Title
接入 OpenART 物体 YOLO 识别链路

## Background / Issue
色块识别在比赛现场稳定性不足, 红色阈值只适合作为演示入口。当前目标是让主车与辅车找物体链路使用 YOLO 模型识别, 同时保留已稳定的回库黄线算法和辅车跟随主车色标算法。

## Change Unit
OpenART 视觉仓库把主车物体搜索、搬运入口对正、绕行修正以及辅车找物体、搬运对正、绕行修正的候选目标来源切换为 YOLO 模型框。车端短帧协议、速度输出、可靠事件和黄线/色标职责保持不变。

## Actions / Outcome
- 在主车与辅车 OpenART 入口加入 YOLO 模型加载和检测框适配 -> 物体候选继续输出中心、底边、面积和可绘制框。
- 把模型 owner 收口到运行入口并按帧传入处理链 -> 避免模块级运行时缓存占用边界不清。
- 保留辅车跟随色标和主辅回库黄线色彩/像素算法 -> 稳定链路不随物体识别改动扩大范围。
- 更新部署脚本的 `yolo` 参数 -> 默认只部署代码, 需要时才同步模型文件到 OpenART 存储根目录。

## Lessons / Refinements
- 图像识别算法切换应优先保持车端协议和事件语义不变, 只替换视觉端候选来源。
- 模型没有覆盖或现场已稳定的元素不应强行纳入模型路径, 否则会把可控改动扩大成训练与联调任务。
- 模型对象需要明确 owner, 不把重型运行时对象放入无边界的模块级可变状态。
