## Title
完成主辅车联动搬运状态闭环

## Background / Issue
双车搬运主线需要从“单个阶段能动作”推进到“主车和辅车能按同一套状态机完成搜索、绕行、对正、搬运、收尾和下一轮搜索”。在此之前, 主车视觉 hook、辅车子状态、绕行、搬运入口对正、搬运前馈和搬运结束收尾分别落在不同改动中, 缺少一个端到端闭环记忆。

## Change Unit
PR#64、PR#68、PR#70、PR#76 和 PR#80 逐步把主车和辅车状态机串成完整协同搬运闭环：主车建立搜索 hook 并进入绕行, 辅车按主车同步执行找物体和绕行, 双方在搬运入口对正后进入协同搬运, 搬运结束后执行后退、回身、横移脱离并恢复下一轮搜索。当前方案通过主机侧回归覆盖状态跳转、可靠同步、前馈融合和收尾动作, 验证了主辅车协同搬运路线的软件闭环可行。

## Actions / Outcome
- 接入主车搜索 hook 与主车本地视觉速度 -> 主车能从搜索阶段获得目标事件和搜索控制量。
- 建立主车与辅车的找物体、idle、绕行和对正同步 -> 双车能按同一状态主线推进到搬运入口。
- 引入统一绕行和搬运前馈链路 -> 主车负责推进和转发, 辅车融合前馈与本地视觉修正辅助搬运。
- 增加搬运结束 hook 与收尾状态 -> 主车根据结束事件进入收尾, 主辅依次完成后退、回身、横移并重启搜索。
- 同步更新状态、协议、控制和视觉文档 -> 开发文档描述当前完整状态闭环, 不再只描述局部阶段。
- 扩展主车、辅车运行时和状态机回归测试 -> 主机侧固定关键状态跳转、同步确认和搬运收尾行为。

## Lessons / Refinements
- 状态机阶段要按端到端闭环检查, 只验证单个状态能进入不足以证明协同搬运方案成立。
- 主车全局状态和辅车子状态应保持职责分离：主车负责主线推进, 辅车只按主车同步执行本地动作并回报。
- 搬运结束不是简单停止, 需要把脱离、回身、横移和下一轮搜索 hook 一起纳入闭环, 否则下一轮目标搜索会被上一目标干扰。
