## Title
完成全部物体后黄线与色标回库闭环

## Background / Issue
比赛规则要求全部物体搬运完成后车辆回到车库。回库流程需要在 `ClearObject` 完整结束后按已完成物体数量分支, 主车负责回库决策, 辅车保持跟随并只接受主车完成同步。视觉状态切换必须沿用现有 `context_id/state/target/arg` hook、ACK 和可靠事件机制, 高频速度包只承载速度。

## Change Unit
车端主车状态机、主车运行时、辅车状态机、辅车运行时和 OpenART 主车视觉共同形成回库闭环: 全部物体完成后主车先后退对正黄线, 再固定左移并用黄线保持前后距离, 发现绿色色标后切换色标跟随, 到位后进入完成态并同步辅车停止。

## Actions / Outcome
- 主车增加 `RETURN_GARAGE_RETREAT`、`RETURN_GARAGE_LINE`、`RETURN_GARAGE_MARKER` 和 `FINISHED` 状态 -> 回库流程从搬运收尾和搜索流程中分离。
- 辅车增加回库跟随态和完成态 -> 回库跟随保持普通跟随融合行为, 完成同步后清空输入并停止。
- 主车 OpenART 增加回库黄线配置和回库色标配置 -> 黄线配置只输出纵向速度并上报色标发现, 色标配置输出绿色色标跟随速度并上报完成。
- spec 与 plan 状态更新为 `Archive` -> 正式文档同步继续由用户后续手动触发。

## Lessons / Refinements
- 回库阶段要把“决策状态”和“运动行为”分开描述: 辅车可以有单独回库跟随状态, 但行为必须等同普通跟随。
- 视觉配置切换要通过 hook 上下文完成, 不把发现色标或完成标志塞进速度包。
- 回库色标完成窗口要使用独立配置, 不能复用红色物体搜索的命中窗口。
