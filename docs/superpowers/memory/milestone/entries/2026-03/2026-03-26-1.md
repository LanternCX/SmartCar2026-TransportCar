## Title
重定向 OpenArt 辅车跟随主线到位置式高频闭环

## Background / Issue
`master` / `assistant` 最小运行时骨架已经形成, 但其目标偏向“运行时拆分与最小协议打通”。后续讨论明确了当前真正要落地的不是完整完赛链, 而是一个 OpenArt 识别辅车目标、主车高频遥控辅车跟随的最小真实闭环。用户同时补充了多条关键实测经验: 角度链在零漂校准、滤波、四元数积分和动态控制周期条件下可靠; `xy` 编码器积分精度差, 但位置式控制仍有必要; 视觉闭环必须和状态机分离; 速度环保留前馈参数辨识, 但不辨识 `PID`; 两个正交 OpenArt 分别走 `UART6` / `UART8` 独立视觉链路, `UART3` 专用于主车到辅车遥控; 视觉误差到控制量直接采用 P 环。

## Change Unit
将当前阶段的控制主线重新定义为“OpenArt 侧计算目标误差 -> 主车高频发送位置式控制量 -> 辅车持续闭环响应”, 并把相关经验收口进正式 spec、开发文档和 skill 参考页, 作为后续实现和评审的统一口径。

## Actions / Outcome
- 新写并补强 `docs/superpowers/specs/archive/PR#16/2026-03-26-openart-assistant-follow-design.md` -> 把当前阶段目标从“最小运行时骨架优先”重定向为“跟随闭环成立优先”, 并钉死 `follow=1,...` 默认控制报文与频率/超时边界
- 更新 `docs/developer/control.md` 与 `docs/developer/vision.md` -> 固化“位置式控制优先”“角度不依赖视觉”“双 OpenArt 持续回传”的经验口径
- 更新 `.agents/skills/using-rules/references/strategy-and-control.md`、`.agents/skills/using-rules/references/hardware-and-protocol.md` 与 `.agents/skills/using-rules/references/openart-protocol.md` -> 将新的串口分工、持续回传协议、P 环映射和最小状态回传提升为实现阶段规则入口

## Lessons / Refinements
- 当视觉输出本质是目标点误差时, 主链路优先保持位置式控制表达, 不要因 `xy` 积分不准就退化成速度式主控制
- 角度链若已被实测验证可靠, 应明确从视觉主链中剥离, 避免高代价视觉角度方案重新回流
- 状态机与高频视觉闭环必须分离, 否则容易把阶段锁语义错误带入高频控制链
- 当专项方案已经切换为持续回传主线时, 旧轮询协议必须明确降级为历史兼容说明, 否则实现者很容易被旧入口带偏
