## Title
视觉状态机迁移到主控端

## Background / Issue
需要读取 `../SmartCar2026-Vision` 的状态机逻辑,将状态跳转迁移到当前 RT1021 主控仓库,并将 OpenArt 端职责收缩为仅回传视觉目标点 `x,y`。同时要尽量保持现有底盘位置式控制效果,不能简单删除 `command_lock` 后继续复用外部增量命令语义。

## Change Unit
将视觉状态机职责迁入主控端搬运车运行时，形成主控内部视觉闭环与位置式控制协同。

## Actions / Outcome
- Approach 1: 直接复用外部 `cmd_dx/cmd_dy/cmd_d_angle` 链路并取消加锁 -> 会把连续视觉观测当成一次性增量累加,容易过冲,放弃。
- Approach 2: 改成纯速度模式跟踪 -> 行为与原车差异较大,且用户明确希望保留 `dx/dy/d_angle` 风格的位置式控制,放弃。
- Final approach: 保留外部命令锁链路,新增 `UART6 x,y -> VisionProtocol -> VisionStateMachine -> 内部相对控制意图 -> 绝对位置目标` 的视觉内部闭环 -> 既保留位置模式跟随效果,又避免高帧率视觉包在串口层阻塞等待。

## Lessons / Refinements
- 连续视觉观测与一次性增量命令不能共用同一语义；即使变量名同为 `dx/dy/d_angle`,也应区分“外部命令增量”与“内部周期目标”。
- 对存在 `command_lock` 的底盘架构做视觉重构时,最稳妥的方式是双链路并存：离散动作继续加锁,视觉闭环在主控内部覆盖式刷新目标。
