## Actions / Outcome
- Approach 1: 修补视觉协议批次边界 -> 支持空帧提交, 拒绝 `camera_id/frame_id` 跳变后的失效批次, 并补 unit/contract 回归
- Approach 2: 为主车加入双摄轮询与按相机缓存 frame batch -> 满足共享 `UART6` 下 `obstacle` 优先轮询和帧边界日志
- Approach 3: 在状态机前增加薄选择层 -> 主车从多检测结果里只选当前 `follower` / `cargo` 目标喂给状态机, 未选择检测不再劫持当前 transport intent
- Final approach: 补齐 `tests/hil/2026-03-dual-camera-polling.md` 和 `tests/hil/README.md` -> 形成 Task 6 的 Stage 2 / Stage 3 / HIL 可执行模板, 并把 `docs/developer/tasks.md` 调整为 host 已完成、设备留证待执行的诚实状态

## Lessons / Refinements
- 多检测协议升级后, 不能再默认用 protocol latest observation 代表状态机真实输入, 诊断快照也必须跟随 selected input 路径
- 用 `TypeError` 试探接口能力会掩盖真实 bug, 嵌入式运行时协作接口要显式而不是异常探测
- HIL 文档可以先补模板和待执行项, 但绝不能把未跑的 Stage 2 / Stage 3 写成已完成
