## Title
参数辨识脚本中速度除以3的设计原理澄清

## Background / Issue
在审查参数辨识脚本 `pid_identify.py` 时，发现 `filter_ident_speed()` 函数对滤波后的编码器速度进行了除以3的操作：

```python
def filter_ident_speed(filter_state, raw_ticks):
    smooth_raw = filter_state["input_lpf"].update(float(raw_ticks))
    fused_speed, _, _ = filter_state["dual_filter"].update(smooth_raw)
    filtered_speed = filter_state["output_lpf"].update(float(fused_speed))
    return float(filtered_speed) / 3.0  # ← 这里除以 3
```

而正式运行时的 `update_wheel_speeds()` 函数（`ctrl/filters.py`）并未进行除法操作。这引发了对辨识参数准确性的疑虑。

## Change Unit
无代码变更。本条目记录三轮全向底盘参数辨识时除以3的设计原理，防止未来误解。

## Actions / Outcome

### 问题诊断
- **初步怀疑**：辨识时除以3但运行时不除，可能导致前馈增益错误（只有实际值的1/3或3倍）
- **用户澄清**：除以3是刻意设计，不是bug

### 设计原理确认
**辨识条件**：
- 三轮全向底盘进行参数辨识时，车体悬空但三个轮子同时施加阶跃指令
- 由于底盘机械构型，三个轮子同时转动时速度是**耦合的**
- 每个轮子的编码器读数是"三轮共同作用下的速度"

**除以3的物理意义**：
- 单个轮子在带载荷（与另外两轮耦合）情况下的**真实速度响应** = 测量速度 / 3
- 辨识出的 `plant_gain` 和 `plant_tau` 是单轮**在耦合载荷下**的真实参数

**正式运行时的差异**：
- 每个轮子独立控制，接收独立的速度指令
- `wheel_speeds` 是各轮独立的编码器读数，不存在三轮同步耦合
- 辨识参数直接适用于独立轮速控制

### 验证结论
- 辨识脚本的除以3设计是**正确的**
- 辨识出的参数能够准确反映单轮在载荷下的动态特性
- 正式运行时不需要除以3，因为控制场景不同（独立控制 vs 耦合辨识）

## Lessons / Refinements

### 设计原则
1. **辨识条件必须接近实际运行工况**：
   - 悬空辨识时必须带载荷（三轮同时转动）
   - 通过除以3将耦合速度还原为单轮真实响应

2. **机械耦合对辨识的影响**：
   - 三轮全向底盘的运动学耦合特性要求特殊处理
   - 简单的单轮独立阶跃辨识会低估载荷影响

3. **代码注释的重要性**：
   - 关键设计决策（如除以3）必须在代码中注释说明物理原理
   - 当前代码缺少注释，容易引发误解

### 避免陷阱
- **不要轻易修改除以3的逻辑**：这是基于底盘机械特性的设计，不是代码错误
- **辨识参数与实际控制的映射关系**：辨识时的耦合条件与运行时的独立控制是一致的

### 改进建议
在 `filter_ident_speed()` 函数添加注释：
```python
def filter_ident_speed(filter_state, raw_ticks):
    """辨识用速度滤波，输出单轮在耦合载荷下的真实响应.
    
    除以3的原因：三轮全向底盘辨识时，三个轮子同时施加阶跃指令，
    速度是耦合的。单轮真实响应 = 测量速度 / 3。
    """
    smooth_raw = filter_state["input_lpf"].update(float(raw_ticks))
    fused_speed, _, _ = filter_state["dual_filter"].update(smooth_raw)
    filtered_speed = filter_state["output_lpf"].update(float(fused_speed))
    return float(filtered_speed) / 3.0
```
