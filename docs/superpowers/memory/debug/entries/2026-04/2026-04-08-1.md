## Title
修复辅车速度模式后续周期退回普通路径的问题

## Background / Issue
辅车已经支持普通跟随模式和 `m=1` 速度模式两个入口，但最近联调发现速度模式只在收包当拍生效，后续周期会把平移输出掉回 `0,0`。同时，“默认持续启用朝向保持、显式角速度例外”的规则只分散在入口拍里，没有被统一收口到周期推进层。当前约束是：不扩大协议面，不处理单位重标定，只在辅车控制链内部用最小改动修复模式持续性与转向规则。

## Change Unit
在辅车运行时内部补齐最小平移模式状态、最小转向来源状态、持续速度目标和手动角速度目标，让 `_tick()` 不再只靠 `follow_active` 猜当前控制路径；普通模式继续走位置目标，速度模式持续走保存下来的速度目标，非显式角速度场景统一持续启用朝向保持，停机/超时/重置会一起清空这些内部状态。

## Actions / Outcome
- 在 `src/assistant/state/__init__.py` 新增最小跨周期控制状态 -> 把平移模式、转向来源、持续速度目标和手动角速度目标收口到 `MotionRuntimeState.control` 下，避免继续靠宽泛开关猜模式。
- 在 `src/assistant/motion_runtime.py` 引入统一模式分发与清理逻辑 -> 速度模式后续周期不再退回普通位置路径，显式角速度接管和撤销后都能按当前模式重新落回自动朝向保持。
- 按 legacy 内核对齐 `src/assistant/motion_runtime.py` 与 `src/assistant/ctrl/kinematics.py` -> 里程积分改为使用姿态更新前朝向，三轮目标改为进速度环前统一按比例缩放，避免逐轮硬截断破坏平移/保头配比。
- 在 `src/assistant/ctrl/pid.py` 为零周期补 legacy 固定拍长回退 -> 保留首拍和保护态的保头输出，同时避免速度环把零周期误当成 1 秒导致过大动作。
- 在 `tests/unit/assistant/test_motion_runtime.py` 补 Task 1 回归测试 -> 固定住普通模式保护、速度模式跨周期持续，以及显式角速度接管/撤销后的周期行为。
- 运行 `python3 -m pytest tests/unit/assistant/test_motion_runtime.py tests/unit/assistant/test_app.py tests/unit/assistant/test_protocol.py tests/unit/assistant/test_runtime_loop.py tests/unit/assistant/test_runtime_params.py tests/unit/assistant/test_stability_baseline.py` -> 117 个测试全部通过。

## Lessons / Refinements
- 对跨周期控制链，`follow_active` 这类宽泛布尔值只能表达“是否激活”，不能同时承担“当前平移模式”和“当前转向来源”的职责。
- 速度模式若要可用，必须把速度目标本身保存成跨周期状态；只在收包当拍写 `velocity_command` 会让后续周期立刻退化。
- 如果要贴 legacy 控制手感，不能只复刻“平移和转向会合成到三轮”这一层，还要把“里程积分的朝向顺序”和“三轮统一限幅”一起对齐；否则编码器积分和保头会在实车上表现出不同的耦合感受。
- 当前架构下允许零周期仍继续保头，但速度环不能直接把零周期当成 1 秒；需要显式回退到固定控制拍长，才能既保留输出又不制造过大动作。
- 最小新增常驻对象也要说明必要性：这次只新增 4 个标量/小元组字段，owner 仍是 `MotionRuntimeState.control`，没有引入模块级运行时全局，也没有把可延后能力重新放回构造期装配。
