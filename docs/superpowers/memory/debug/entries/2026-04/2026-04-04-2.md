## Title
主车轮子方向与控制手感会被映射冲突和固定 dt 一起带偏

## Background / Issue
主车姿态链量级恢复后, 现场继续暴露出两个紧连的问题: 轮子转向与期望相反, 同时在大量打印调试信息时, 原本能工作的参数又会被拖坏。用户通过手动微调参数推断出, 真正的问题不只是参数值, 而是运行时接线映射和控制环时间基准都还没有完全对齐。

## Change Unit
对齐主车正常运行时与已验证 legacy 风格脚本的电机/编码器映射, 并把主车角度环、速度环、前馈统一改成使用同一拍真实 `dt`, 避免“前半段按真实时间走、后半段按固定 5ms 估算”导致方向和手感一起漂移。

## Actions / Outcome
- 对照 `src/master/script/pid_identify.py` 和正常运行时硬件表 -> 确认主车运行时的左右轮电机端口与编码器端口映射, 和已验证的 legacy 风格脚本存在直接冲突, 这是轮子方向异常的高概率根因。
- 修正主车运行时硬件映射 -> 左右轮电机/编码器按已验证脚本顺序重排后, 运行时方向判断不再依赖临时翻符号试错。
- 把实时 `dt` 回写到运行时状态 -> 角度环积分、三个速度环积分和前馈变化率改为共用同一拍真实时间差, 现场“大量打印后必须重新调参数”的现象有了直接根因修复。

## Lessons / Refinements
- 对主车这类板端链路, 已经跑通过的辨识脚本和诊断脚本不仅能验证参数, 也是接线与方向事实的最高可执行参考, 运行时不应再各写一套不同的左右映射。
- 如果姿态积分已经改成动态 `dt`, 那后面的角度环和速度环也必须同步改成动态 `dt`; 否则日志阻塞或其他周期抖动会伪装成“参数软硬不对”。
