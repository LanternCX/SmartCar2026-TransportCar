## Title
收敛辅车 UART6 视觉输入与 UART8 前馈输入的串口调试口径

## Background / Issue
辅车侧 `UART6` 与 `UART8` 之前被收成对称双速度输入，但串口联调继续暴露一个更上层的问题：当前正式职责并不是“双路同类速度”，而是 `UART6` 承接视觉侧 `vx / vy`，`UART8` 承接前馈侧 `vx / vy / omega`。由于代码、开发文档和规则入口里同时存在两套端口职责口径，后续实现和调试都容易被带偏，尤其会把 `UART6` 的 `omega` 也错误带进最终输出。

## Change Unit
把辅车角色层的双路串口输入重新收口为“`UART6` 视觉、`UART8` 前馈、`vx / vy` 裸相加、`omega` 只取 `UART8`、两路都保持上一包”，并同步清理测试、开发文档、规则入口与设计执行文档中的错误口径。

## Actions / Outcome
- 先把 spec 和 plan 重写为统一口径 -> 明确 `UART6` 只消费视觉侧 `vx / vy`，`UART8` 提供前馈侧 `vx / vy / omega`，两路异步读取且保持上一包。
- 先改测试再实现 -> 主机侧先固定“单独视觉可跑、单独前馈可跑、双路裸相加、`omega` 只来自 `UART8`、显式零包只清本路贡献”。
- 在 `follow_runtime.py` 中新增按来源归一化输入 -> `UART6` 收到带 `omega` 的包时不再把该轴写入角色层状态，`UART8` 保持原有 `omega` 贡献。
- 保留现有共享解析边界和共享底盘速度写回入口 -> 没有引入新的同步器、模式开关或超时清零规则。
- 扩充最小诊断快照 -> 可以直接看见 `uart6_velocity`、`uart8_velocity` 和最终输出之间的关系，便于继续上板联调。
- 同步 `docs/developer/control.md`、`docs/developer/vision.md` 和 `strategy-and-control.md` -> 清掉“端口写反”与“对称双速度输入”这类旧口径。
- 运行回归 `python3 -m pytest tests/unit/test_assistant_follow_runtime.py tests/unit/test_assistant_velocity_packet.py tests/unit/test_assistant_velocity_source_state.py -q` -> 42 个测试全部通过，主机侧行为和文档口径一致。

## Lessons / Refinements
- 串口 debug 的第一优先级不是先优化融合公式，而是先收口“哪一路是谁、哪些轴有效、没有新包时怎么保持”这三个事实；这一步不稳，后面的联调现象会持续失真。
- 当角色层和正文文档同时存在两套端口职责口径时，要先统一 spec、测试和规则入口，再改实现；否则很容易把板端症状错误归因到硬件或串口本身。
- 对双路异步输入，当前项目更适合“控制拍收口 + 保持上一包”的同步语义，而不是报文配对或等待两路同时更新。

## Integration Summary
这次变更形成了一个完整的串口调试闭环：先纠正文档和设计里的端口职责，再用失败测试锁定新语义，随后把角色层输入归一化到“视觉只给 `vx / vy`、前馈给 `vx / vy / omega`”，最后用回归测试和最小诊断确认行为已和当前正式口径一致。后续继续上板联调时，应直接沿用这套口径检查单路视觉、单路前馈、双路异步和显式零包四类场景。
