## Title
用交叉编译避开 PR#56 注释引发的板端编译期内存峰值

## Background / Issue
PR#56 给 `src/` 目录补充了更详细的注释后，上板测试触发 issue #57：板端出现类似内存泄漏的现象。后续确认问题不在运行期控制链，而在 MicroPython 板端编译阶段。`#` 注释会在词法分析阶段丢弃，但三引号文档字符串会进入语法分析阶段，虽然最终会被丢弃，仍会在板端编译期短暂抬高内存峰值；非 docstring 的字符串也可能作为普通字符串进入编译流程后再被丢弃。RT1021 板端内存余量不足时，这类编译期峰值会表现为上板后内存异常。

## Change Unit
PR#56 在补充 `src/` 注释的同时，接入 `mpy-cli-dev` 的交叉编译上传流程，让主要运行代码在电脑侧先编译为 `.mpy`，板端部署时优先加载编译产物，从而绕过板端运行时编译源码注释导致的内存峰值。

## Actions / Outcome
- 确认 issue #57 的根因是注释导致的板端编译期内存峰值 -> 不再按运行期内存泄漏或控制链异常排查
- 在 `mpy-cli-dev` 增加交叉编译支持 -> 通过电脑侧 `mpy-cross` 预编译降低板端编译压力
- 调整当前仓库的 mpy-cli 文档和规则入口 -> Agent 部署时知道优先使用交叉编译流程
- 调整板端入口脚本分发逻辑 -> 存在 `.mpy` 产物时优先加载编译后的脚本，同时保留 `main.py` 作为启动入口
- 调整命令模块自动发现逻辑 -> 串口命令和查询处理器在 `.mpy` 部署结构下仍能完成注册
- 保留串口协议紧凑回包格式 -> 注释格式化与部署结构调整不影响上位机或串口侧解析
- 完成本地测试和板端交叉编译部署验证 -> 车端姿态保持与串口命令响应正常

## Lessons / Refinements
- MicroPython 的“注释引发内存问题”要区分 `#` 注释、docstring 和普通未使用字符串；真正危险的是板端编译期峰值，不一定是运行期对象长期滞留
- 大量补充文档字符串前，要考虑目标板是否会在板端编译源码；低内存板应优先走电脑侧交叉编译
- `.mpy` 部署会改变模块发现和入口加载方式，修复内存峰值时必须同步验证启动入口、命令注册和串口回包格式
