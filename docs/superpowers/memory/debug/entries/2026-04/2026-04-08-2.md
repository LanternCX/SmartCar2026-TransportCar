## Title
上调辅车位置式固定平移速度上限以扩大单窗口位移

## Background / Issue
辅车位置式跟随链最近联调时暴露出“在 150ms 有效窗口内走不够远”的问题。前序排查已经确认当前瓶颈不是协议失效、也不是位置式没有持续执行，而是位置式平移速度上限固定值偏低。当前约束是：继续保留位置式、继续保留 150ms 硬停边界、不引入动态调速规则、不改协议，也不同时改位置比例项。

## Change Unit
把辅车位置式跟随默认平移速度上限从 1.5 上调到 3.0，并用主机侧回归固定住“只改这一个参数”的边界，同时把对应 spec 标记为 archive、plan 勾选完成。

## Actions / Outcome
- 在 `tests/unit/assistant/test_runtime_params.py` 补默认上限回归 -> 固定 `FOLLOW_POSITION_MAX_SPEED` 默认值已上调到 3.0
- 在 `tests/unit/assistant/test_motion_runtime.py` 补大误差位置式输出上限回归 -> 固定位置式在默认配置下会按 3.0 限速, 而不是旧值 1.5
- 在 `src/assistant/runtime_params.py` 只上调 `FOLLOW_POSITION_MAX_SPEED` -> 未改协议、超时窗口、位置比例项和其它控制分支
- 运行 `python3 -m pytest tests/unit/assistant -q` -> 154 个测试全部通过
- 在 `docs/superpowers/specs/archive/PR#33/2026-04-08-assistant-follow-position-speed-cap-design.md` 标记 `archive` 并把对应 plan 勾选完成 -> 后续若再讨论新的跟随设计, 应新开 spec 而不是覆写这份文档

## Lessons / Refinements
- 当位置式跟随表现为“单窗口位移不足”时, 应先检查固定平移速度上限, 不要直接把问题混成协议、超时窗口或控制模式设计问题
- 若用户明确要求减少联调变量, 优先只动一个固定参数, 再用回归测试钉死“没有顺手扩大改动面”的边界
