## Title
主车高频控制诊断会放大串口热路径并触发 UART3 写超时

## Background / Issue
主车在板端排查控制周期异常时，先后加入了逐拍周期打印和分段耗时诊断。实测日志显示 `control_profile` 中多段耗时同时异常偏大，并在 `app.py -> uart3.write_line()` 路径上触发 `OSError: [Errno 116] ETIMEDOUT`。当前约束是：先恢复可用的主车调试基线，不扩大到 UART 驱动重写或整条主辅架构重构。

## Change Unit
把主车控制周期诊断从热路径内的分段取时与逐拍输出，收口为外层循环的轻量总时长汇总；保留低频 `control_profile` 观察口径，但不再让诊断本身持续放大 `UART3/UART6/UART8` 热路径负担。

## Actions / Outcome
- 复核板端现象与仓库实现 -> 确认异常发生在主车为诊断新增多次取时与高频输出之后，`UART3` 写超时是这轮被放大的主症状。
- 收轻 `src/master/app.py` 单拍逻辑 -> 去掉内部 `perf_diag` 分段统计，避免在主车热路径里反复取时和拼装分段结果。
- 收轻 `src/master/main.py` 控制诊断 -> 保留低频 `control_profile` 汇总，但只记录外层周期和单拍总时长，不再逐拍打印，也不再依赖内部阶段明细。
- 同步主车回归测试口径 -> 更新 `tests/unit/master/test_app.py`、`tests/unit/master/test_runtime_loop.py`、`tests/unit/master/test_decision.py` 等相关断言，使其与当前按轴跟随和轻量诊断语义一致。
- 运行 `python3 -m pytest tests/unit/master/test_vision_state_machine.py tests/unit/master/test_decision.py tests/unit/master/test_app.py tests/unit/master/test_runtime_loop.py tests/unit/master/test_runtime_params.py tests/unit/master/test_protocol.py -q` -> 77 个测试全部通过。

## Lessons / Refinements
- RT1021 这类板端性能排查应优先使用低频外层汇总，避免把分段取时和逐拍打印直接塞进高频控制热路径；否则诊断数字会和真实控制负担互相污染。
- 当现场同时在讨论“当前 bug”与“是否切架构”时，应先恢复一条不失真的运行基线，再用新的实测数据判断是否值得做更大重构。
