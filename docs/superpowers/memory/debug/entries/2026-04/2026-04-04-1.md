## Title
主车运行时姿态口径必须对齐 inspect_attitude 的 yaw_deg

## Background / Issue
主车悬空手动旋转 30 到 90 度时, 运行时打印出来的朝向变化量明显不对, 导致角度环输出远小于预期。用户明确要求现场判断必须以 `src/master/test/inspect_attitude.py` 已验证通过的 `yaw_deg` 口径为准, 不能再混用别的朝向口径。

## Change Unit
把主车运行时姿态更新链改成与 `inspect_attitude.py` 同一套口径: 陀螺仪先按同样方式归一化, 四元数按弧度推进, 每拍用真实时间差积分, 并补充板端实际加载辨识参数的调试输出, 方便后续继续核对控制链前半段是否进入正确量级。

## Actions / Outcome
- 对照 `src/master/test/inspect_attitude.py` 与运行时姿态链 -> 确认原运行时仍混用了固定 `tick_s` 和不同的朝向观察口径, 会把大角度手动旋转场景压成接近零误差。
- 重写 `update_heading_from_gyro()` -> 运行时改为按真实 `dt`、同样的角速度归一化和四元数更新路径推进, 现场朝向量级恢复到和独立验证脚本一致。
- 增加 `ident_lookup_loaded` 调试输出 -> 确认板端实际读到了 `/flash/ident_params.txt` 中的三轮辨识参数, 排除“前馈文件没加载”的假设。

## Lessons / Refinements
- 主车姿态链联调时, 现场观测口径必须先和已验证脚本统一, 尤其要以 `inspect_attitude.py` 的 `yaw_deg` 为准, 不要把连续累计角和当前偏航角混着看。
- 当板端现象和理论量级明显对不上时, 先确认运行时是否真的沿用了同一套时间基准和角速度归一化方式, 再讨论参数软硬。
