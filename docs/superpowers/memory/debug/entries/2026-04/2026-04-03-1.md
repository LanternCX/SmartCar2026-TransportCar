## Title
梳理主车板端导入链、采样链与朝向保持链的关键坑点

## Background / Issue
本轮在主车板端持续排查“上电后主循环已运行但轮子不转、姿态与保持链表现异常”的问题。用户要求在重置上下文前，把已经确认的失败点、根因和当前状态沉淀到 memory，便于后续继续接上。

## Change Unit
沉淀这一轮板端调试中已经确认的关键坑点，包括板端缺失模块、平铺运行导入边界、`demo v3.0` 采样方式、朝向保持目标被重复刷新，以及独立姿态诊断脚本的已确认问题。

## Actions / Outcome
- 排查板端启动入口导入失败 -> 确认 `os.path`、`types`、`__package__`、`__spec__`、`__file__` 这些假设在板端都不稳，入口必须按平铺上传方式写直接导入路径，不能依赖临时伪造包对象。
- 排查 IMU/编码器采样 -> 确认 `seekfree_demo/v3.0.0` 与 `legacy` 都要求先建立 `ticker.capture_list(...)` 采样触发链，且 `get()`/数据引用应在初始化时绑定，不应在每拍重复重取。
- 排查主车不补偿朝向 -> 通过精简日志确认 `heading` 在变但 `target_heading` 跟着一起变，导致误差恒为 0；根因是连续收到 `hold` 时重复执行了 `capture_heading_target()`。
- 对照 `demo v3.0` 与 `legacy` -> 确认编码器读取、电机驱动、串口读写当前没有发现和 IMU 同级别的调用方式错误；编码器分频按用户要求保持默认值，不额外自定义。
- 排查独立姿态诊断脚本 -> 确认脚本最初存在三个问题：板端直接运行时还按 `master.xxx` 导入、积分步长用固定 `tick_ms` 代替动态 `dt`、欧拉角输出未明确标出 `roll/pitch/yaw` 名字。
- 核对零漂校准链 -> 确认当前主线会加载 `/flash/gyro_offset.txt` 并在 `read_calibrated()` 中减偏移，单位缩放链也是通的；但 `src/master/script/calibrate_gyro.py` 目前仍是空壳，尚不可用。

## Lessons / Refinements
- 板端脚本与入口默认按“平铺文件直接运行”设计，不能假设主机侧包结构、标准库完备度或运行时内建名字一定存在。
- 对 `IMU660RX` / `encoder` 这类设备，`demo v3.0` 的调用语义要逐项对齐：采样触发链、数据引用绑定、时间步长来源都不能靠猜测补。
- 朝向保持类问题不能只看陀螺仪是否出数；要同时看 `heading`、`target_heading`、补偿输出和目标轮速，才能看出是传感器链还是控制目标链出错。
- 参数辨识不会解决“补偿链根本没有启动”的问题，应先修正目标锁定和采样/积分链，再做辨识。
