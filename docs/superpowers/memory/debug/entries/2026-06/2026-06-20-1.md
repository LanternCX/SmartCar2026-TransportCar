## Title
收敛回库 Play 第 2 步黄线就绪事件早到与 gate 控制失效的问题

## Background / Issue
主辅车回库改成 `Play` 接管后, 现场出现“都能进入第 2 步, 但跳不到第 3 步”的问题。调试日志显示旧的 `RETURN_LINE_ALIGNED=10` 会在第 2 步 gate 打开之前到达; 之后即使车继续前进到黄线, 也没有新的事件触发。进一步联调发现视觉侧虽然已接入 gate 开关逻辑, 但 `LOCAL_VISION_CONTROL` 的 TCP 控制帧没有被扫描入口识别, 同时 ACK topic 也回错, 导致车端只能看到 `master_gate: start action=3`, 看不到 `done action=3`。

## Change Unit
把回库第 2 步的黄线判据收口为“只在 gate 打开期间按 yellow touch 触发一次可靠事件”, 并补齐车端到视觉端的 gate 控制链路、ACK topic、运行时日志和 `v2` 旧回库残留清理。

## Actions / Outcome
- 在车端保留 gate/ready 日志 -> 确认旧事件先于第 2 步 gate 打开到达, 不是 `until` 回调本身失效。
- 把 `yellow_line_ready` 清空动作挂到第 2 步 `on_enter` -> 旧 ready 不再直接带过第 2 步。
- 给所有 `_BaseStep` 子类统一增加 `on_enter/on_exit` -> 具体回库 Play 可以在第 2 步进入时开 gate, 离开时关 gate。
- 回库 ready 判据从旧的线中心/回退滤波改成 yellow touch -> 主辅都统一复用 touch 口径, 不再依赖 `line_y` 跟踪。
- 在车端协议里增加 `LOCAL_VISION_CONTROL_RETURN_LINE_GATE_ON/OFF` -> 第 2 步显式打开/关闭视觉判定窗口。
- 在视觉 `main_v2.py` 中接入 gate 开关 -> 只有 gate 打开时才允许产出 `RETURN_LINE_ALIGNED`。
- 修复视觉侧 `_find_control_frame_start(...)` 不识别 `TCP + LOCAL_VISION_CONTROL` -> gate 控制帧能被真正消费。
- 修复视觉侧 gate 控制 ACK 回错 topic -> 车端能看到 `done action=3/4`。
- 清理 `v2` 中旧回库线中心识别、上一帧回退滤波和相关测试口径 -> `v2` 只保留 touch ROI 判据、gate 开关和 `RETURN_LINE_ALIGNED`。

## Lessons / Refinements
- `Play` 第 2 步之后才生效的视觉事件, 不能只靠状态编号猜测, 必须由步骤生命周期显式开关判定窗口。
- 现场看到 `start action=3` 但看不到 `done action=3`, 优先怀疑控制帧扫描入口或 ACK topic, 不要先怀疑判据本身。
- 可靠控制链路除了发包逻辑, 还要同时核对“扫描入口识别”和“ACK topic 是否匹配”, 任何一处漏掉都会表现成 silent fail。
- `v2` 收口后, 旧回库线中心识别和上一帧回退滤波不应继续保留在正式主线里, 否则会干扰对当前策略的判断。
