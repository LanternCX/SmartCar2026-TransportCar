## Title
收敛回库黄线状态卡在后退段的问题

## Background / Issue
主车完成搬运后能进入 `RETURN_GARAGE_RETREAT`, 并成功向视觉同步 `state=6 target=3 arg=5`, 但车一直后退, 没有切到 `RETURN_GARAGE_LINE`。现场现象显示黄线能被看到, 但主车没有收到黄线对正事件。

## Change Unit
让回库黄线视觉判定、坐标口径和正式上下文同步收敛到同一套流程: 黄线识别复用已调黄色阈值, 黄线 Y 与目标 Y 使用同一矫正坐标, 后退段按越过目标触发事件, 同时删除只为现场调试加入的默认上下文和额外显示/日志。

## Actions / Outcome
- 在主车增加临时视觉事件日志 -> 确认主车已进入回库后退并完成视觉上下文同步, 但没有收到 `EVENT_RETURN_LINE_ALIGNED=10`。
- 在视觉端临时显示黄线识别状态 -> 确认 `line_y` 能计算但曾与目标 Y 混用不同坐标口径。
- 修改后退段判定 -> 回库后退时黄线 Y 越过目标值即发 `EVENT_RETURN_LINE_ALIGNED`, 不再要求落在窄容差窗口内。
- 复用 `FINISH_HOOK_YELLOW_THRESHOLD` -> 回库黄线识别不再使用临时硬编码 RGB 判断。
- 统一黄线 Y 坐标口径 -> 黄线检测值、目标值和事件判定使用矫正后的 Y, 需要画面显示时再转换回图像坐标。
- 删除调试入口残留 -> 视觉端不再上电默认进入黄线识别上下文, 避免占用 `context_id` 历史并阻止主车第一次正式同步。
- 删除临时日志和画面叠加 -> 保留普通状态跳转和同步日志, 不把现场调试输出留进正式流程。

## Lessons / Refinements
- 调试用默认上下文不能留在正式视觉入口里; 即使主车收到了 ACK, 视觉也可能因为本地 `last_context_id` 或待确认事件停在调试上下文。
- 视觉调试值、目标值和画面叠加必须先确认坐标口径; 不能把原始图像 Y、反装矫正 Y、协议 Y 混着比较。
- 现场临时日志要在闭环后删除, 只保留和其他流程一致的状态跳转/同步日志。
- 看到主车 `sync done` 只能证明视觉回了 ACK, 不能证明视觉后续事件一定会按预期发出; 需要同时检查视觉上下文是否真实应用。
