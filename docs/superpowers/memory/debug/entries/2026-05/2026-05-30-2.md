## Title
修复通信发送热路径重复导入导致的控制周期拉长

## Background / Issue
固定短帧通信接入后, 板端控制周期日志显示主循环稳定拉长到约 39ms, 怀疑通信改动引入阻塞。分段计时显示接收路径与底盘控制本身耗时较小, 主要耗时集中在发送段。

## Change Unit
把通信发送路径和主辅角色运行时的时间模块导入从函数内移动到模块加载期, 避免 `poll_tx()` 高频发送路径反复动态导入 `time`。

## Actions / Outcome
- 先用板端日志拆分 `rx / step / tx` 耗时 -> 确认主要耗时集中在 `tx`, 曾稳定达到 30ms 以上。
- 继续拆分 `poll_tx / encode / uart.write` 耗时 -> 确认编码与串口写入耗时很小, 慢点集中在发送准备路径。
- 将 `protocol.transport`, `vision.master.forward_runtime`, `vision.assistant.follow_runtime` 中的函数内 `import time` 移到模块级 -> 板端发送耗时从 30ms 量级降到 0.1ms 量级, 主循环回到约 5ms 附近。
- 删除临时诊断日志与统计字段 -> 最终提交只保留热路径导入修复。

## Lessons / Refinements
- MicroPython 热路径中的函数内导入可能造成毫秒级阻塞, 高频控制链和通信调度链应避免重复动态导入。
- 诊断实时问题时先用低频分段计时定位边界, 再逐步缩小到单个函数调用; 收口前必须删除诊断日志, 避免调试本身继续放大周期抖动和内存压力。
