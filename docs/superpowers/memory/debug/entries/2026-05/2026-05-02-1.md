## Title
收敛主车视觉 hook 底边判据与纵向速度饱和问题

## Background / Issue
主车单车链路接入视觉 hook 后，主车能够进入绕行，但现场联调暴露两个连续问题：一是 `TARGET_FOUND` 跳转等待时间异常；二是主车视觉纵向速度在底边目标切换后长期输出最大值，随后又出现目标越近输出越大的反向现象。当前调试范围限定为主车单车链路，不控制辅车状态，不扩大到辅车子状态机。

## Change Unit
把主车单车状态机、主车本地视觉 hook 可靠链路和主车 OpenART 搜索底边判据收口到同一个可联调闭环：主车进入 `SEARCH_OBJECT` 后建立 hook，视觉用归一化底边判断目标，命中后主车进入 `ORBITING` 并使用 rear only 绝对 `+90°` 绕行。

## Actions / Outcome
- 在主车 RT1021 侧新增 `IDLE -> SEARCH_OBJECT -> ORBITING -> IDLE` 状态机 -> hook 上下文、视觉事件确认和 rear only 绕行由主车维护。
- 在主车角色运行时接入本车 `UART6` 的 `s/a/r/v` 语义 -> hook 确认、命中事件和搜索速度在同一角色周期内收口。
- 在共享底盘补充 rear only 绝对角度入口 -> `ORBITING` 使用上电基准航向 `+90°`，绕行结束后回到零输出。
- 在 OpenART Vision master 中保留归一化底边量 -> 纵向目标使用图像底边，候选选择和 hook 判据使用同一底边语义。
- 将主车纵向搜索速度按图像高度缩放 -> 目标接近图像底边时 `vy` 绝对值变小，避免大部分距离区间固定输出最大值。
- 用回归测试固定“目标越近纵向速度越小” -> 避免再次把真实底边量和当前搜索坐标量混用。
- 同步 `docs/developer/protocol.md`、`state.md`、`control.md` 和 `vision.md` -> 正式文档描述当前 hook、底边、绕行和可靠事件语义。
- 运行 TransportCar 回归 `python3 -m pytest tests/unit tests/contract -q` -> 160 个测试通过。
- 运行 Vision 回归 `PYTHONDONTWRITEBYTECODE=1 python3 -m pytest tests/unit tests/contract -q -p no:cacheprovider && python3 -m py_compile master/main.py assistant/main.py` -> 69 个测试通过，主车和辅车入口编译通过。

## Lessons / Refinements
- 视觉坐标调试必须先用现场单调性校验：目标靠近时控制量应按预期减小，仅靠“底边数值接近目标”单元测试不足以发现方向反了。
- 改视觉底边判据时要同时覆盖候选选择、搜索速度和 hook 命中三个入口；只验证 hook 命中会漏掉速度输出饱和问题。
- 对高频视觉速度输出，像素误差切到图像底边目标后要重新检查输出尺度；原有 `kp` 和限幅组合可能让控制量长期饱和。
- 单车调试阶段应把辅车控制排除在变更外，避免把主车 hook、视觉底边和主辅状态同步混到同一个故障面。
