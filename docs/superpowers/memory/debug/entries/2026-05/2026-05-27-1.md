## Title
修复绕行视觉同步沿用搜索上下文导致 OpenART 继续输出搜索速度

## Background / Issue
主车接入绕行视觉修正后，现场把 `ORBIT_VISION_CORRECTION_ENABLED` 打开时，绕行阶段持续出现“一顿一顿”的表现。按视觉仓库默认参数，绕行修正的增益为零，理论上绕行阶段不应持续收到搜索语义的速度。联调中打印主车 `UART6` 原始速度行后，确认绕行阶段仍在持续收到 `v,0,-2`、`v,-2,-2`、`v,0,2` 这一类搜索速度。

## Change Unit
把主车进入绕行时的本车视觉同步从“复用搜索阶段上下文编号”修正为“先分配新的上下文编号，再下发绕行视觉同步”，并把相关状态机与运行时回归统一到新的上下文序列：搜索 `1`、绕行 `2`、绕行后搜索 `3`、搬运结束 hook `4`、收尾后重启搜索 `5`。

## Actions / Outcome
- 在主车角色层打印绕行阶段收到的 `UART6` 原始速度行 -> 确认问题不是底盘把零修正算成非零，而是视觉端持续发送搜索速度。
- 复核 OpenART master 的上下文应用规则 -> 确认视觉端对相同上下文编号做重复包处理，只回 ACK，不切换到新的绕行配置。
- 对照主车状态机和运行时同步链路 -> 确认进入绕行时下发的视觉同步沿用了搜索阶段上下文编号，导致 OpenART 继续运行搜索模式。
- 在主车状态机里进入 `ORBITING` 前先递增当前上下文编号 -> 绕行视觉同步获得独立上下文，OpenART 能正确切换到绕行配置。
- 补充“绕行视觉同步必须使用新上下文”的回归测试，并统一调整后续阶段上下文预期 -> 固定住完整序列，避免后续再把绕行和搜索共用同一编号。
- 清理临时调试日志并回跑主机侧相关测试 -> `tests/unit/vision/test_master_state_machine.py`、`tests/unit/runtime/test_master_forward_runtime.py`、`tests/unit/runtime/test_assistant_follow_runtime_velocity_flow.py`、`tests/unit/core/test_runtime_public_api.py` 共 182 个测试通过。

## Lessons / Refinements
- 视觉状态切换类问题先打印角色层真正收到的原始串口行，再判断是视觉端没切模式还是车端算错控制量；先打底盘内部量很容易误判。
- 对 OpenART 这类带上下文去重的同步链路，新语义必须占用新的上下文编号；只换状态字段不换上下文编号，接收端可能按重复包直接丢弃。
- 只给“开关打开后行为变化”下结论不够，必须同时核对“速度是否真的来自当前模式”这条边界；高频速度包如果没有模式标签，就要靠上下文编号保证模式切换成立。

这次闭环把“角色状态切换”和“视觉上下文切换”重新绑在了一起：主车从搜索进入绕行时，必须先切换到新的视觉上下文，再让 OpenART 接收绕行修正任务。后续只要增加新的本车视觉模式，都应先检查该模式是否拥有独立上下文编号，以及接收端是否会把相同编号当作重复包直接忽略。
