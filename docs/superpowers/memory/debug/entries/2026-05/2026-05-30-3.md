## Title
修复 CLEAR 后退位置锁被可靠事件零速度覆盖的问题

## Background / Issue
主车进入 CLEAR 阶段后, 车模大概率不后退, 但偶尔能触发后退。初步测试显示 CLEAR 后退目标会下发, 底盘也能生成 Y 负方向控制命令, 问题只在长测和真实事件时序下暴露。

## Change Unit
让主车可靠业务事件到达时只清掉旧视觉速度缓存, 若底盘正在执行位置或角度锁定动作, 不再写入零速度覆盖当前锁定目标。

## Actions / Outcome
- 在 CLEAR 阶段加临时日志 -> 确认状态机已收到辅车同步确认, 并且下发了后退位置目标。
- 在底盘目标写入和解锁路径加临时日志 -> 确认后退目标不是被里程计误判完成, 而是可靠事件到达后调用零速度写入, 清掉了位置目标并释放锁。
- 修改 `_clear_local_velocity_for_reliable_event()` -> 可靠事件仍更新 UART6 速度缓存版本, 但 `command_lock=True` 时跳过零速度写入。
- 补充回归测试 -> 固定“可靠事件不能覆盖正在执行的锁定位置目标”和“CLEAR 流程确实下发主车后退目标”。
- 删除临时日志 -> 最终提交只保留行为修复和回归测试。

## Lessons / Refinements
- 可靠事件清旧速度缓存和向底盘写零速度是两个不同动作; 前者是通信输入边界, 后者会改变底盘执行目标, 在位置锁定期间不能混在一起。
- 调试状态机动作丢失时, 先确认目标是否下发, 再看 `command_lock` 是否被其他输入覆盖; “没动”不一定是状态没到, 也可能是动作刚发出就被后续输入清空。
- 板端定位日志要覆盖跨层边界: 角色同步确认、目标写入、锁定状态、目标清空来源。收口前删除临时日志, 用回归测试保留结论。
