# 2025 智能车蚂蚁搬家组 - 搬运车模代码

## 项目概述

这是一个基于 RT1021 微控制器的全向轮搬运车控制系统。车模支持通过串口消息在 `x`、`y`、`w` 三个自由度上进行速度模式和位置模式的灵活控制，具备完整的电机参数辨识、陀螺仪校准、多层滤波和级联 PID 控制的控制框架。

### 主要特性

- **三轴独立控制**：支持 `x` 轴（横向）、`y` 轴（纵向）和 `w` 轴（旋转）三个方向的独立速度或位置控制
- **双模式控制**：
  - **速度模式**：直接指定目标速度，车模保持运动
  - **位置模式**：指定目标位置/角度，车模自动规划轨迹并锁定
- **全向运动能力**：采用三轮福来轮布局，支持任意方向运动
- **自动姿态保持**：当角速度接近 0 时自动进入角度保持模式，保证车模不会因干扰而出现航向角漂移
- **参数辨识与校准**：直流电机（无电流环）的参数辨识和自动陀螺仪零飘校准
- **多层滤波架构**：编码器采用中值滤波、双窗口线性回归滤波等多种滤波方案
- **级联 PID 控制**：位置环串接速度环，双串级 PID
- **运动锁定机制**：对于相对运动指令等重复发送导致命令结果累加的，继而导致运动状态出现非预期变化的命令，进行加锁
- **无线调试支持**：通过 UART3 无线串口实时监听协议，便于在线调试

## 开发和配置指南

### 前置要求

1. **电机参数辨识**（每次更换地面或配重后）
   - 运行 [pid_identify.py](pid_identify.py) 进行电机特性自动辨识
   - 系统将自动计算前馈增益（gain）和时间常数（Tau），保存到 `/flash/ident_params.txt`
   - 这使得后续速度控制能够利用前馈补偿，提高速度环的响应速度
   - 把拨码开关（具体哪个我忘了）打开之后再上电就会进入参数辨识模式，车模会旋转几圈采集数据
   
2. **陀螺仪零飘校准**（首次部署和定期校准）
   - 运行 [calibrate_gyro.py](calibrate_gyro.py)，在车模完全静止的情况下校准陀螺仪零点
   - 校准结果保存到 `/flash/gyro_offset.txt`
   - 不进行此步骤会导致航向角漂移

### 核心控制流程

```
1. TransportCar 初始化
   ├─ 硬件初始化（UART、IMU、电机、编码器）
   ├─ 参数加载（电机辨识参数、陀螺仪零偏）
   ├─ 滤波器初始化
   └─ PID 控制器初始化

2. 定时器启动（5ms 周期）
   └─ pit1.callback(car.mark_tick) 触发 car.step()

3. 每周期执行 step()
   ├─ 读取传感器数据（编码器、IMU）
   ├─ 编码器滤波 + 速度计算
   ├─ IMU 姿态解算（四元数积分）
   ├─ 里程计更新（位置和航向角）
   ├─ 指令接收与解析
   ├─ 速度/位置模式切换和锁定逻辑
   ├─ PID 计算（位置环 → 速度环 → 电机输出）
   └─ 运动学逆解（机器人速度 → 三轮轮速）

4. 电机驱动 + UART 反馈
```

## 控制模式详解

### 速度模式（Velocity Mode）

指定目标速度，车模以该速度持续运动：

```
vx=10, vy=5         # X、Y 轴速度（脉冲/周期）
omega=5              # 角速度（rad/s）
```

当 `omega` 接近 0 时（< `HOLD_SPEED_EPS`），系统自动进入**角度保持模式**，即：
- 保持当前航向角不变
- 对航向角偏差使用 PID 反馈控制自动纠正
- 防止车模因外界干扰而漂移

### 位置模式（Position Mode）

车模自动规划轨迹并锁定在目标位置/角度：

#### 绝对位置模式
```
x=1.0, y=0.5        # 世界坐标系目标位置（米）
angle=45            # 目标航向角（度）
```

#### 相对位置模式
```
dx=0.5, dy=0.3      # 相对车身坐标系的增量（米）
d_angle=30          # 相对目标角度的增量（度）
```

**位置控制流程**：
1. 计算位置偏差（目标 - 当前）
2. 位置环 PID 计算目标速度（增益 `POS_KP`，限幅 `POS_MAX_SPEED`）
3. 目标速度传入速度环进一步 PID 计算
4. 当位置偏差 < `POS_TOLERANCE` 且速度 < 阈值时，认为到达并进入锁定状态

### 运动锁定机制（Motion Lock）

为了防止相对运动指令（`dx`、`dy`、`d_angle`）重复发送时命令累加，系统引入运动锁定：

- **进入锁定**：发送相对位置指令或切换后轮模式时（详见[遥控协议](##遥控协议)部分）
- **锁定期间**：所有新的运动控制指令都被丢弃，直到运动完成
- **解除锁定**：位置到达且速度静止，或收到新的绝对位置指令

可通过 `?lock` 查询当前锁定状态

可以借助 `?lock`命令，在每次发送命令的时候查询 `?lock`实现同步消息控制，具体参考 ART 的代码

## 遥控协议

支持对 UART3 或者 UART6 发送下符合格式的字符串进行控制。

格式使用键值对 (Key-Value) 格式进行控制。

推杆指向的方向是 `y+`（纵向）。其余单位方向遵循右手系。也就是 `x+` 是右移（横向），`w+` 是顺时针旋转。

### 键值对格式说明

| 参数标签 | 说明 | 单位 | 模式 | 备注 |
| :--- | :--- | :--- | :--- | :--- |
| **vx** | 车身坐标系 X 轴向速度 | 编码器脉冲 | 速度 | 范围限制在 `[-V_CMD_MAX, V_CMD_MAX]` |
| **vy** | 车身坐标系 Y 轴向速度 | 编码器脉冲 | 速度 | 范围限制在 `[-V_CMD_MAX, V_CMD_MAX]` |
| **omega** / **w** | 目标角速度 | rad/s | 速度 | 接近 0 时自动进入角度保持模式 |
| **x** | 世界坐标系 X 目标位置 | 米 | 位置（绝对） | 触发绝对位置模式 |
| **y** | 世界坐标系 Y 目标位置 | 米 | 位置（绝对） | 触发绝对位置模式 |
| **dx** | 车身坐标系相对位移 X | 米 | 位置（相对） | 触发运动锁定，防止指令累加 |
| **dy** | 车身坐标系相对位移 Y | 米 | 位置（相对） | 触发运动锁定，防止指令累加 |
| **angle** / **yaw** | 目标航向角 | 度 | 位置（绝对） | 绝对角度指定 |
| **d_angle** / **dyaw** / **da** | 相对航向角 | 度 | 位置（相对） | 触发运动锁定 |
| **rear** | 后轮单轮模式 | - | 模式切换 | `rear=1` 启用，`rear=0` 禁用；切换时触发运动锁定 |
| **reset** | 重置状态（设置零点） | - | 系统 | 发送 `reset` 或 `reset=1`：将里程计位置(x,y)及航向角归零，也就是设置当前状态为零点 |
| **print** | 打印字符串 | - | 系统 | `print=Hello World`：由 uart6 接收并通过 uart3 打印 |

### 信息查询（Query Interface）

通过发送 `? + token` 的形式向 UART6 查询当前运行状态：

| 查询指令 | 返回格式 | 含义 | 备注 |
| :--- | :--- | :--- | :--- |
| **?pos** | `?pos=x,y,yaw` | 当前世界坐标和航向角 | 位置与角度精度为浮点数 |
| **?lock** | `?lock=0/1` | 当前是否处于位置锁定状态 | 0=解锁，1=锁定 |

### 使用示例

```
# 速度控制：沿 Y 轴向前运动
vy=10

# 位置控制：移动到 (1.0, 0.5)，同时转向 45°
x=1.0, y=0.5, angle=45

# 相对位置：相对当前位置向前移动 0.3m
dy=0.3

# 查询位置
?pos

# 重置起点
reset=1
```

### 命令优先级与互斥

- **位置指令 > 速度指令**：如同时发送位置和速度指令，位置指令获得优先处理
- **绝对位置 > 相对位置**：相对位置指令会触发运动锁定，防止重复执行
- **速度模式与位置模式互斥**：发送位置指令会切换至位置模式，相反亦然

> **重要**：`x/y/dx/dy/angle/d_angle` 为位置控制逻辑，`vx/vy/omega` 为速度控制逻辑

## 控制算法

### 前馈 + 反馈两层控制结构

```
目标速度 → 前馈补偿 + 速度环 PID 输出 → PWM 占空比 → 电机
                     ↑
                  编码器反馈
```

- **前馈**：基于电机参数辨识结果（增益 `K` 和时间常数 `tau`），预测目标转速所需的 PWM 占空比，也就是通过参数辨识计算出一个估计的目标速度到电机占空比的映射关系，在无负载的情况下是很准的，但是有负载的时候还是需要通过闭环控制来补偿。
- **速度环**：使用编码器反馈的实际速度通过 PID 控制进行修正，在代码中是一个带有二次 P 项目的 PD 环

由于全向轮的性质，实际上车模在运动过程中各轮的阻尼存在各向异性，也就是在每个运动方向上的阻尼并不一致，前馈也因此并不准确。

### 编码器滤波与速度计算

N20 自带的八线霍尔编码器精度和稳定性都没有，因此采用多层滤波策略通过离散的速度样本估计真实速度：
1. **中值滤波**：去除随机脉冲干扰
2. **双窗口线性回归滤波**：对脉冲序列进行线性拟合，提高速度计算精度
3. **差分限幅滤波**：限制单周期速度变化率，防止陡峭跳变

### IMU 姿态解算（四元数积分）

```
IMU 原始数据（加速度 + 角速度）
     ↓
四元数积分（每周期更新）
     ↓
四元数 → 欧拉角（Yaw/航向角）
```

## 参数辨识

### 电机参数辨识（`pid_identify.py`）

目的：自动测定电机的动态特性（增益和时间常数），用于前馈补偿

**流程**：
1. 给电机施加阶跃 PWM 指令（`IDENT_STEP_DUTY = 5000`）
2. 在 4 秒内采集编码器反馈数据
3. 使用系统辨识算法（IMC 方法）拟合直流电机无速度环的一阶模型：`G(s) = K / (1 + tau*s)`
4. 计算三个轮参数（K 和 tau）之后保存到 `/flash/ident_params.txt`

**建议进行参数辨识的情况**：

- 首次部署
- 每次更换地面（影响摩擦力）
- 每次调整配重（改变转动惯量）

**输出**：

- `ident_params.txt`：含 `K` (增益) 和 `tau` (时间常数)
- `pid_params.txt`：自动计算的 PID 参数，不过这个并没有在代码中使用

### 陀螺仪零飘校准（`calibrate_gyro.py`）

目的：测定陀螺仪在静止状态下的输出偏差，用于姿态解算补偿

**流程**：
1. 采集 2000 个 IMU 样本（车模完全静止）
2. 计算各轴平均值和标准差
3. 保存陀螺仪三轴零点到 `/flash/gyro_offset.txt`

**重要**：
- 校准前必须平放车模
- 保持车模绝对静止（建议放在平稳的平面上）
- 周期采样 2ms × 2000 = 4 秒

不进行此步骤会导致航向角长期漂移（尤其是相对位置模式）

## Q&A

### 为什么不闭环位置只闭环航向角？

因为闭环位置依赖的是轮速积分 + 运动学解算。这种方式对轮子的打滑是敏感的。

如果闭环位置实际上是为了应对位置的扰动，但是实际上位置扰动在车模运行过程中是几乎没有的。

就就算出现了外力对位置发生了扰动，由于速度环的存在，实际上这个时候发生的应该是轮子打滑，因此无法正确将位置闭环。

### 为什么不使用 IMU 闭环位置？

首先 IMU 的加速度计静止的时候读数就包括零飘和重力加速度 + 重力加速度分量。其次重力加速度分量会因为车模角度的不同在三个轴的方向上发生变换，也就是说如果车模角度发生旋转，三个轴的度数都会发生剧烈变化。

因此实际上 IMU 加速度计的解算需要通过四元数算出车模当前的位姿，然后在三个轴上减掉重力分量，减完之后还要校准 0 飘。

然后这个减掉重力分量依赖加速度计的安装姿态，也就是说如果你不能保证重力加速度分量全在一个轴上的时候，解算就会发生偏转。

再加上通过加速度计算速度使用的是二次积分，误差会被平方之后累计。

最后的效果就是光是放着不动距离都在涨。

一种做法是通过九轴陀螺仪感知安装姿态加上拓展卡尔曼滤波（EKF）和轮速融合，但是我们组只能用 IMU660RB 也就是六轴模块。

所以这个方案行不通。

另外我也问了几位学长、群u、朋友，确实是做不了的。

### 那为什么航向角计算的这么准？

1. 精度足够
2. 零飘好校准
3. 加速度三个轴的耦合比较深而且还和当前姿态耦合，但是航向角几乎没有耦合
4. 四元数好用
5. 陀螺仪读出来的是角速度，单位中是带了一个时间 `dt` 的，我在代码中通过 `RT1021` 的时间 `API` 动态计算了这个 `dt` 也就是控制周期，使得数据几乎不会因为控制周期变化而产生误差

### 为什么要加锁？

一般来说，锁是一个异步操作过程中很常见的操作

一个常见的使用相对运动模式控制的场景是：我通过视觉系统闭环当前车模的姿态，然后通过 P 环计算一个 `dx` 值，通过多段控制最终使得车模对正到目标位置。

例如为我当前计算出的`dx=10`，如果我车模在还没响应完上一条命令的时候（也就是车模还没有移动到目标位置），我 P 环计算出的误差应该依然是 `dx=10`，这时候车模实际上的运动目标是 `dx=20` 也就是这里的命令重复导致了最终执行效果的过冲，这种话效果显然不是我们想看到的。

因此通过加锁，我们可以避免两个异步线程通信的时候出现的各种问题，这里加锁丢掉所有命令则是为了保证当前命令的完整执行，防止相对位置、绝对位置、速度模式来回切换的时候出现的神秘 BUG。

实际的通信协议中，为了避免神秘 BUG，一般会先查询 lock 状态，在确认没有 lock 的情况下再发送，防止命令丢失。
