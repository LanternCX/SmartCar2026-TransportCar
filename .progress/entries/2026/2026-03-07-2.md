## Title
建立 Stage 3 设备观测诊断链路

## Background / Issue
用户希望在主机侧 `pytest` 之外，增加一条 agent 可主动触发的真实板观测阶段，用于在本地通过 `mpy-cli` 读取车辆运行状态，并帮助归因控制周期、传感器、执行器与视觉状态机问题。

## Actions / Outcome
- Approach 1: 仅增加 `UART6` 查询接口 -> 可以暴露运行时状态，但 agent 通过 USB/`mpy-cli` 直接调用仍不够顺手。
- Approach 2: 仅依赖临时探针脚本 -> 能跑通本地观测，但缺少稳定的运行时协议面，后续联调复用性不足。
- Final approach: 统一 `TransportCar` 运行时快照，叠加 `UART6` 诊断查询与 `mpy-cli` 临时观测探针 -> 既能支持后续联调，也让 agent 能直接从本机发起 Stage 3 观测并自动归因。

## Lessons / Refinements
- 真正对 agent 有用的不是“更多日志”，而是低频、结构化、可判定的快照面。
- 设备侧诊断应优先做摘要而不是持续刷屏，才能不破坏 5ms 控制周期。
- 主机侧硬件工具若要可测试，先把命令编排和输出解析抽成纯函数，再补设备执行流程。
