## Title
修复 ORBITING 切出后的残留旋转与航向跨圈语义

## Background / Issue
视觉状态机在 `ORBITING` 结束后本应安全从 `rear_only` 切回三轮全向, 但实车上出现了两类叠加问题: 一类是视觉输出使用规范角 `(-180, 180]`, 而 `TransportCar.heading_est` 使用连续角, 导致等价航向被当成跨圈误差继续追踪; 另一类是 `ORBITING -> ALIGN_DX` 时视觉本拍已经不再输出有效角度目标, 姿态环却继续保持上一拍的 `heading_target`, 于是底盘在切回 full 模式后又多转一段并最终丢目标.

## Actions / Outcome
- Approach 1: 先按角度 wrap 问题排查, 对比 `vision_state_machine` 的 `normalize_angle(...)` 与 `TransportCar` 的连续航向 PID 误差定义 -> 复现了 `-90` 与 `270` 被算成 `-360` 度误差的路径, 并补了 wrapped-angle 回归测试
- Approach 2: 上板读取 `VSM TRANS` 日志继续追 `ORBITING -> ALIGN_DX` 切换后的实测航向变化 -> 发现即使没有跨圈, 车辆仍会在切出 `rear_only` 后继续转动, 根因是视觉 intent 变为 inactive 后旧 `heading_target` 未立即释放
- Final approach: 在 `src/services/transport_car.py` 中统一使用最短路径角差, 将视觉规范角映射回当前连续航向附近, 并在 `_refresh_vision_target()` 检测到“上一拍有视觉目标, 本拍变 inactive”时立即把 `heading_target` 贴到当前 `heading_est` 并 reset `yaw_pid` / `yaw_integral`; 同时在 `tests/unit/services/test_transport_car_vision_integration.py` 增加 wrapped-angle、rear-only 解锁和 stale heading release 三个回归测试 -> `python3 -m pytest tests/unit/services -q` 通过 `99` 项, Stage 2 另外暴露出 `.agent/stage2_smoke_probe.py` 在板端导入时有独立的 `MemoryError`, 但与本次旋转根因分离

## Lessons / Refinements
- 状态机输出若使用规范角, 下游姿态控制若使用连续角, 必须在边界层做语义转换, 不能让两套角度域直接混用
- 对“当前拍 intent inactive”这类状态切换, 不能只清数据源引用, 还要显式释放上一拍残留的控制状态, 否则闭环会在模式切换后继续输出旧动作
- 设备日志对这类时序 bug 非常关键: host 侧测试能锁定角度语义, 但 `VSM TRANS` 与实测航向变化才能证明真正的残留控制发生在 `ORBITING` 切出后的哪一拍
