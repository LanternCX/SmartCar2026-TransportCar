## Title
完成 legacy 归档与 master-assistant 主机侧最小闭环

## Background / Issue
项目已决定把旧系统冻结到 `src/legacy`, 并同时长出 `src/master` 与 `src/assistant` 两套独立最小运行时。重构目标是保留稳定性内核和完赛主线, 删除旧统一运行时的复杂结构。过程中出现一个关键分叉: 旧系统真实归档后, 原有大量旧测试和旧入口整体失效。用户随后明确要求旧仓库代码仅作参考, 旧仓库对应测试全部删除, 当前主线只保留新系统验证。

## Actions / Outcome
- Approach 1: 把旧系统真实归档到 `src/legacy` 并补归档验收 -> 完成, `tests/unit/legacy/test_archive_layout.py` 通过
- Approach 2: 先建立 `assistant` 最小执行闭环 -> 完成主机侧闭环, 去掉对旧根目录 `filters` / `utils` 的直接依赖, `10 passed`
- Approach 3: 建立 `master` 最小主控链 -> 完成单视觉串口轮询双摄、简化视觉状态机、最小决策和主车/辅车目标输出, `14 passed`
- Approach 4: 固定主辅最小运动级协议契约 -> 完成 `MOVE` / `HOLD` 与最小 `STATE` 回包契约测试, `3 passed`
- Final approach: 删除旧仓库对应测试, 只保留 `master` / `assistant` / 主辅协议 / 归档检查的新测试面 -> `python3 -m pytest tests/unit tests/contract -q` 结果为 `29 passed`

## Lessons / Refinements
- `src/legacy` 若只是占位目录而不是实际归档位置, 目录目标会失真, 必须先真实归档再继续新系统实现
- 旧系统真实归档后, 若用户明确要求 `legacy` 仅作参考, 就不应再回头补旧入口兼容层, 而应直接删除旧测试面, 让验证范围与新主线保持一致
- `master` 和 `assistant` 的稳定性层必须真正自足, 不能偷偷依赖旧根目录, 否则一旦旧系统归档就会立即暴露结构问题
